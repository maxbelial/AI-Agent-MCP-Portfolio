## P1 · 两层客户结构

**公司定位「中企出海」之下，EMS 的主要用户分为两层**（2026-08-19 用户澄清）：

```
                 ┌─────────────────────────────────────┐
                 │  MSP / 二类运营商（HKT · 信天 · CTE） │ ← 买家 · 多租户
                 │  用 EMS 运营自己服务的多个最终客户    │
                 └───────────────┬─────────────────────┘
                   多租户（每租户 = 一个最终客户）
                 ┌───────────────┴─────────────────────┐
                 │  最终客户（周大福 · 达美乐 …）        │ ← 使用者 · 门店+DC
                 │  统一监控运维 · 数据在自己租户内      │
                 └─────────────────────────────────────┘
```

### 各层角色与诉求

| 层                           | 典型代表                                | 诉求                                                                   | 对 EMS 的要求                                                              |
| :--------------------------- | :-------------------------------------- | :--------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| **MSP / 二类运营商**（买家） | HKT · 信天 · **CTE 中国电信欧洲分公司** | 一平台管理多个客户的项目与运维 · 工时可核算 · 客户数据隔离 | **多租户**（每租户=最终客户）· 项目/工单/资产按客户归属 · 管理层跨租户总览 |
| **最终客户**（使用者）       | 周大福（门店+DC）· 达美乐（门店）       | 统一监控运维 · 项目进度可见 · 报告与 SLA 可查                          | 租户内完整运维能力（ITAM/ITOM/ITSM）· 客户自助门户（提单/看进度/看报告）   |
| **季冠自身**（MSP 之一）     | 上海季冠                                | 与外部 MSP 同口径使用 EMS                                              | EMS 对 MSP 无差异化限制（季冠也是租户）                                    |

### 与 00 客户档位的关系

- [00 §P1](00-product-value-thesis.md#p1--价值主张) 现有档位：SMB（10-40 人）/ 中大型（40-200+ 人）/ 出海档（中企总部+海外站点）
- **本档位是"角色维度"而非"规模维度"**：MSP 客户的 IT 部门可能很小（10-40 人），但管理的资产/工单/项目跨多个最终客户——**分档逻辑需叠加"租户×客户数"维度**
- 处理建议：MSP 客户按"中大型档能力 + 多租户运营视图"处理；最终客户按既有档位处理

## P3 · PMS 产品定位与边界

### 定位

**PMS（Project Management System · 项目管理）**：基于 PMBOK 知识体系的项目全生命周期管理平台——从**立项审批、规划分解（WBS）、执行追踪到结项归档**，覆盖 PMBOK 十大知识领域在数字化平台的落地。

#### 行业基线：PMS 核心流程与关键词（2026-08-19 调研）

| 知识领域（PMBOK） | 平台落地功能 | 关键流程 |
|:---|:---|:---|
| **范围管理** | 需求池 · 立项评审 · WBS 分解 · 验收标准 | 需求 → 立项 → 范围基线 |
| **进度管理** | 甘特图 · 关键路径（CPM）· 里程碑 · 基线管理 · 计划排程 | 排程 → 里程碑 → 偏差跟踪 |
| **资源管理** | 角色技能矩阵 · 负载热力图 · 资源日历 · 工时填报与审批 | 资源分配 → 工时报工 → 负载平衡 |
| **成本管理** | 预算编制 · 挣值管理（EVM）· 成本归集 · 超支预警 | 预算 → 实际归集 → 偏差分析 |
| **风险管理** | 风险登记册 · 概率/影响评级 · 应对策略 · 风险预警 | 识别 → 评估 → 应对 → 监控 |
| **沟通与干系人管理** | 沟通计划 · 会议纪要 · 干系人分析与参与跟踪 | 干系人识别 → 沟通 → 反馈 |
| **采购与合同管理** | 招采流程 · 供应商管理 · 合同里程碑 | 采购计划 → 合同执行 → 验收 |
| **质量管理** | 质量计划 · 检验清单 · 缺陷闭环 | 质量规划 → 质量控制 → 验收 |
| **变更管理**（集成管理） | 变更评审 · 基线管理 | 变更申请 → 评审 → 基线更新 |
| **文档与报表** | 模板库 · 版本管理 · 指标看板 · 燃尽图 · 项目归档 · 经验教训 | 文档沉淀 → 报告 → 结项归档 |

> 数据来源：PMBOK 十大知识领域（PMI 项目管理知识体系）· 项目管理系统行业资料（[百度百科 · 项目管理系统](https://baike.baidu.com/item/%E9%A1%B9%E7%9B%AE%E7%AE%A1%E7%90%86%E7%B3%BB%E7%BB%9F/8894065) · [Celoxis · Top Project Management Software Features](https://es.celoxis.com/article/project-management-software-features)）· 2026-08-19 调研

- **真实开发**：由**低代码产品经理**负责设计（当前需求调研阶段），基于低代码平台搭建；**本表为行业基线，具体功能裁剪以需求调研结论为准**
- **授权口径**：`org/license-management.html` 已有 **Champ-PMS** 产品定义——MGT 主管账号（创建/修改/删除基础设置）· PM 项目经理账号（项目执行/进度跟踪）
- **原型状态**：`prototype/pms/` 5 页已交付（2026-08-19 · 独立顶级域 · 色 `--c-pms #0D9488`），用于老板演示与 CTE 测评预演——原型字段（PM/BM/里程碑/进度/预算/合同引用/风险）对应上表"资源/进度/成本/采购/风险"领域，工时页对应"资源管理·工时填报"

### EMS 与 PMS 的接口关系（EMS 的角色）

**EMS 不重造 PMS 领域功能，PMS 不重造资产/工单/派工**。EMS 提供：

| 接口面               | 内容                                                                                                       | 原型已演示                      |
| :------------------- | :--------------------------------------------------------------------------------------------------------- | :------------------------------ |
| **项目数据标签实体** | 项目作为一级实体，与资产/合同（ITAM）、告警（ITOM）、工单（ITSM）、派工（FSM）、工时/报告（PMS）互相可跳转 | 项目详情「贯通」Tab 6 卡        |
| **贯通 API 契约**    | 项目 ↔ 各产品域的数据/操作契约（PMS 需求冻结后细化）                                                       | `?project=` 参数预过滤          |
| **Work Queue 集成**  | 项目相关的审批/工时/报告交付进待办队列                                                                     | 工时审批待办引用 Work Queue     |
| **治理/审计**        | 项目操作日志 · AI 建议（风险/进度/工时）留痕                                                               | 项目详情 AI 面板 + 操作日志 Tab |

### 边界（Scope Fence）

- ❌ EMS 不做 PMS 领域深度（预算财务管理 / 复杂 Gantt / 项目计划引擎）——由低代码产品经理设计
- ❌ PMS 不做资产台账/告警/工单/派工——引用 ITAM/ITOM/ITSM/FSM 数据
- ❌ 不新增 Work Queue 队列类型（现有 7 类 alert/ticket/approval/dispatch/sla/handover/change 覆盖，项目数据通过数据标签贯通）

## P4 · 对产品设计的含义

### 形态层：租户 → 项目 → 站点/资产 层级

MSP 视角下信息架构增加两个层级：

```
租户（MSP 的客户 · 周大福 tn_corp）→ 项目（类型由 PMS 定义）→ 站点/资产/工单/工时
                                        ↓
             Work Queue / Governance / Dashboard（现有形态保留，下沉为租户内、项目内视图）
```

- MSP 管理层首屏：**多租户运营总览**（每租户 SLA/工单量/项目进度/成本视角）
- PM/BM 首屏：**项目工作台**（进度 / 里程碑 / 资源 / 风险——对应 PMBOK 进度·资源·风险领域，PMS 提供 · EMS 聚合）
- 最终客户：**自助门户**（提单/看进度/看报告——对应客户期望的"客户协同"）

### 角色体系扩展

| 现有（技术角色）                      | 新增（业务角色 · 2026-08-19）                                                                                    |
| :------------------------------------ | :--------------------------------------------------------------------------------------------------------------- |
| U1 一线 · U2 专业 · U3 中层 · U4 领导 | **PM**（项目经理 · 项目执行/进度/工时审批）· **BM**（业务经理 · 商务/变更审批）· **客户方**（验收确认/自助查看） |

- PM/BM 可映射到 U3 治理视角扩展；客户方是新视角（[01 §P6](01-user-persona-workday.md#p6--客户组织形态映射表) 待补客户门户 Persona）
- 权限来源：Champ-PMS 的 MGT/PM 账号（与既有 RBAC 联动）

### 平台能力（MSP 准入条件）

| 能力         | 说明                                                        |                         状态                         |
| :----------- | :---------------------------------------------------------- | :--------------------------------------------------: |
| **多租户**   | 租户隔离（数据/配置/报表）· 租户切换 · 跨租户总览（管理层） | ⚠️ 存量有基础（tenant-management）；数据级隔离待确认 |
| **多语言**   | 中文 + 英文界面（海外客户/海外站点）· 英文工单/报告         |                    ❌ 未系统设计                     |
| **多时区**   | SLA 基准按区域 · 交接班跨时区                               |            ⚠️ 06 §P5 已预留区域/时区字段             |
| **多币种**   | 项目预算/合同/工时计费按币种 · AI 账单多币种                |         ⚠️ 00 §P3 T2 已预留；PMS 预算已演示 · AI 账单已演示（ai-billing 币种切换） |
| **数据驻留** | 欧盟 GDPR / 属地存储（海外部署形态）                        |           ⚠️ 00 §P7 已预留；原型已演示标签           |
| **AI 二层计费** | 第一层：平台 → MSP/直接客户（credits 批发/零售价目表）· 第二层：MSP → 名下租户（配额/转售单价/超量策略/账单）· 转售利润分析 | ✅ 08 §P3 已设计（2026-08-21）· `org/ai-billing.html` 原型已落地 · 租户级 AI 计量是 EMS 差异化能力（SN 只到实例级） |

### 指标与 AI

- **项目级指标**：项目 SLA 达标率 · 里程碑准时率 · 工时计费结构（可计费%）· 备件 4h 到场 · 站点就绪
- **AI 场景**（PMS 域）：项目风险预测 · 进度偏差预警 · 工时异常检测 · 报告自动起草（L2）· 里程碑排期建议
