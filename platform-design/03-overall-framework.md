## P1 · 定位承接

**EMS 价值主张（三条）**（论证详见 [00-product-value-thesis.md](00-product-value-thesis.md)，三条价值的完整场景/治理项/量化口径见 00 §P1-§P8）：

- **价值一 · 倍增 junior / 解放高级人才**（购买动机）—— 用同样的人力做更多事、把高级人才从琐事里解放出来；落地为辅助模式（×1.5-2.5 效能，不承诺 L4）；**讲两个故事**：对决策者讲降本（一线可裁减 5-15%），对使用者讲解放（junior 从低价值劳动脱身）
- **价值二 · AI 治理可信**（准入证 · 敢用）—— 所有 AI 活动可审计、成本可控，让 IT 主管 / 财务 / 合规敢在生产环境上；中大型企业档提供完整 T1-T8 治理，**SMB 档降级为成本可控**（T2 账单 + T5b 调用记录）
- **价值三 · 一个平台打通运维闭环**（能力跃迁 · 差异化）—— 从发现问题到处置派工，跨 ITOM/CMDB/ITSM/FSM/NPM/**ITAM** 六产品端到端闭环，MTTR 降 50%+；做以前做不到的事（Datadog 无工单/派工 · SN 监控弱 · 运营商只卖线路，闭环是 EMS 独有）

> **出海定位承接（2026-08-19 公司定位「中企出海」）**：价值主张的客户故事扩展至**出海中资企业**——跨境链路与海外站点纳入闭环（NPM 跨境拨测 → ITAM 资产/合同 → ITSM 建单 → FSM 海外派工）；架构需支持**多区域部署 / 数据驻留 / 多币种**（详见 §P2 L1/L2 扩展 · §P3 ④模型接入海外形态）。ITAM 已从外部产品**转正**为第六产品域（2026-08-19 决策）。

**服务三条价值的产品设计手段**：
- 价值一 → 三条加法（高频操作聚合 + 跨产品联动 + AI 洞察/建议）覆盖 17 项 junior 场景 S01-S17
- 价值二 → AI 治理面板 T1-T8 + 数据标签体系
- 价值三 → 跨产品联动链（L4 联动编排）+ CMDB 数据底座（L2）+ 统一侧边栏与数据标签（L5）

**本文档核心命题**：把三条价值主张翻译成**架构层次 + AI 边界 + 6 大产品协同关系**三张图，作为后续各链段设计（见 02 §P4）的输入基线。

## P2 · 架构层次

### 五层架构一览

```
┌──────────────────────────────────────────────────────────────┐
│  L5 · 应用入口层（EMS 工作台）                                 │
│  Portal / 三类角色视图 / 统一侧边栏 / Dashboard / 跨产品数据标签 │
│  ── 用户直接看到的一切，本轮设计主战场 ──                       │
├──────────────────────────────────────────────────────────────┤
│  L4 · 联动编排层                                              │
│  跨产品操作链（L1-L3 场景化） + AI 洞察/建议 + 高频操作聚合      │
│  ── 三条加法的实现层 ──                                        │
├──────────────────────────────────────────────────────────────┤
│  L3 · 能力接入层                                              │
│  六大产品原生能力 + 数据/操作契约（EMS 只调用，不重实现）        │
│  ── 靠既有产品 API/事件/MCP Services 接入 ──                    │
├──────────────────────────────────────────────────────────────┤
│  L2 · 数据底座层                                              │
│  CMDB 主数据 + 各产品业务数据（存量数据模型延续）               │
├──────────────────────────────────────────────────────────────┤
│  L1 · 平台治理层（贯穿所有层）                                 │
│  SSO · 租户 · RBAC · License · 审计 · AI 治理面板 T1-T8         │
└──────────────────────────────────────────────────────────────┘
```

> "贯穿"含义：治理层不是被上层调用的下游，而是"横跨所有层的一套约束"——权限矩阵、成本账单、审批卡点、审计日志在每一层都能命中。

### 各层职责与边界

| 层 | 职责 | 关键组件 | 本轮增量 | 边界（不做什么） |
|:---|:---|:---|:---|:---|
| **L5 · 应用入口层** | 统一工作台入口 · 三类角色视图 · 高频操作露出 · 跨产品数据可跳转 | Portal · 三类角色工作台（值班经理/IT 主管/运维总监）· 统一侧边栏 · Dashboard 跨产品聚合卡片 · 数据标签体系 | N1 高频操作聚合 · N6 Dashboard 增强 | 不重造各产品原生 UI；不做子产品替代品 |
| **L4 · 联动编排层** | 跨产品操作链的定义与调度 · L1-L3 场景化 AI 建议/摘要 · 高频操作路由 | 联动链定义（触发点/参数流转/失败兜底）· AI 洞察引擎（内嵌在流程节点上）· 高频操作路由表 | N2 联动链 · N3 增强版根因分析 · N4 业务级告警降噪 | 不做以 Agent Hub 为平台中心的「AI 编排层」架构定位，不做通用编排引擎（Agent Hub 是 EMS 内的 AI 资产管理页面，非平台架构形态）；不做与场景无关的 AI 中枢 |
| **L3 · 能力接入层** | 声明式接入各产品的**数据**（读）与**操作**（写）· 契约稳定性等级管理 | 产品数据契约（读）· 产品操作契约（写）· MCP Tools 注册表（可选接入方式之一）· 事件订阅 | 契约稳定性等级定义（P0 冻结 / P1 稳定 / P2 演进） | 不重实现子产品的领域 AI（ITOM RCA / CMDB 服务模型等）；不做无契约的私有接入 |
| **L2 · 数据底座层** | CMDB 主数据 · 各产品业务数据 · 数据一致性/时效性 SLA | CMDB · ITOM 时序 · ITSM 工单 · FSM 派工 · NPM 拓扑 · **ITAM 资产台账**（2026-08-19 转正 · 与 CMDB 双向对账 · ic-013 每 30 分钟同步） | — （沿用存量数据模型与同步链路，本轮无增量） | 不改动子产品自有数据模型 |
| **L1 · 平台治理层** | SSO · 租户 · RBAC · License · 审计 · **AI 治理面板 T1-T8** · 成本账单 | 存量平台治理组件 + AI 治理面板（T1 审批卡点 · T2 成本账单 · T3 熔断 · T4 证据链 · T5 审计 · T6 override · T7 可视化 · T8 权限矩阵） | N5 AI 治理面板 T1-T8 | 不做与 AI 治理无关的平台改造 |

## P3 · AI 能力边界

### 四种 AI 接入方式

EMS 里的 AI 能力不是"一个大一统的 Agent 中枢"，而是**四种独立的接入方式，各自适配不同场景**：

| 接入方式 | 载体 | 场景例 | 落地档位 | 归属层 |
|:---|:---|:---|:---:|:---|
| **① Agent Hub** | 独立入口页（对话/任务列表） | 用自然语言问全局：「今天有哪些告警值得关注？」「帮我起草本周变更评审总结」 | L1-L2 | L5 应用入口 |
| **② 页面内嵌洞察** | 各工作台页面的卡片/侧栏 | 事件详情页嵌"AI 建议根因 Top 3"；工单页嵌"AI 起草处置步骤" | L1-L2 | L4 联动编排 |
| **③ MCP Tools** | 声明式工具，被联动链或 Agent Hub 调用 | 联动链「告警转工单」调用 ITSM.createTicket；Agent Hub 让 LLM 决策调用哪个 tool | L1-L3（含 L3 硬编码） | L3 能力接入 |
| **④ 模型接入** | 平台侧模型管理 · 模型 SKU · 供应商切换 · **本地私有化一体机** · **三种计费模式** | 提供模型库/切换/成本控制；不锁定单一模型；**支持中国系开源模型本地部署（dense 32B 档 · 如 Qwen2.5-32B；MoE 激活小参数档 · 如 DeepSeek-V4-Flash / Kimi K2 / GLM-4.5-Air；型号与硬件配置待技术评估 · 数据不出境 · 成本敏感/数据安全客户必须提供，候选清单与选型策略见 00 §P7 私有化方案）· 海外部署形态（2026-08-19）：海外云节点按量（客户海外账号 · 数据驻留可选）+ 海外本地一体机（属地存储法规 · GDPR/CCPA），模型不锁中国系（海外场景可接 Claude/GPT 等）· **计费模式（2026-08-21 · 08 §P2）：托管（credits 全价）/ BYOK（平台费半价 · Token 客户自付）/ 私有化（本地调用免 credits），租户级选择 · 场景级混合** | — | L1 平台治理 |

### AI 档位归属规则（L1-L3 覆盖，L4 不做 · 对齐 [product-value-thesis §P5](00-product-value-thesis.md#p5--关键设计参数已确认)）

> 审计要求列的 T 编号档位归属与 [00-product-value-thesis §P3](00-product-value-thesis.md#p3--价值二--ai-治理可信) 一致；**"核心兜底 4 层"（T1/T3/T5/T6）即 [02-design-split-plan §P1](02-design-split-plan.md#p1-产品定位) 治理面板 4 层兜底（审批卡点 + 熔断 + override + 审计）的展开，T4 证据链 / T8 权限矩阵按档位附加。**

| 档位 | 定义 | 本轮范围 | 审计要求 | 成本记录 |
|:---|:---|:---|:---|:---|
| L1 · 辅助 | AI 提供建议/摘要/排序，人工决策 | ✅ 默认档位 | **不做完整决策审计**（只保 T5b AI 调用记录 + Token 消耗；T4 证据链可选） | ✅ 每次调用 |
| L2 · 推荐 + 审批 | AI 起草动作，人工 inline 审批后执行 | ✅ 覆盖 | ✅ 核心兜底 4 层（T1 审批卡点 + T3 熔断 + T5 审计 + T6 override）+ T4 证据链 | ✅ 每次调用 |
| L3 · 端到端自动执行 | AI 触发跨产品动作链无人工干预 | ⚠️ **窄场景 + 硬编码白名单** | ✅ 核心兜底 4 层（T1 审批卡点 + T3 熔断 + T5 审计 + T6 override）+ T4 证据链 + T8 权限矩阵，**全部命中** | ✅ 每次调用 |
| L4 · 无人值守 | 完全无人参与 | ❌ 明确不做（不符合"辅助模式"落地档位） | — | — |

### 关键约束（对齐价值主张 · 价值二 AI 治理可信）

- **不用 LLM 自报置信度作为闸门**：改用「确定性规则闸门 + 场景白名单 + 治理面板 4 层兜底（审批卡点 + 熔断 + override + 审计）」
- **AI 能力必须绑定业务场景**：不做"通用 AI 助手"入口；每个 AI 入口必须服务 [product-value-thesis §P2](00-product-value-thesis.md#p2--价值一--倍增-junior--解放高级人才) 里 S01-S17 中的一个具体场景
- **L3 场景一律硬编码白名单**：不允许运行时动态开放；新增 L3 场景走 T1 审批卡点流程。档位开关语义（2026-09-03 拍板）：拨档位本身不审批，但拨 L3 需至少存在一条已审批的白名单规则（无规则时 L3 灰置）；从 L3 降级永远自由；开关仅 IT 主管/管理员可操作（对齐 T8）
- **落地档位 = 辅助模式**：junior 效能 ×1.5-2.5（POC 校准）但仍在岗，不承诺完全替代（L4 不做）【🔴 **P0 待校准**：需 ≥3 家 POC 客户实测回填，完整口径见 [00 §P1](00-product-value-thesis.md#p1--价值主张)】
- **成本颗粒度 = 每次 AI 调用**：作为最小记录单位，汇总维度用户自定义（日/周/月）· 支持用户/租户/场景/模型四维下钻
- **计量双口径（2026-08-21 · 08 §P1）**：AI Credits 对外计费（一次动作 = 固定 credits · 对话 1 / 摘要 2 / 检索 3 / 风险评估 5 / 工作流 10）× tokens 对内核算（成本/BYOK 分账/熔断）· 每次调用六要素记录（身份/行为/模型/消耗/决策链/内容）
- **L1 审计颗粒度 ≠ L2/L3**：L1 只需 T5b（AI 调用记录 + Token 消耗），L2/L3 走完整审计链（T4 + T5 + T6）
- **AI 安全防护（2026-08-21 · 08 §P4）**：三道防护（Prompt 注入检测全平台 / 敏感内容过滤 16 分类 / 输出白名单校验 M8）各分 log-only / log+block 两档 · 调用 LLM 前剥除 PII · AI Gateway 全局暂停/恢复（与 T3 自动熔断互补）

## P4 · 六大产品协同关系

### 各产品在 EMS 里的角色

> **ITAM 转正说明（2026-08-19 产品决策）**：ITAM（资产生命周期管理）从 08-14 的"外部产品"回归为**第六产品域**（公司定位「中企出海」），一级导航在 ITSM 与 FSM 之间；原型模块 5 页已交付（`prototype/itam/`），与 CMDB 双向对账（ic-013 · 8,421 匹配 / 234 差异）；领域功能增量（资产申请/发运流程深化）后续批次设计（见 [02 §P1](02-design-split-plan.md#p1-产品定位)）。

### 统一侧边栏与菜单体系

- **一级导航**：Portal · ITOM · CMDB · ITSM · **ITAM** · FSM · NPM · Agent Hub · 治理 · 设置 · 组织
- **ITAM**（2026-08-19 转正）：独立顶级域（ITSM 与 FSM 之间），4 个子页（资产概览/资产台账/合同管理/库存盘点），可见性由 L1 License 过滤控制（Champ-ITAM SKU 已授权）
- **切换体验**：切换子产品时**保留当前 CI/服务/工单/资产上下文**，同一实体在不同产品间连续跳转，不掉线
- **权限过滤**：由 L1 治理层的 RBAC + License 决定每个用户可见的一级菜单

#### 菜单展示体系（三层过滤 + 应用启动器）

任何用户的可见菜单 = **License × 角色菜单集**，个性化由收藏承担：

| 层 | 内容 | 配置者 | 说明 |
|:---|:---|:---|:---|
| **L1 · License 过滤** | 未购买模块整组隐藏 | 自动（SKU 联动） | 无人工配置，跟随 EMS 平台授权管理 SKU |
| **L2 · 角色菜单集** | 每角色一套默认菜单集，**粒度到页面项**（可见 + 排序） | 租户管理员（基于内置模板微调） | 内置 U1-U4 四套 + SMB 合并集（U-Frontline / U-Manager）；平台模板 + 租户覆盖，MSP 不逐租户配置 |
| **L3 · 用户收藏** | 任意页面收藏：改名 / 图标 / 颜色 / 分组 / 拖拽排序 | 用户自助 | **后端存储（tenant × user）**，同账号跨设备一致；租户内隔离，不跨租户 |

**关键设计决策**：

1. **用户级菜单显隐不做**：菜单是能力目录，「能看什么」由角色与 License 决定（可追溯、可审计）；个性化诉求由收藏覆盖（对标 ServiceNow Favorites）
2. **核心三入口**（Work Queue / Governance / Dashboard）不参与任何隐藏
3. **管理员配置留痕**：角色菜单集变更进入 T5 审计

#### 应用启动器（App Launcher）

- **位置**：Domain rail 最顶部（左侧竖条第一项，全局可达），指南针图标；Logo 保持 Header 最左
- **展开面板**：「我的收藏」区（用户收藏列表 + 管理入口）+「产品」区（License 过滤后的产品图标：ITOM / ITSM / CMDB / FSM / NPM / Agent Hub）
- **产品 icon 点击**：直达该产品默认首页（各产品已有默认入口页），不经过中间页
- **与 Domain rail 分工**：rail = 常驻领域导航（下钻当前域）；launcher = 折叠的收藏 + 跨产品快速跳转
- **收藏入口**：任意页面 Header 右侧星标按钮，点击收藏 / 再点取消；收藏管理支持改名 / 图标 / 颜色 / 分组 / 拖拽排序
- **空态**：无收藏时显示引导文案「点击页面星标收藏常用页面」

### 跨产品数据标签

**这是"跨产品联动"（第 ② 条加法 · 价值三"一个平台打通运维闭环"）的关键载体**：同一个业务实体（服务、CI、工单、告警、派工、诊断报告）在任何一个产品页面上都用统一的**数据标签**标记，点击标签可跨产品跳转，跳转后自动定位到该实体的详情视图。

| 数据标签 | 主数据来源 | 出现在 | 跳转到 |
|:---|:---|:---|:---|
| 服务 (Service) | CMDB | ITOM 告警 · ITSM 工单 · FSM 派工 · NPM 诊断 · Portal Dashboard | CMDB 服务详情 |
| CI (Configuration Item) | CMDB | ITOM 拓扑 · ITSM 工单 · NPM 路径 | CMDB CI 详情 |
| 告警 (Alert) | ITOM | ITSM 工单来源 · Portal Dashboard · Agent Hub | ITOM 告警详情 |
| 工单 (Ticket) | ITSM | ITOM 告警下钻 · FSM 派工来源 · Portal Dashboard | ITSM 工单详情 |
| 派工 (Dispatch) | FSM | ITSM 工单下钻 · Portal Dashboard | FSM 派工详情 |
| 诊断报告 (Diagnosis) | NPM | ITOM 告警下钻 · 根因分析工作台 | NPM 诊断详情 |

### 联动链（价值三"一个平台打通运维闭环"的核心载体 · 三条加法之 ②）

联动链是**从 L5 用户操作触发 → L4 编排 → L3 调用多个产品操作 → L2 更新数据 → L5 反馈结果**的端到端路径，是价值三"做以前做不到的事"的直接体现。存量与增量：

| 联动链 | 状态 | 触发点 | 涉及产品 | 档位 |
|:---|:---|:---|:---|:---:|
| L01 · 告警转工单（存量样板） | ✅ 生产运行 | ITOM 告警规则匹配 | ITOM → ITSM | L3（硬编码窄场景） |
| L02 · 根因 → 建单 → 派工 → 通知 | ⏳ 反应性处置链设计 | 事件详情页点击"处置" | ITOM → CMDB → ITSM → FSM | L2/L3 |
| L03 · 变更影响面评估 | ⏳ 后续 | ITSM 变更单创建 | ITSM → CMDB → NPM | L1 |
| L04 · 容量预警 → 扩容工单 | ⏳ 后续 | ITOM 容量预测触发 | ITOM → ITSM → FSM | L2 |

> 完整联动链属于反应性处置链（N2）产出物，本节仅列参考样例。
