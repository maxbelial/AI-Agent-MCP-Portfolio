## 1. 背景

ITSM / FSM / ITAM 三个产品基于 **Corteza 低代码底座**，通过 AI 能力扩展提升产品价值与市场竞争力；EMS 从综合运维平台角度**统一规划管理其下产品的 AI 能力构建**。本文件完整记录该规划（含附件详细预期）并给出与 EMS 现有设计（00-05）的对齐分析，供 EMS 各周设计取用。

---

## 2. 前置共识（确定性 vs AI 边界）

1. **Corteza 全权承接结构化流程**：表单流转、定时告警、跨模块数据联动、权限、消息推送、基础表单校验、可枚举规则——**AI 不接手确定性自动化**
2. **AI 只处理非结构化内容**：文本解析、语义匹配、内容归纳、智能判别、资料生成、脏数据排查
3. **调用模式**：Corteza 表单变更触发 WebHook → 推送文本载荷给 AI-Agent → Agent 内置标签枚举/业务规则/释义/few-shot 案例作为 Skill 上下文 → 输出**结构化 JSON** → 回调 Corteza 开放 API 写入自定义 AI 字段 → 运维人员可人工修正，**修正样本反哺优化 Agent**
4. **AI 输出严格约束在系统预定义选项池内，禁止大模型自行生成自定义标签/名称**

### 3.2 每项功能的详细预期（回填字段 = AI 字段契约）

> 每项功能统一规格：**Agent 预置上下文 / 触发时机 / 入参 / 回填字段 / 业务预期价值**。节选关键字段：

| 功能 | 触发时机 | 回填字段（ai-xxx） | 业务价值 |
|:---|:---|:---|:---|
| 意图识别与智能标签 | 工单新建 / 故障描述编辑保存 | `ai-故障分类` `ai-业务影响标签` `ai-诉求类型` | 替代关键词脚本自动归类 |
| AI 优先级研判 | 故障描述更新 | `ai-推荐优先级` | 语义评估紧急程度 |
| 工单智能摘要 | 新增评论/日志上传 | `ai-故障摘要` | 浓缩冗长记录 |
| RAG 知识推荐 | 工单初次保存 | `ai-推荐知识ID列表` `ai-处置建议预览` | 语义匹配解决方案 |
| 知识草稿生成 | 工单关闭 | `ai-知识草稿` | 自动整理结构化案例 |
| 同源故障聚类 | 每日定时批量 | 重复故障分组清单（独立问题管理表单） | 事前隐患排查 |
| 变更风险识别 | 变更单提交 | `ai-变更风险等级` `ai-风险备注` | 高危操作提前识别 |
| 自助助手 | 用户提交咨询 | AI 答复 + 自动闭环结果 | 减少人工工单量 |
| 脏数据巡检 | 资产新增/编辑 + 每日定时 | `ai-资产异常标签` `ai-整改建议` | 检出重复/矛盾/缺失 |
| 资产识别关联 CI | ITSM 工单保存 | `ai-推荐关联资产ID` | 口语文本自动绑定资产 |
| 闲置资产分析 | 每日定时 | `ai-闲置评估结果` + 回收建议 | 减少重复采购 |
| 前置检查+备件清单 | FSM 工单新建 | `ai-上门检查清单` `ai-建议备件` | 自动归纳检修事项 |
| 历史案例推荐 | FSM 单据保存 | `ai-相似维修案例编号列表` | 语义召回同设备经验 |
| 表单智能校验 | 外勤提交维修结果 | `ai-表单整改提示` | 识别简略/冲突/缺失 |
| 外勤语音助手 | 外勤前端语音交互 | 排查步骤建议 | 现场免打字查询 |
| 维修照片核验 | 上传完工附件图片 | 完工核验结果 + 整改建议 | 图像核验落实 |
| AI 增强派单 | 工单等待指派 | `ai-推荐工程师打分清单` | 经验维度人选参考 |

| M6 | Dispatch-Profile-MCP | 人员技能矩阵、在岗状态、服务区域、班次、负载、历史成功率 | A7 |

| M9 | Audit-Governance-MCP | 每次调用记录（谁/单据/模型/输入输出/脱敏权限命中），超时异常告警 | 全部（按场景启用） |

### 3.5 MCP 功能设计案例（W3 联动链设计样板）

**案例 1 · 工单意图识别与智能标签（A1）**：
- 调用链路：M1 从 Corteza 取字段组装载荷 → M5 补齐上下文（历史相似单）→ A1 输出候选分类/标签/优先级 → **M2 白名单校验（不合法值拦截并返回可选值）** → M1 回填 `ai-故障分类/业务影响标签/诉求类型`
- 异常兜底：AI 超时 → M1 回填空值标记 `ai-status=timeout` 主流程继续；校验失败 → 工单进入人工分拣队列
- 验收指标：自动标签命中率、人工改写率、平均分派耗时下降比例

**案例 2 · 变更工单风险识别（A4）**：
- 调用链路：M1 拉取变更字段 → M5 聚合历史同类变更结果 → A4 输出风险等级+备注 → M2 校验等级池 → M1 回填并按规则触发审批分支
- 异常兜底：无法判定 → `待人工判定` 强制高级审批；高风险命中 → 自动追加"回退预演证明"必填校验
- 验收指标：高风险命中准确率、审批前拦截率、变更失败率下降比例

### 3.6 EMS 平台统一管理建议（配置视角 · 5 中心）

1. **统一 Agent 注册中心**：Agent 版本、启停、租户可见范围、灰度策略
2. **统一 Skill 配置中心**：标签枚举、释义、few-shot 样例、规则字典
3. **统一 MCP 授权中心**：按产品线与场景控制 Agent 可调用的 MCP 白名单
4. **统一场景编排**：在 Corteza 中仅维护触发事件、入参映射、回填字段映射，业务模块不重复实现 Agent 逻辑
5. **统一质量运营**：按功能统计命中率、人工修正率、回填成功率、超时率

**结论声明**：首版 7 Agent + 9 MCP，各产品仅做 Corteza 配置编排与字段映射，**不再各自建设独立 AI 服务**。

### 4.2 张力与化解：7 个 Agent 的归属

**张力**：附件建议 7 个 Agent 由 **EMS 统一托管**；03 §P2/P3 明确"**不做通用 Agent Hub / 编排引擎**"，02 X1 把 Agent/MCP 技术架构划给研发。

**化解路径（建议）**：7 个 Agent 是**场景化能力**而非编排中枢，按职责拆分归属：

| 归属 | Agent | 理由 | 对应 EMS 设计 |
|:---|:---|:---|:---|
| **平台通用 AI 能力（EMS 提供）** | A1 文本理解 / A2 知识检索 / A3 摘要 / A6 对话 | 跨产品复用 · 无领域偏重 | 03 §P3 四种接入方式的底层能力 |
| **子产品领域 AI（产品自建 · EMS 挂接）** | A4 风险评估（ITSM）/ A5 数据质量（ITAM）/ A7 调度推荐（FSM） | 领域规则与数据在子产品 | 03 §P1"子产品保留领域 AI，EMS 不重复实现" |
| **统一注册与调度（EMS 平台）** | M1-M9 MCP 注册 · 权限挂接 · 白名单 · 质量运营 | 平台职责 | 03 §P3 L3 能力接入层 · MCP 注册表 · 03 §六 5 中心 |

**关键边界**：EMS **托管**（统一注册 + 通用能力 + 授权/质量运营）≠ EMS **编排**（Agent 中枢，明确不做）。附件 §3.6 的 5 中心（注册/Skill/授权/场景编排/质量运营）恰好落在 EMS 的平台职责内，与"不做 Agent 中枢"不冲突——场景编排在 Corteza 侧，EMS 只管注册/授权/运营。

**与 03 §P1"各子产品保留领域 AI"的调和**：附件结论"各产品不再各自建设独立 AI 服务"针对 **ITSM/FSM/ITAM 的新建 AI 能力**（统一到平台托管）；ITOM RCA 等已上线存量领域 AI 保持既成事实。即"**新增统一、存量保留**"。
