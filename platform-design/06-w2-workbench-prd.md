## P1 · 定位与范围

### 一句话定位

**打开 EMS 就是你的待办清单，不用找、不用切系统、不用自己判断优先级。**

### 范围定义

- **工作台**（[02 §P4 链段路线图](02-design-split-plan.md#p4--设计路线图链段驱动-2026-08-19-重写)）= [05-product-form-factor §P2](05-product-form-factor.md#p2--两个核心模式) 的 **Work Queue 工作模式**（U1/U2 默认首屏）+ **Governance Console**（U3 默认首屏）
- **角色**：本链段定义为**所有后续链段的载体**——技术角色（U1/U2/U3）+ **业务角色（PM/BM · 2026-08-19 出海定位新增）** 的入口与视图在此定义；操作**行为与链路**归后续链段（反应性处置链 B · 治理闭环 C · 计划性与履约 D · 出海与 MSP E）
- 服务三条加法中的 **① 高频操作聚合**（[02-design-split-plan §P1](02-design-split-plan.md#p1-产品定位)）：各子产品最常用的操作，搬到 EMS 一处露出，日常工作只需 1 个入口
- 架构归属（[03-overall-framework §P2](03-overall-framework.md#p2-架构层次)）：L5 应用入口层（工作台载体）+ L4 联动编排层（操作路由）+ L3 能力接入层（子产品 API/事件）
- 不重造子产品原生 UI：深操作下钻进入各 Domain Page，工作台只做聚合露出与高频闭环

### 价值指标（承接 [04-v1-mainline-spec §P4](04-v1-mainline-spec.md#p4--业务指标目标区间) + SN SOW 对标基线）

| KPI | 现状基线 | 目标值 | 来源 |
|:---|:---|:---|:---|
| 工具切换次数/事件 | 5-8 次 | 0 次 | SN SOW 对标（itom-reverse E-02） |
| 告警分诊平均时间 | > 15 分钟 | < 5 分钟 | SN SOW 对标 |
| 告警到工单转化时间 | > 20 分钟 | < 3 分钟 | SN SOW 对标 |
| Junior 效能倍数 | 1× | ×1.5-2.5（POC 校准） | [00 §P1](00-product-value-thesis.md#p1--价值主张) |

## P3 · 高频操作归属边界

### 三级边界定义

| 边界类型 | 含义 | 判定规则 |
|:---|:---|:---|
| **原生 UI 操作** | 在子产品页面内完成（下钻进入 Domain Page） | 子产品领域深操作，EMS 不重造：告警详情深查（ITOM alert-detail）、变更实施（ITSM change-detail）、派工详情（FSM dispatch-detail） |
| **EMS 聚合入口** | 工作台队列/面板直接完成 | 高频、跨产品、需 AI 预填的操作：认领、转单（L2 放行）、派工、通知、状态查询、交接、AI 起草类 |
| **L4 联动路由** | 一个动作触发跨产品操作链 | 跨产品端到端闭环：告警→转工单（ITOM→ITSM）、告警→派工（ITOM→FSM）、变更→影响面→审批→执行（ITSM→CMDB→ITSM）、容量→扩容工单 |

### 归属边界表（示例 · 完整清单）

| 高频操作 | 所属产品 | 边界判定 | 子产品侧依赖（引用依赖矩阵） |
|:---|:---|:---|:---|
| 告警认领 | ITOM | EMS 聚合入口 | ITOM 告警标准化 API · 告警标签体系 |
| 告警转工单 | ITOM → ITSM | EMS 聚合入口 + L4 联动路由 | ITSM 工单创建 API · 工单模板引擎 · 自动路由规则 |
| 派工 | FSM | EMS 聚合入口 + L4 联动路由 | FSM 工程师技能矩阵 · 位置/负载 · SLA 计时器 API |
| RCA 排查 | ITOM（Coach-ITOM）+ CMDB | EMS 聚合入口（展示）+ 原生 UI（深查下钻） | ITOM 时序指标 API ✅已上线 · CMDB CI 关系图谱 · 服务链路映射 · 影响面计算引擎 |
| 变更影响面评估 | CMDB + ITSM | EMS 聚合入口 | CMDB CI 关系图谱 · 变更历史 · 影响面计算；ITSM 变更管理流程 · 变更类型分类 · 历史变更结果 |
| 全栈诊断 | ITOM + NPM + CMDB | EMS 聚合入口 + 联动路由 | NPM 路径探测数据 · 拨测结果 API |
| 审批（M3/M4/M5/白名单） | ITSM + EMS 治理层 | EMS 聚合入口（L2 起草放行，T1 载体） | ITSM 工单/变更/服务请求数据契约 |
| 状态查询 | 跨产品 | EMS 聚合入口 | ITSM 工单查询 API · CMDB CI 查询 API · FSM 派工状态 |
| 资产查询/到期处置（2026-08-19 新增） | ITAM | EMS 聚合入口（只读展示 + 到期预警队列项） | ITAM 资产台账 API · 合同到期事件 · 与 CMDB 双向对账（ic-013） |
| ICT 服务数据接入（2026-08-19 新增） | ITAM + FSM + NPM | EMS 聚合入口（只读展示 · 不重造交付系统） | 线路资产（ITAM）· 海外建站进度（FSM 服务工单）· 跨境拨测（NPM）——服务手臂数据作为 EMS 输入展示 |

**核心约束**：严格按 [03 §P2 L5](03-overall-framework.md#p2-架构层次) —— 不重造各产品原生 UI、不做子产品替代品；跨产品操作走 L4 联动编排路由表。

## P4 · SMB U-Frontline 合并视图规则

### 降级模型（[01 §P7](01-user-persona-workday.md#p7--客户规模档位与-persona-降级模型)）

| 档位 | IT 部门规模 | Persona 映射 | 工作台视图 |
|:---|:---|:---|:---|
| SMB 档 | 10-40 人 | U1+U2 → **U-Frontline** · U3+U4 → U-Manager | 合并视图（本 PRD 覆盖 U-Frontline；U-Manager 随 W4 治理面板落地） |
| 中大型企业档 | 40-200+ 人 | U1/U2/U3/U4 四类清晰分离 | 分角色视图 |

> **出海客户（2026-08-19）**：出海中企按**中大型档四类 Persona** 处理（总部 + 海外分支合并分档 · 01 §P7 出海客户档位处理）；"总部-海外"跨区域协同视图（区别于 SMB 合并视图——不是角色合并而是区域协同）在 02 §P4 出海支撑度盘点后另行评估，W2 不扩展。

### U-Frontline 合并规则（[05 §P2](05-product-form-factor.md#p2--两个核心模式)）

1. **队列**：显示所有类型（告警 + 工单 + 派工 + 交接 + SLA 预警 + 审批），一人同时处理简单告警和疑难排查
2. **AI 建议深度**：完整版（RCA Top3 + 证据链 + 历史相似案例），不因合并降级
3. **不强制分账号**：单账号在合并视图内完成 U1 动作（转单/派工/通知）与 U2 动作（排查/变更）两类操作
4. **分档展示**：视图名标注「U-Frontline · SMB 档」；租户规模档位由 License/租户属性判定 → 角色模板自动映射，用户无需手动切换
5. **效能口径**：SMB U-Frontline 效能倍数与中大型档 U1/U2 一致（×1.5-2.5，POC 校准 · 对齐 01 §P7 口径）

## P5 · 队列数据模型与排序规则

### 统一待办项模型（05 §P2 关键设计决策）

不管来源是告警/工单/审批，在队列里都是一个「待办项」（item）：

| 字段 | 说明 |
|:---|:---|
| 类型 | 告警 / 工单 / 派工 / 审批 / 交接 / SLA 预警 / **资产事件**（2026-08-19 新增 · ITAM 合同/维保到期） |
| 优先级 | P1-P4 |
| 标题 | 一句话事件摘要 |
| 来源 | 所属产品（ITOM / ITSM / FSM / **ITAM** / M3 转单 / 交接…） |

### 队列项状态模型（2026-08-19 链段化新增 · 操作闭环的 PRD 侧定义）

每类队列项定义**状态流转**（操作入口在工作台 · 行为链路在后续链段）：

| 队列项类型 | 状态流转（示意） | 关键状态迁移的操作 | 链路归属 |
|:---|:---|:---|:---|
| 告警 | 待处理 → 已认领 → **已转单** → 已关闭 | 认领（工作台内）· 转单放行（L2 抽屉 · 反应性处置链）· 关闭 | 反应性处置链 |
| 工单 | 处理中 → 待确认 → 已解决 → 已关闭 | 处理/升级（工作台内入口）· 解决确认 | 反应性处置链 |
| 派工 | 待接单 → 已接单 → 执行中 → 已完成 | 接单/转派（工作台内）· FSM 回传状态 | 反应性处置链 |
| 审批 | 待审批 → **已放行 / 已驳回** | 放行（L2 抽屉 · 工作台 + 治理闭环）· 驳回留痕（T5） | 治理闭环 |
| 交接 | 待认领 → 已认领 → 已闭环 | 认领（工作台内）· 跨时区交接单 AI 起草 | 计划性与履约链 |
| SLA 预警 | 预警中 → 已升级 / 已解除 | 升级/加急（工作台内） | 反应性处置链 |
| 资产事件 | 待处理 → 已发起续约 / 已处理 | 发起续约（联动 ITSM 变更 · 计划性与履约链） | 计划性与履约链 |
| 项目事件 | 待审批 → 已审批 / 已驳回 | 工时/报告审批（工作台 + 出海与 MSP） | 出海与 MSP |

> **对原型的要求**：原型需演示至少一条完整状态流转（如告警：待处理 → 已转单 → 队列项标记"已转单"并链接 ITSM 工单）——这是"链可走通"在工作台层的体现。

### 排序规则

- 默认 **AI 排序**：综合优先级 × 时间 × SLA 紧迫度 × AI 置信度（L1 建议档）
- 用户可切换：按时间 / 按域 / 按优先级 / 按类型（05 §P6 可配置）
- 点击队列项 → 右侧面板加载对应详情（不跳转）；深操作 → 「在新标签打开」进入完整 Domain Page

### SN 对标补全项（P7 对标结论，原型需补齐）

- **批量操作**：批量确认 / 批量关闭 / 批量转派，单次最多 100 条（SN F-04 BR-03）
- **上下文面板含「最近变更」**：关联 CI + 服务拓扑 + 历史告警 + 最近变更（SN F-04 AC-02）
- **SLA 分档倒计时**：不同优先级 SLA 时长不同，从进入队列开始计时（SN F-04 BR-04）

## P7 · 竞品对标（SN Service Ops Workspace）

对标来源：`itom-reverse/competitors/servicenow-itom/service-reliability-management/service-ops-workspace/`（E-02 Epic · F-03/F-04/F-05 逆向文档）。

### SN SOW 与我们设计的一致性

| SN SOW 能力 | 我们的对应设计 |
|:---|:---|
| 「单一窗口」零工具切换（5-8 次 → 0 次） | N1「一屏做完」核心目标（P1 KPI 表同源） |
| 告警队列按优先级 × 新鲜度排序 | AI 排序规则（优先级 × 时间 × SLA × 置信度） |
| 告警上下文面板（CI 详情/服务拓扑/历史告警） | 右侧详情面板（关联 CI · 影响面 · 历史相似案例） |
| SLA 分诊倒计时 | 队列 SLA 预警类型 + slaRemaining |
| 一键创建 Incident | 告警转工单 L2 起草放行 |
| 可配置工作空间（按团队/区域/服务） | 角色→默认首屏绑定 + 队列过滤器可配置（05 §P6） |

### 差异与结论

| # | 差异 | 结论 |
|:--:|:---|:---|
| D1 | SN 有**批量操作**（确认/关闭/转派，≤100 条） | **补全**：U1 高频动作，加入 P5 原型规格（本 PRD P5 已登记） |
| D2 | SN 上下文面板含**最近变更** | **补全**：变更窗口是分诊关键上下文，加入右侧面板规格 |
| D3 | SN SLA 时长**按优先级分档** | **对齐**：队列 SLA 预警按 slaLevel（Gold/Silver）分档倒计时 |
| D4 | SN 支持**多 Workspace 机制**（团队各自定制布局） | **不照搬**：我们的形态是「角色绑定默认首屏 + 队列过滤器配置」（05 关键设计决策 #1），角色视图由 RBAC 决定，不做自由创建 Workspace 的复杂度——但保留队列排序/过滤器可配置 |
| D5 | SN Major Incident **作战频道**（协作 + 时间线） | **反应性处置链承接**：对应 L4 联动链（N2）设计输入，不在工作台范围 |
