# AI Agent / MCP 产品能力总结（求职用）

> 基于 ems-product 仓库实际设计文档提炼，可作为简历改写、面试自我介绍与作品集讲解的底稿。
> 关键词：AI Agent 产品设计 · MCP 工具生态 · 智能运维（AIOps）· 自主权分级治理 · 执行闭环 · 商业化

---

## 一、一句话定位

**企业级智能运维平台的 AI Agent 产品操盘者**：独立完成「价值主张 → 平台架构 → Agent 目录 → MCP 工具生态 → 治理体系 → 计费模式 → 单 Agent PRD」的全链路产品设计，把 6 大运维产品线（监控/CMDB/工单/现场服务/网络/资产）的传统运维能力，重构为 **14+ 个内置 Agent、6 个产品级 MCP Server（28+ 工具）、L1-L3 自主权分级治理** 的 AI 产品体系。

## 三、核心能力详解（面试展开用）

### 3.1 Agent 体系设计 —— 「场景编码 + 契约 + 治理」三件套

- **Agent 六要素定义**：标识与目标 / 场景范围（触发页面与事件）/ 输入输出契约 / Skill 使用 / CLI 范围 / 治理配置（模型、档位、预算、熔断、发布、审计）。
- **分层 Agent 架构**：平台通用 Agent（A1 文本理解、A2 知识检索 RAG、A3 摘要生成、A4 风险评估、A5 数据质量巡检、A6 对话助手、A7 调度推荐）由平台统一托管，各产品按场景调用；产品域 Agent（告警降噪、根因分析、容量预测、链路健康、资产巡检等）深耕单产品数据。
- **关键设计决策**：模型不在全平台自由选择 Agent，业务页面通过**稳定场景编码**调用指定 Agent——避免「通用 AI 助手」式失控入口，每个 AI 入口必须绑定具体业务场景。
- **单 Agent PRD 方法论**：11 章标准结构（定位复用结论 / 用户场景 / 范围边界 / 触发前置条件 / 输入输出契约 / 业务流程与确定性规则 / 模型职责与提示词约束 / Skill 与 CLI 要求 / 状态异常降级 / 权限审计计量 / 验收标准），每份 PRD 带可度量成功指标（如根因分析 Top3 命中率 ≥85%、30 秒内完成初步分析、MTTR ≤15 分钟）。

### 3.2 工具抽象 —— Agent / Skill / CLI 三层职责分离

- **Skill = Markdown 格式 AI 工作流文件**：描述任务步骤、判断规则、参数获取、证据要求与风险边界；强制声明机器可校验的 JSON Schema 输入输出契约，且必须定义输入缺失、证据不足、调用失败、超时、校验失败五种异常处理策略。
- **EMS CLI = Agent 访问业务能力的唯一工具接口**：将 6 大产品 API 封装为 Agent 友好的命令行（`ems itom alert get`、`ems cmdb ci relations`、`ems fsm dispatch candidates` 等），具备按需发现（--help）、结构化输出、身份继承、可审计、版本兼容九项产品要求。
- **明确不做的边界**：CLI 不是脚本上传/自由 Shell/工具注册平台——防住「Agent 变成任意代码执行器」的安全风险，这是面试中讲边界感的最佳素材。

### 3.3 MCP 应用设计 —— 产品级 MCP 生态

- **6 个产品 MCP Server**：CMDB（CI 查询/拓扑/影响面）、ITOM（告警/指标/静默）、ITSM（建单/SLA/知识 RAG）、FSM（派工画像）、NPM（拨测/Traceroute）、ITAM（台账/备件/盘点）。
- **端点全生命周期管理**：生成（范围+权限+限额配置）→ Token 仅展示一次 → 凭证轮换（旧 Token 立即失效）→ 吊销即断连；端点绑定签发人+租户+RBAC，审计六要素。
- **写操作安全设计**：写类 Tool（评论/状态流转/回传等）默认 ⛔ 不开放对外端点，需单独授权；组织级共享配额（频率/日次/并发/超限策略）。
- **归属判断能力**：多模态能力（语音转写/图片质检）拍板从 MCP 目录移出——「模型推理能力 ≠ 产品数据工具」，改走模型接入层。这类「什么该进 MCP、什么不该」的判断是 MCP 产品设计的核心功力。

### 3.4 安全治理 —— 让企业「敢用 AI」

- **L1/L2/L3 自主权档位**：L1 只保调用记录；L2 起草+人工 inline 审批；L3 端到端自动执行必须硬编码白名单；L4 明确不做。档位升级走治理审批，降级永远自由。
- **确定性规则闸门**：不用 LLM 自报置信度做执行闸门，改用「确定性规则 + 场景白名单 + 治理四层兜底（审批卡点/熔断/override/审计）」。
- **审计六要素**：身份 / 行为（场景·Agent·Skill·档位·动作）/ 模型 / 消耗（credits·token·延迟·重试）/ 决策链（审批人·证据引用）/ 内容（脱敏后输入输出，L1 只存 hash）。
- **数据安全**：调用 LLM 前剥除 PII、保留期可配（90/180/365 天对齐 GDPR 数据最小化）、密钥信封加密 + JIT 解密、数据驻留（出海部署属地存储）。

### 3.5 执行闭环 —— 从「给建议」到「办成事」

- **告警闭环主链路**：告警流入 → 告警降噪 Agent → 根因分析 Agent（Top3 根因）→ 工单起草 Agent（L2 放行）→ 调度推荐 Agent（派单确认）→ 闭环回写 + 全链路审计 + 反馈学习。
- **证据反查机制**：模型引用的每条证据必须在原始 CLI 返回结果中反查验证，删除未验证证据——根治 LLM 幻觉进生产。
- **异常兜底完整度**：CLI 能力不完整时 Agent 必须停止而非生成伪完整结论；数据不足、调用失败、超时、服务离线均有明确降级路径与用户可见状态。

### 3.6 商业化设计（稀缺加分项）

- **双层计费**：AI 功能 License（按 Agent × 期限控制开关）+ 模型用量（credits / BYOK token 显示 / 私有化免 credits）。
- **MSP 二层转售**：SaaS 平台定价转售（credits）与 MSP 自营订阅（tokens）两套独立逻辑。
- **竞品对标**：ServiceNow Now Assist（assists 计量/三档 SKU）、Salesforce Agentforce（Flex Credits 定价）、BYOK 行业实践（64% 企业买家已直签 LLM 合约、平台收软件费+平台费）——定价决策有数据支撑。

## 四、代表 Agent 设计故事（STAR 素材）

### 故事 1：根因分析 Agent（生产复用型）
**背景**：ITOM 已有生产级 RCA 能力（防火墙端口 Down/CPU/内存/设备离线四类告警）。
**方案**：不重写算法，只重构承载——Agent 由 AI 平台托管、经 CLI 取数、进统一审计计量；多数据源并行收集 → 快速预判 → 模型仅从预置原因体系输出 Top3（独立置信度不要求和 100%）→ 原始数据反查验证 → 删除未验证证据。
**结果口径**：场景覆盖率 ≥90%、30 秒初步分析、Top3 命中率 ≥85%、RCA 辅助 MTTR ≤15 分钟。
**面试点**：确定性规则（类型识别/时间范围/证据有效性）与模型职责（语义归纳/排序/建议生成）的切分。

### 故事 2：FSM 调度推荐 Agent（闭环交付型）
**背景**：调度员跨工程师档案、排班、工单、收费信息人工筛选，判断口径不一、依据难追溯。
**方案**：基于服务连续性/满意度/技能/区域/负载/收费/SLA 生成可解释 Top3 推荐（含证据与评分）；按租户档位执行 L1 自动派单、L2 人工确认、L3 高风险审批；跟踪到工程师实际认领，超时自动重派或升级人工。
**结果口径**：Top3 命中率 ≥90%、推荐采纳率 ≥80%、派单成功率 ≥90%、准时到场率 ≥90%，共 8 项可验收指标。
**面试点**：「目标是完成认领而不是生成推荐」——Agent 设计以业务终态倒推，不是以输出物为终点。

### 故事 3：MCP 目录收敛（边界判断型）
**背景**：MCP 目录从 7 收敛回 6：多模态（语音/图片）曾被登记为第 7 个 MCP Server。
**决策**：语音转写/图片质检是模型推理能力而非产品数据工具，移出 MCP 目录改走模型接入层；对外通过平台能力型端点暴露（Token 签发/限额/审计照旧）。
**面试点**：MCP 的本质是「产品数据能力的受控暴露」，不是所有 AI 能力都该塞进 MCP。

## 六、高频面试问题与应答要点

| 问题 | 应答核心 |
|:---|:---|
| Agent 怎么防幻觉进生产？ | 模型只能从预置原因体系选择；引用证据必须在原始工具返回中反查，未验证即删除；不把模型输出写回为业务事实 |
| 怎么决定哪些能力做成 MCP？ | 只暴露产品数据能力；模型推理能力（多模态）走模型接入层；写操作默认封锁需单独授权 |
| Agent 安全边界怎么划？ | L1-L3 档位 + 确定性规则闸门（不用 LLM 置信度）+ 场景硬编码白名单 + 治理四层兜底；CLI 不允许用户上传脚本 |
| 多租户下 Agent 怎么管？ | 全局能力资产 + 租户运行策略 + CLI 能力门禁三层：Agent/Skill/CLI 全局一份，租户只补业务提示词与档位策略，CLI 按租户做 License 门禁 |
| 怎么衡量 Agent 效果？ | 每个 Agent PRD 定义成功指标（覆盖率/时效/命中率/采纳率/MTTR），并定义分母排除规则（无反馈、测试数据、依赖不可用不进准确率分母） |
| 和 ServiceNow 差异？ | SN 按实例计量 AI 消耗不按租户拆分（MSP 需自行加工，是我们的机会点）；EMS 以跨六产品端到端闭环为差异化（SN 监控弱、Datadog 无工单派工） |
