# AI Agent、Skill 与 EMS CLI 定位说明

> 本文是 EMS AI 平台关于业务场景、模型、Agent、Skill 与 CLI 的权威设计基线。EMS 采用官方 CLI 作为 Agent 访问业务能力的唯一工具接口，不建设或保留第二套 Agent 工具接入方式。

## 1. 核心结论

1. 业务页面通过稳定场景编码调用指定 Agent，模型不在全平台自由选择 Agent。
2. Agent 负责理解目标，并依据提示词自主选择可用 Skill、规划步骤、调用 CLI、验证证据并组织结果。
3. Skill 是 Markdown 格式的 AI 工作流文件，描述任务步骤、注意事项和输出要求。
4. EMS CLI 是官方提供的产品能力命令行，把 EMS 各产品 API 转换为适合 Agent 发现、调用和组合的命令。
5. CLI 不是用户上传脚本、自由 Shell、运维脚本市场或工具注册平台。
6. EMS 内部 Agent Runtime 预装 CLI，并自动继承当前用户或平台服务身份；用户无需登记、安装或提前授权内部产品命令。
7. Agent 通过命令帮助与配套 Skill 按需发现能力，不在每次请求中加载全部工具定义。
8. 内部产品访问由 EMS RBAC、租户与对象权限自动控制；外部应用连接才需要管理员配置认证、租户映射和权限范围。
9. AI 平台及 CLI 不受 Corteza 低代码设计规范约束；Corteza 仅是部分产品 API 的底层实现。

## 2. 核心定义

### 2.1 业务场景

业务场景定义 AI 能力的稳定入口，包括场景编码、触发页面或事件、目标 Agent、输入对象、输出契约和治理策略。

### 2.2 模型

模型负责语言理解、推理、规划和生成，不直接连接业务数据库，不自行决定权限，也不把生成内容视为业务事实。

### 2.3 Agent

Agent 是面向明确业务目标的智能能力单元。一个 Agent 至少包含：

| 组成 | 定义 |
| :--- | :--- |
| 标识与目标 | 稳定 Agent ID、业务目标和完成标准 |
| 场景范围 | 可触发 Agent 的场景编码、页面、事件和对象 |
| 输入输出 | 启动上下文、结构化结果、证据和错误契约 |
| Skill 使用 | 模型依据提示词与任务上下文按需读取 Markdown Skill |
| CLI 范围 | Agent 允许调用的命令域、命令和动作范围 |
| 治理配置 | 模型、L1/L2/L3、预算、熔断、发布和审计 |

### 2.4 Skill

Skill 是模型可按需加载的专业任务知识包，包含：

- 适用条件与任务目标。
- 推荐分析步骤和判断规则。
- 所需业务上下文。
- 推荐使用的 CLI 命令域或命令模式。
- 参数获取方法、结果解释和证据要求。
- 输出结构、失败处理和风险边界。

每个 Skill 必须声明可机器校验的输入与输出契约：

- 输入使用 JSON Schema，至少包含 `scene_code`、`tenant_id` 和 `context`；可按场景扩展约束和业务对象字段。
- 输出使用 JSON Schema，至少包含 `conclusion`、`confidence`、`evidence`、`unverified`、`suggested_actions` 和 `trace_id`。
- Skill 必须定义输入缺失、证据不足、CLI 调用失败、超时和输出校验失败时的处理策略。
- Skill 测试必须同时验证测试样本、推荐命令范围和模拟结果是否符合输入输出 Schema。

Skill 不持有权限，不替代 Agent，也不与 Agent 或 CLI 建立配置绑定。Agent 根据提示词、任务上下文和可用能力自行选择 Skill 与 CLI。AI 平台只负责 Skill Markdown 文件的导入、删除和内容预览。

### 2.5 EMS CLI

EMS CLI 是 EMS 官方维护、面向 Agent 优化的统一命令行产品。它封装 EMS 产品 API，提供稳定命令、按需帮助、结构化输入输出、身份认证、错误反馈和调用审计。

示例：

```text
ems itom alert get --alert-id ALT-20260918-001
ems cmdb ci relations --ci-id CI-10028
ems npm path diagnose --target 10.20.3.18
ems itsm incident create --from-alert ALT-20260918-001
ems fsm dispatch candidates --work-order WO-20260918-006
```

CLI 的产品要求：

| 要求 | 说明 |
| :--- | :--- |
| Agent 友好 | 命令命名稳定，帮助清晰，错误信息给出可执行修正建议 |
| 按需发现 | Agent 通过 `--help`、命令索引和 Skill 获取所需能力，不常驻加载全部定义 |
| 结构化输出 | 默认支持 JSON 等机器可读格式，并保留来源、分页和错误语义 |
| 内部身份 | 内部产品命令自动继承当前用户或平台服务身份，无需单独登记授权 |
| 外部连接 | 外部应用由管理员配置连接、认证、租户映射和权限范围 |
| 权限继承 | 内部命令继承 EMS 租户、角色、产品域和业务对象权限 |
| 可组合 | 支持筛选、分页、批处理和必要的命令组合，减少无效上下文 |
| 可审计 | 记录身份、租户、Agent、Skill、命令、对象、结果和耗时 |
| 版本兼容 | 命令、参数和输出遵循兼容策略，破坏性变更必须升级主版本 |

CLI 不提供用户自定义命令注册、脚本上传、任意二进制发布或自由 Shell 管理能力。

### 2.6 命令来源

| 来源 | 示例 | 接入与认证 |
| :--- | :--- | :--- |
| EMS 内部产品 | ITOM、ITSM、FSM、ITAM、PMS、CMDB、NPM | 平台内置；CLI 随 Agent Runtime 提供，自动继承当前用户或平台服务身份，不需要用户登记、安装或提前授权 |
| 外部应用 | 客户已有系统、第三方 SaaS、厂商平台 | 由平台管理员建立外部应用连接，完成认证、租户映射、权限范围和健康检查后，由 EMS 官方 CLI 命令访问 |

外部应用接入不等于用户注册 CLI 命令。命令仍由 EMS 官方交付，管理员只配置外部系统连接。

## 3. 职责边界

| 对象 | 核心职责 | 不承担的职责 |
| :--- | :--- | :--- |
| 业务页面 | 提交场景编码和业务上下文，展示运行过程与结果 | 选择 Skill、拼接 CLI 命令、复制 Agent 编排 |
| 场景配置 | 固定目标 Agent、输入输出和治理策略 | 让模型任意选择 Agent |
| Agent | 理解目标、选择 Skill、规划和调用 CLI、校验证据 | 绕过权限、直接访问内部数据库 |
| Skill | 提供专业方法和 CLI 使用知识 | 持有权限、执行命令、承担完整业务目标 |
| EMS CLI | 提供真实业务查询与操作能力 | 规划完整任务、生成综合业务结论 |
| 模型 | 在边界内推理、选择和组织结果 | 决定权限或把推测写成确认事实 |

## 4. 固定与动态边界

| 固定配置 | 运行时动态决策 |
| :--- | :--- |
| 场景编码和目标 Agent | 本次加载哪些 Skill |
| Agent 提示词、任务上下文与平台可用能力 | 运行时选择哪些 Skill 与 CLI |
| 必需上下文与确定性校验 | 分析步骤和补充证据顺序 |
| 用户、租户、对象权限和自主权档位 | 如何综合证据形成建议 |
| 输出契约和高风险动作规则 | 证据不足时继续、降级或停止 |

## 4.1 平台配置与租户运行策略

EMS AI 平台采用“全局能力资产 + 租户运行策略 + CLI 租户能力门禁”三层结构，不为每个租户复制 Agent、Skill 或 CLI 定义。

| 层级 | 作用域 | 内容 | 维护方式 |
| :--- | :--- | :--- | :--- |
| 全局能力资产 | 平台全局 | Agent 定义、默认模型、启停状态、系统基础提示词、Skill 库、CLI 命令与输入输出契约 | 平台统一维护 |
| 租户运行策略 | Agent × 租户 | 租户业务提示词、生效档位、待审批档位 | 在 Agent Hub 选择租户后维护；档位升级经 AI 治理审批 |
| CLI 租户能力门禁 | CLI × 租户 | 产品 License、模块、基础字段、状态映射、适配器和健康状态 | CLI 调用前自动检查 |

边界规则：

1. Agent 只有一份全局定义，不按租户复制。默认模型和启停状态对所有租户生效。
2. 租户只能补充业务提示词，不能覆盖系统基础提示词、安全边界、权限规则和输出契约。
3. 自主权档位按租户生效。L1/L2/L3 档位变更先形成带租户的治理申请，审批通过前继续执行原档位。
4. Skill 进入平台全局 Skill 库，不按租户拆分。系统预置与用户导入 Skill 均可被 Agent 按任务发现。
5. Skill 导入必须提供名称、用途或摘要和 Markdown 文件；Skill 不持有租户权限。
6. CLI 命令名称及结构化契约全局统一，不为租户复制命令。CLI 根据目标租户选择产品适配并执行能力门禁。
7. CLI 能力不完整时，Agent 必须停止依赖该能力的场景，不得根据缺失数据生成伪完整结论或执行动作。
8. “全部租户（MSP视角）”只用于汇总查看和筛选。租户运行策略保存、治理申请、CLI 测试及业务执行必须解析到一个具体租户。
9. 原型暂时同时保留页面内租户选择器和右下角全局租户切换器，两者必须共享租户数据源、选项和语义；最终采用哪一个入口由研发实现评审决定。

### 4.1.1 CLI 租户能力门禁

每条 CLI 命令必须声明所需产品模块、基础字段、状态映射和输出契约。运行前至少执行：

```text
目标租户识别
→ 产品 License 检查
→ 产品模块检查
→ 基础字段与状态映射检查
→ 当前身份、租户与对象权限检查
→ CLI 执行
```

检查结果分为：

- `ready`：能力完整，允许 Agent 调用。
- `missing_module`：目标租户未开通所需产品或模块。
- `missing_field`：产品存在，但缺少 CLI 契约要求的基础字段。
- `mapping_invalid`：业务状态或字段映射不完整。
- `unhealthy`：适配器或产品服务不可用。

能力门禁失败时，CLI 返回租户、缺失项、影响场景和修复建议。业务页面显示 AI 能力暂不可用，不展示确认或自动执行入口。

### 4.1.2 FSM 智能派工最低能力

| 模块 | 最低要求 |
| :--- | :--- |
| FSM 工单 | 工单编号、状态、类型、描述、服务网点、费用或预算、技能要求、SLA 时间 |
| 工程师画像 | 工程师编号、姓名、级别、技能、服务范围、接单状态、状态恢复时间、收费标准 |
| 工程师负载 | 作业中、已申请验收、其他未完成工单、最大容量 |
| 状态映射 | 待派单、待认领、作业中、已申请验收、已结束 |

上述能力不完整时，FSM 调度推荐 Agent 不生成推荐，L1 也不得自动派单。

FSM 调度推荐 Agent 按租户支持 L1 自动执行、L2 手工确认和 L3 业务审批。首次推荐的触发对象必须处于待派单且尚未指定候选工程师；待认领期间由 FSM 继续响应 SLA 计时并在既有阈值发布事件。Agent 根据租户提示词选择 Skill，由 Skill 结合 FSM 返回的当前/最大重派次数决定重派或升级人工；FSM 对最大次数实施最终校验。L3 每次执行都提交目标产品业务审批流。派单可包含一个或多个候选工程师，系统同时通知，最先认领者成为处理工程师。

L1 由业务状态事件触发，不依赖用户打开页面。租户未获得 Agent License 时，业务页面不展示对应 AI 功能，也不产生 Agent 待办或调用。智能派工使用不可删除的系统预置必需 Skill；必需 Skill 缺失或解析失败时停止运行并回退到手工派单。

CLI 返回原始事实、数据来源、统计时点和完整度；Skill 定义评分权重、归一化、并列排序和缺失处理；Agent 产品契约定义硬性过滤、权限、状态、输出和执行边界。

关键数据缺失时停止推荐；非关键数据缺失时可以返回部分完成结果，但对应证据必须标记未验证。运行失败统一展示原因、各 CLI 结果、处理建议与日志入口，并回退到 FSM 原有手工派单。业务派单权限沿用 FSM 调度员权限，无权限用户只读查看推荐。

## 5. 标准运行链路

```text
业务页面或事件
  → 提交场景编码和业务对象
场景配置
  → 路由到指定 Agent
Agent
  → 校验身份、租户、权限与治理策略
  → 按需加载 Skill
  → 依据任务和 Skill 选择 EMS CLI 命令
EMS CLI
  → 使用当前用户或平台服务身份调用 EMS 产品 API
  → 返回结构化事实、来源和错误
Agent
  → 校验证据并形成分析、建议或拟执行动作
业务页面
  → 展示结果，或按 L2/L3 进入人工确认/审批
```

内部产品命令调用的有效权限为以下范围的交集：

```text
Agent 允许的命令范围
∩ 当前用户或平台服务身份权限
∩ 当前租户范围
∩ 当前身份对应的产品角色
∩ 业务对象权限
∩ 场景治理策略
```

## 6. Skill 与 CLI 的关系

1. EMS CLI 提供业务能力，Skill 以 Markdown 工作流描述处理方法。
2. Agent 不配置 Skill 或 CLI 绑定关系，而是依据提示词和任务上下文动态选择。
3. Skill 可以在 Markdown 中给出命令示例，但不形成系统配置依赖。
4. CLI 权限始终由执行身份、租户和业务对象权限决定。
5. CLI 版本发布时同步提供官方 Skill；Agent 运行环境重载后发现新能力。
6. Skill 缺失或匹配不足时，Agent可查询 CLI 帮助；仍无法确认时停止并提示能力不足。

## 7. ITOM 根因定位示例

1. 告警中心以 `itom.alert.root-cause-analysis` 场景编码调用根因分析 Agent。
2. Agent 使用 CLI 获取告警、指标、CI、拓扑、历史事件和近期变更。
3. 模型根据证据选择同源告警聚类、网络故障诊断或变更影响分析 Skill。
4. Skill 指导 Agent按需调用路径诊断、指标查询、日志检索等 CLI 命令。
5. Agent 交叉验证命令返回的事实，输出 AI 推测根因、置信度、证据和未验证项。
6. 用户确认后记录人工确认根因。
7. 如需创建事件，Agent 在 L2/L3 规则下调用 `ems itsm incident create`，不切换其他工具协议。

## 8. AI 平台承载

| 能力 | 产品职责 |
| :--- | :--- |
| Agent Hub | 管理 Agent 的模型、提示词、场景档位、发布和测试 |
| Skill 管理 | 导入、删除和预览 Markdown 工作流文件 |
| CLI 管理 | 展示 CLI 版本、内部产品命令、外部应用连接、运行状态和调用记录 |
| 场景档位 | 管理 L1 自动执行、L2 手工确认、L3 业务审批和熔断 |
| AI 治理 | 管理高风险命令范围、Agent 发布、权限扩大和审计 |
| AI 计费 | 统计模型、Agent、Skill 与 CLI 调用用量和成本 |

AI 平台不提供 CLI 命令注册、脚本上传或制品发布。CLI 命令随 EMS 产品版本由研发统一交付。

## 9. 当前版本边界

1. 只提供 EMS 官方 CLI，不开放用户自定义 CLI。
2. 首期仅覆盖 EMS 内部产品，不交付外部应用连接。
3. 首期按已确定业务场景提供最小命令集，不一次性封装全部产品 API。
4. 内部产品命令自动继承当前用户或平台服务身份。
5. 首期提供官方预置 Skill 和用户导入 Skill；用户只可导入 Markdown、删除导入文件和预览内容，不提供在线编辑、测试、发布或绑定配置。
6. CLI Runner 只执行目录内 EMS 命令，不提供自由 Shell、管道和重定向。
7. 高风险写命令继续受 L1/L2/L3、审批和熔断约束。
8. 外部应用官方 CLI 适配、连接管理和 CLI 分发升级属于后续版本。
9. 不建设、不暴露、不兼容其他 Agent 工具协议。

## 10. 设计检查清单

- [ ] 页面通过稳定场景编码调用指定 Agent。
- [ ] Agent 不配置 Skill 或 CLI 绑定，通过提示词和运行时上下文动态选择。
- [ ] Skill 不持有权限，只提供方法和 CLI 使用知识。
- [ ] CLI 命令具有稳定输入、结构化输出和明确错误语义。
- [ ] 凭证不进入模型上下文或命令日志明文。
- [ ] 用户、应用、租户和对象权限均在调用时校验。
- [ ] 高风险写命令符合自主权和治理规则。
- [ ] 场景、Agent、Skill、CLI 命令与结果能够关联审计。
- [ ] AI 推测与人工确认事实明确区分。
