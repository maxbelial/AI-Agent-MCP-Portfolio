# Feature - AI 平台运营控制台

> AI 平台提供模型接入、Agent Hub、Skill 管理、EMS CLI 与场景档位五类运营能力。EMS CLI 是 Agent 访问 EMS 业务能力的唯一工具接口。

| 属性 | 内容 |
| :--- | :--- |
| 所属主题 | EMS 标准方案 AI |
| 所属 Epic | AI 平台 |
| 所属菜单 | AI → AI 平台 |
| 对应页面 | `prototype/ai/ai-platform.html` |
| 权威基线 | `AI-Agent-Skill-CLI定位说明.md` |
| 状态 | 待评审 |

## 1. 产品目标

1. 统一管理模型、Agent、Skill 文件、EMS 内置 CLI 和场景自主权。
2. 业务页面通过场景编码稳定调用 Agent。
3. Agent 在边界内动态选择 Skill 和 EMS CLI 命令。
4. 通过当前用户或平台服务身份、EMS 权限和治理策略控制 CLI 访问。
5. 对场景、Agent、Skill、命令和结果形成完整审计。

## 2. 范围边界

### 2.1 本期范围

- 云端模型与本地模型接入。
- 内置 Agent 配置、测试、发布和停用。
- Skill Markdown 文件导入、删除和详情预览。
- EMS CLI 内置产品命令、运行状态、运行测试和调用记录。
- L1 自动执行、L2 手工确认、L3 业务审批、熔断和审计。

### 2.2 不在本期

- 用户注册 CLI 命令。
- 上传脚本、可执行程序或自定义二进制。
- 自由 Shell 管理平台。
- 同时维护第二套 Agent 工具协议或兼容层。
- Agent 市场和跨 Agent 自由编排。
- 外部应用连接和第三方系统 CLI 适配。
- CLI 制品分发、灰度升级和多运行环境管理。

## 4. 用户与权限

| 用户 | 主要职责 |
| :--- | :--- |
| AI 平台管理员 | 管理模型、Agent、Skill、CLI 接入状态和发布 |
| CLI 管理员 | 管理内部命令可用范围、运行健康和调用记录 |
| Agent 负责人 | 配置 Agent 模型、提示词和运行参数并运行测试 |
| 治理审批人 | 审批高风险命令范围、Agent 发布和档位变更 |
| IT 技术人员 | 使用业务页面 AI 能力并查看可解释结果 |
| 审计人员 | 查看配置、身份、命令和业务结果调用链 |

申请人与最终审批人必须分离。普通运维用户不得编辑 Agent、Skill、CLI 配置或模型。

## 5. 页面需求

### 5.1 模型接入

模型供给只分为平台模型池与 BYOK 池。模型实例保留名称、供应商、接入类型、接入点、鉴权、归属租户、能力标签、上下文窗口、最大输出 Token、QPS、超时、Token 单价和状态。接入类型分为云端 API、本地模型服务。实际输入和输出 Token 由调用自动计量，不在接入时预设。

平台模型由 AI 平台管理员在模型接入页新增、修改和测试。BYOK 由计费中心按租户登记凭证、服务地址和模型标识，验证通过后自动同步只读模型实例到模型接入页，模型接入页只负责能力测试、启用和停用。凭证使用密钥服务别名管理，不回显明文。

MVP 每个租户、每个部署环境仅允许一条生效 BYOK。Agent 维护全局平台默认模型和备用模型；租户存在已启用 BYOK 时，运行时优先使用该 BYOK，不复制 Agent 配置。BYOK 调用失败时不得静默回退平台模型池，页面返回明确原因并按业务场景提供重试或手工处理入口。

### 5.2 Agent Hub

Agent 详情至少展示：

| 分组 | 内容 |
| :--- | :--- |
| 基础信息 | Agent ID、名称、目标、负责人、产品域和状态 |
| 场景入口 | 场景编码、页面、触发方式、输入输出契约 |
| 模型 | 平台配置默认模型和备用模型；候选范围为已测试通过并启用的模型 |
| 提示词 | 产品维护系统基础提示词；租户只补充业务偏好 |
| 自主权 | L1/L2/L3、人工确认、审批和熔断策略 |
| 发布 | 当前版本、变更摘要、测试结果和审批状态 |
| 运行 | 成功率、耗时、成本、最近失败和调用记录 |

Agent 不配置 Skill 或 CLI 绑定。Agent 定义、默认模型和启用状态为全局配置；业务提示词和运行档位按租户维护。模型根据任务上下文和系统提示词从平台全局 Skill 库及可用 CLI 中按需选择；任何 Skill、提示词或模型建议均不得绕过身份、租户、对象权限和场景治理策略。

模型接入不配置“测试环境、指定 Agent、全平台、私有化环境”等混合范围。测试由模型状态表达，部署方式不作为模型范围；平台模型与 Agent 的关系统一在 Agent 默认模型和备用模型中配置，业务用户不直接选择模型。SaaS 可选择平台模型池或 BYOK，私有化部署只使用 BYOK。

模型解析顺序固定为：校验 Agent License → 读取租户生效 BYOK → 校验模型能力与状态 → 使用租户 BYOK；没有租户 BYOK 时使用 Agent 的平台默认模型，默认模型不可用时才使用平台备用模型。每次调用统一记录租户、Agent、模型实例、供给来源、输入 Token、输出 Token、credits、耗时、状态和 trace ID；平台池按 credits 计费，BYOK 只记录 token 与租户成本归属。

内置 Agent 的名称、ID、能力、场景入口、触发条件和输入输出契约由产品定义并随版本交付，不允许租户修改。默认模型和启用状态为平台全局配置；租户只维护业务提示词、测试样例，并在场景支持范围内申请调整自主权档位。研发实现组合、能力编号、内部案例集、CLI 选择机制和发布灰度不在租户页面展示。

FSM 调度推荐 Agent 默认采用 `L2 手工确认`，按租户配置 L1/L2/L3：低风险白名单可使用 L1，高风险工单强制使用 L3。档位和高风险判定规则变更必须进入 AI 治理，审批前使用当前版本。FSM 负责响应 SLA 计时、阈值事件、当前重派次数和最大重派次数；Agent 不配置时间阈值。租户提示词可以明确优先加载的智能派工 Skill，不同 Skill 可在收到同一 FSM SLA 事件后选择重派或升级人工，但不得越过 FSM 返回的最大重派次数。运行测试执行 dry-run，并展示实际加载的 Skill、FSM 事件与次数事实、各项 CLI 结果、排除原因、Top 3 推荐证据和 trace ID；测试不得执行派单或改变工单状态。

### 5.3 Skill 管理

| 能力 | 说明 |
| :--- | :--- |
| Skill 文件 | Markdown 工作流文件 |
| 来源 | 系统预置、用户导入 |
| 详情 | 预览 Markdown 原文与基础文件信息 |
| 维护 | 导入 `.md` 文件；删除用户导入文件；系统预置文件不可删除 |

Agent 不与 Skill 建立配置绑定。Skill 不按租户拆分，导入时填写名称、用途或摘要并选择 Markdown 文件，统一进入全局 Skill 库。Markdown 文件名是提示词引用的稳定标识，平台禁止重复文件名。运行时由 Agent 根据租户提示词、任务上下文和 Skill Markdown 内容自主选择处理方法。运行时必须验证 Skill 存在、已启用、适用当前场景与事件，并记录最终选择的 Skill 及原因。指定 Skill 不可用时停止自动执行并回退产品人工流程，不允许模型猜测替代高风险工作流。

CLI 当前版本只展示 EMS 内置命令，提供详情、运行测试和调用记录。平台不提供外部 CLI 接入、命令注册、在线编辑或发布入口。CLI 本身不承载自动执行、手工确认或业务审批分类，这些控制由业务场景档位负责。

### 5.4 EMS CLI

EMS CLI 页面不是工具注册页面，由以下区域组成。

#### 5.4.1 状态与健康

- 当前 CLI 版本和更新时间。
- Agent 执行环境运行状态。
- CLI 服务可达性、认证状态和最近健康检查。

#### 5.4.2 运行环境

- EMS 内部 Agent Runtime 默认预装并托管 CLI，普通用户不需要安装或配置。
- 页面展示首期运行环境的 CLI 版本和健康检查。
- CLI 或官方 Skill 更新后由平台统一重载 Agent Runtime。
- 面向外部 Agent 的 CLI 分发能力不属于本期 EMS 内部 AI 平台原型范围。

#### 5.4.3 命令目录

| 字段 | 说明 |
| :--- | :--- |
| 命令域 | `itom`、`cmdb`、`npm`、`itsm`、`fsm`、`itam`、`pms` 等 |
| 命令 | 稳定命令路径，如 `itsm incident create` |
| 用途 | 命令解决的业务任务 |
| 输入 | 参数、类型、必填、来源和约束 |
| 输出 | 结构化字段、分页、证据来源和错误码 |
| 权限 | 所需产品权限、租户和对象范围 |
| 状态 | 可用、受限、异常、已废弃 |

#### 5.4.4 内部产品身份

- EMS 内部产品命令由平台内置，无需用户登记或提前授权。
- 交互任务自动继承当前用户的租户、角色和对象权限。
- 定时任务和后台 Agent 使用平台托管的服务身份，绑定明确租户、角色、命令和对象范围。
- MSP 跨租户命令必须使用具备相应范围的平台服务身份，并记录实际目标租户。
- 首期不提供外部应用连接。
- 自动执行、手工确认或业务审批由业务场景档位决定，不属于 CLI 命令分类。

#### 5.4.5 调用记录

每次调用至少记录时间、场景、Agent、Skill、CLI 版本、命令、身份类型、租户、业务对象、参数摘要、结果、耗时、错误和关联业务动作。

### 5.5 场景档位

| 档位 | 定义 | 执行规则 |
| :--- | :--- | :--- |
| L1 自动执行 | 自动完成只读分析，或在已批准白名单内执行低风险、可验证动作 | 高风险对象和动作不得配置为 L1；命令、对象和条件必须命中自动执行规则 |
| L2 手工确认 | Agent 可组合只读分析与数据变更，形成拟执行动作后由业务用户确认 | 单次确认与治理审批无关，但执行前重新校验权限、对象状态和影响 |
| L3 业务审批 | 对用户或业务有高风险的动作形成不可变快照，每次任务提交目标产品的业务审批流 | 审批人和节点由 ITSM/FSM、ITOM/CMDB 等目标产品流程决定；审批通过且执行前复核成功后，由系统执行快照 |

Skill 选择和只读命令不单独决定档位；档位由最终业务动作风险决定。场景档位按 `租户 × Agent 场景` 配置，同一场景在不同租户可以采用不同档位。平台必须阻止把高风险对象或动作配置为 L1，例如将高等级告警关联的现场任务自动分配给缺少资质或经验不足的工程师。L3 运行任务不进入 AI 治理待审批队列；AI 治理中心只审批档位、自动执行规则和平台发布，并只读审计业务审批结果。

L3 统一的是审批提交契约，不统一替换产品审批引擎。契约至少包含租户、目标产品、Agent 场景、业务对象、拟执行动作、冻结证据快照、申请人、执行身份和结果回调。ITSM/FSM 路由到 Corteza 业务审批流，ITOM/CMDB 路由到各自审批服务；产品返回审批中、通过、驳回、撤回或失效结果。通过后 Agent 必须重新校验对象状态、权限、CLI 能力和熔断状态，再执行原快照。

全局熔断阈值由 AI 平台管理员统一配置，不按租户拆分。触发后暂停所有租户受影响场景的自动写动作，保留只读分析、L2 人工处理入口和原产品手工流程；熔断不等同于把任务改成 L3 审批。恢复必须由有权用户人工解除并记录审计。

Agent 未采纳抑制是平台通用策略，与技术熔断分开管理。平台提供全局默认的统计窗口、连续未采纳次数和暂停时长，并允许租户场景覆盖。统计维度为`租户 × Agent × 场景`；CLI 失败、数据不足、License 不可用和用户未看到建议不计入未采纳。命中后只暂停该租户场景的主动调用，保留手动调用、只读结果和产品人工流程，不改变档位，也不全局停用 Agent。

## 6. 标准业务链路

```text
页面提交场景编码和对象
→ 路由到指定 Agent
→ Agent 加载允许的 Skill
→ Agent 选择允许的 CLI 命令
→ CLI 使用当前用户或平台服务身份调用产品 API
→ 返回结构化事实
→ Agent 验证并形成结果
→ 按 L1/L2/L3 执行、确认或审批
→ 记录完整调用链
```

## 7. 业务规则

- **BR-01 固定场景路由**：页面不能由模型自由选择 Agent。
- **BR-02 有界动态选择**：模型只在 Agent 允许范围内选择 Skill 和命令。
- **BR-03 单一工具接口**：Agent 对 EMS 业务能力只使用官方 CLI。
- **BR-04 无命令注册**：用户不能注册命令、上传脚本或修改官方命令实现。
- **BR-05 权限交集**：内部命令有效权限为 Agent 范围、当前用户或平台服务身份、租户、角色、对象和治理策略交集。
- **BR-06 Skill 不授权**：Skill 只能提供方法和命令知识。
- **BR-07 结构化结果**：正式命令必须提供稳定机器可读输出和错误语义。
- **BR-08 凭证隔离**：凭证不得进入提示词、模型上下文或明文审计。
- **BR-09 写动作治理**：写命令执行遵守 L1/L2/L3 和产品业务校验。
- **BR-10 全链路审计**：场景、Agent、Skill、命令与业务结果必须可追溯。
- **BR-11 失败透明**：命令失败、权限不足和数据缺失不能由模型伪装成功。
- **BR-12 版本兼容**：破坏性命令变化必须升级主版本并完成 Agent 兼容测试。

## 8. 验收标准

| 编号 | 验收标准 |
| :--- | :--- |
| AC-01 | AI 平台展示五个功能页签，且不出现第二套工具协议入口 |
| AC-02 | Agent 不配置 Skill 或 CLI 绑定，通过提示词和运行时上下文动态选择 |
| AC-03 | CLI 页面不提供注册命令、上传脚本或发布制品入口 |
| AC-04 | 用户可查看 CLI 状态、内部命令、运行健康和调用记录 |
| AC-05 | Agent 调用 CLI 时校验当前身份、租户和业务对象权限 |
| AC-06 | Agent 根据提示词与上下文动态选择 Skill 和 CLI，不依赖配置绑定 |
| AC-07 | L2 写动作必须展示拟执行命令和业务影响并由用户确认 |
| AC-08 | L3 动作审批快照包含 Agent、Skill、命令、参数摘要、对象和影响 |
| AC-09 | ITOM 根因分析调用链可追溯到 CLI 原始结果和证据 |
| AC-10 | 调用记录能够按租户、Agent、Skill、命令、状态和时间筛选 |
| AC-11 | 用户可以导入 Markdown Skill、预览内容并删除用户导入文件 |
| AC-12 | 系统预置 Skill 不允许删除，Skill 不提供在线编辑、测试、发布或 Agent 绑定 |
| AC-15 | CLI 只展示 EMS 内置命令目录、详情、测试和调用记录，不提供外部接入与在线维护 |
| AC-16 | CLI 不定义执行确认档位，L1/L2/L3 由业务场景配置 |
| AC-17 | Skill 导入仅接受 `.md` 文件，并可在详情抽屉预览 Markdown 内容 |
| AC-18 | 删除操作只对用户导入 Skill 开放，并提供二次确认 |
| AC-21 | 模型接入抽屉覆盖供应商、类型、接入点、鉴权、能力、范围、成本和场景配置 |
| AC-22 | 模型凭证仅保存密钥服务别名，连通测试通过后才能启用模型 |

## 9. 异常与降级

| 异常 | 处理 |
| :--- | :--- |
| 内部运行环境 CLI 版本不兼容 | 阻止正式运行并通知平台管理员统一升级 |
| 用户或应用无权限 | 不返回越权数据，显示权限不足 |
| Skill 不适用或缺失 | 查询 CLI 帮助或降级为无 Skill 直接调用；无法确认时停止 |
| 命令超时或部分失败 | 返回部分结果、缺失项和失败原因，不生成伪完整结论 |
| 高风险动作未确认或审批 | 不执行写命令 |
| 审计写入失败 | 正式写动作不得执行 |
