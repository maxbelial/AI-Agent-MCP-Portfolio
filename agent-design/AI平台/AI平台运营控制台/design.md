# AI 平台运营控制台设计

## 1. 设计基线

- EMS CLI 是 Agent 访问 EMS 业务能力的唯一工具接口。
- CLI 是 EMS 官方命令行产品，不是脚本注册、上传或发布平台。
- Skill 为 Agent 提供专业方法与 CLI 使用知识，不持有权限。
- 页面固定调用场景 Agent，Agent 在允许范围内动态选择 Skill 和命令。
- AI 平台不适用 Corteza 低代码设计规范。
- 首期只覆盖 EMS 内部产品 CLI，外部应用连接属于后续版本。

## 2. 页面结构

| 页签 | 核心任务 |
| :--- | :--- |
| 模型接入 | 管理模型连接、能力、状态和成本 |
| Agent Hub | 管理 Agent 的场景、模型、提示词和发布 |
| Skill 管理 | 导入、删除和预览 Markdown 工作流文件 |
| EMS CLI | 查看内部命令、运行健康和调用记录 |
| 场景档位 | 管理 L1/L2/L3、规则、审批和熔断 |

模型供给只分为平台模型池与 BYOK 池。模型接入页使用右侧抽屉维护平台模型；BYOK 在计费中心按租户登记，验证后同步为只读模型实例。配置包括模型名称、供应商、接入类型（云端 API/本地模型服务）、接入点、鉴权方式、凭证别名、归属租户、能力标签、上下文窗口、最大输出 Token、QPS、超时及输入输出 Token 单价。平台只保存密钥服务中的凭证别名，不保存或回显明文密钥。

模型按“草稿 → 测试通过 → 运行中 → 已停用”流转，测试至少验证鉴权、基础对话和 JSON 结构化输出。Agent 只维护全局平台默认模型与备用模型；租户生效 BYOK 在运行时覆盖默认模型。MVP 每租户、每部署环境只允许一条生效 BYOK，失败时不静默回退平台池。

## 3. EMS CLI 页面设计

### 3.1 顶部状态

展示当前版本、运行状态和近 24 小时调用成功率。不提供安装、注册、上传或外部连接入口。

### 3.2 命令目录

按产品域组织 EMS 内置命令，支持搜索和状态筛选。命令行展示名称、用途、状态和调用情况，不展示读写、风险、确认方式或 Agent 绑定分类。

命令详情包含：

- 命令格式和使用示例。
- 参数、结构化输出和错误码。
- 当前用户或平台服务身份权限要求。
- 适用场景和调用情况。
- 命令状态和废弃说明。
- 运行测试和调用记录入口。

### 3.3 运行环境

EMS 内部 Agent Runtime 预装 CLI，并自动继承当前用户或平台服务身份，不提供面向普通用户的安装认证流程。首期只展示单一运行环境的版本、状态和健康检查，不提供 CLI 分发升级与外部应用连接管理。

### 3.4 调用记录

调用链按“场景 → Agent → Skill → CLI 命令 → 业务结果”展示。用户可以查看参数摘要、租户、对象、耗时、退出状态、结构化结果和错误，但不能查看敏感凭证。

## 4. Agent 页面设计

Agent 不配置 Skill 范围或 CLI 命令范围。Agent 通过提示词定义目标、方法和边界，并在运行时根据任务上下文从平台可用 Skill 与 EMS 内置 CLI 中动态选择。实际 CLI 调用仍校验当前身份、租户和业务对象权限。
- 当前用户或平台服务身份决定本次调用的实际业务权限。

运行测试必须显示实际选择的 Skill、实际命令、权限校验和结果来源。

### 4.1 配置分层

| 层级 | 维护责任 | 内容 | Agent Hub 是否可改 |
| :--- | :--- | :--- | :--- |
| 产品定义 | 产品与研发 | Agent ID、业务目标、场景编码、页面入口、触发条件和输入输出契约 | 否 |
| 平台实现 | 研发与 AI 平台运营 | 系统基础提示词、CLI 命令实现、Skill 发现机制、权限校验、结构化输出、审计与熔断 | 否 |
| 租户运行策略 | 租户 AI 管理员或 Agent 负责人 | 租户业务提示词和目标运行档位 | 是；档位升级按治理流程生效 |

Agent、模型和启用状态为平台全局配置，不按租户复制；Skill 进入全局 Skill 库。仅业务提示词与生效档位按租户维护。产品定义和平台实现属于版本交付物。Agent Hub 只展示用户完成配置、验证和日常运营所需的信息，不展示能力编号、研发实现组合、内部模板数量、CLI 选择说明、案例集版本或发布灰度比例。

### 4.2 内置 Agent 编辑规则

- 内置 Agent 不允许修改名称、ID、业务能力、页面入口、触发条件和输入输出契约。
- 系统基础提示词只由产品版本维护；租户只能补充业务偏好，不得覆盖安全边界、权限校验和输出契约。
- Agent 不建立 Skill 或 CLI 绑定关系，也不向用户提供能力选择器。
- 启用或停用与保存业务配置是两个独立动作，均记录审计。
- 自主权档位允许按场景支持范围调整。由 `L2 手工确认`升级为`L1 自动执行`时只提交治理申请，不立即生效；高层治理审批通过后才发布新档位。申请人与审批人必须分离。
- 发布灰度由平台运营在发布系统中管理，不属于租户 Agent 配置。首期租户侧只展示当前租户是否启用。
- Few-shot 与评测样本由产品与研发维护。样本可来自标准案例、脱敏后的人工确认结果和采纳/改派反馈，经评审后随 Agent 版本发布，不允许租户在线编辑。

### 4.3 FSM 调度推荐 Agent

| 项目 | 设计要求 |
| :--- | :--- |
| 固定目标 | 为处于待派单且尚未指定候选工程师的 FSM 工单生成可解释 Top 3 推荐 |
| 默认档位 | `L2 手工确认`，用户确认推荐后执行派单并将工单置为待认领 |
| 可申请档位 | 按租户申请 `L1 自动执行`或`L3 业务审批`；治理审批通过后生效，审批前保持当前档位 |
| 推荐依据 | 技能、服务范围、接单状态、当前负载、收费匹配和到场时效 |
| 固定约束 | 排除离线、服务范围不符或关键技能缺失人员；不得绕过租户、对象和人员权限 |
| 全局可配 | 默认模型、Agent 启用或停用 |
| 租户可配 | 派工偏好补充、目标运行档位 |
| 不可配置 | Agent 能力、场景入口、Skill/CLI 选择机制、系统基础提示词和输出结构 |
| 测试输入 | 当前租户内一张待派单且尚未指定候选工程师的工单编号 |
| 测试方式 | Dry-run，仅生成推荐，不修改候选工程师、不通知工程师、不改变工单状态 |
| 测试结果 | 前置校验、实际读取的 Skill、CLI 调用及耗时、排除人员及原因、Top 3 推荐与证据、版本和 trace ID |

测试必须校验 License、租户与对象权限、工单状态、未指定工程师、Skill 可读、三项 FSM CLI 可用和输出契约。任一前置条件失败时停止测试并给出明确原因，不生成伪完整推荐。

L1 由 FSM 工单状态事件触发，不依赖用户打开列表或详情页。工单进入待派单且尚未指定候选工程师时，事件提交租户与工单编号；Agent 完成推荐和派单后，业务页面只读取并展示结果。原型允许以页面加载模拟事件结果，但研发不得将页面访问作为运行条件。

租户 License 必须参与所有入口的可用性判断。未授权 FSM 调度推荐 Agent 时，FSM 工单、我的待办、现场服务等业务页面不渲染 AI 推荐区，也不产生 AI 派工待办；AI 平台管理页可显示“Agent 未开通”供管理员识别。授权变更后由 License 服务发布能力变更事件。

`dispatch-recommend.md` 是智能派工不可删除的系统基础 Skill。租户提示词可以明确优先加载其他已导入 Skill，以实现“无人认领后优先重派”或“直接升级人工”等不同策略；这不是 Agent 与 Skill 的配置绑定。运行时必须记录提示词版本、最终 Skill ID/版本和选择原因。指定 Skill 不存在、无法读取、解析失败或不支持当前事件时停止自动执行并保留 FSM 手工派单。用户 Skill 不能改变权限、FSM 最大重派次数、硬性过滤和执行档位。

派单可以选择一个或多个候选工程师。派单完成后系统同时通知全部候选人，任一候选人先认领即成为处理工程师，工单随后进入已派单；候选人不存在“拒绝”操作。长期无人认领的超时、升级和重新派单策略不纳入本期，作为后续迭代项。

智能派工按租户配置 L1/L2/L3。低风险白名单可使用 L1 自动派工，普通工单默认 L2 由调度员确认，高等级告警关联工单、关键站点或其他高风险条件强制使用 L3 业务审批。三个档位使用相同的候选过滤、评分和证据要求，只改变动作执行闸门。L3 每次把派工快照提交 FSM 所属业务审批流，审批节点由 FSM/低代码审批配置决定，AI 治理中心不处理该运行任务。待认领期间由 FSM 响应 SLA 继续计时并发布阈值事件；Agent 根据租户提示词选择 Skill，由 Skill 结合 FSM 返回的当前/最大重派次数决定重派或升级人工。平台未采纳抑制或全局熔断命中时停止主动调用。

运行失败采用统一状态：显示失败或受限原因、工单/工程师/负载/历史履约/派工历史/满意度 CLI 的独立结果、处理建议和运行日志入口，同时保留 FSM 原有手工派单操作。Agent 按平台统一超时时限与重试次数执行，超过限制后结束本次运行，不持续占用业务页面。

关键数据包括工单状态、服务网点、关键技能、工程师服务范围、接单状态和有效负载；缺失时停止推荐。收费或预计到场时间等非关键数据缺失时允许输出部分完成结果，但必须在候选证据中标记“未验证”，不得伪造数值。接单状态读取失败时，L1 本次运行降级为 L2，不改变租户生效档位。

档位变更必须保留当前档位、申请档位、申请人、申请时间、适用租户、风险说明和审批记录。审批完成前，业务页面继续执行当前生效档位；驳回后不得改变运行行为。

### 4.4 CLI 租户能力检查

CLI 命令及输入输出契约全局统一，但每次执行前必须按目标租户检查产品能力。FSM 智能派工至少要求：

- FSM 工单模块：工单编号、状态、类型、描述、服务网点、费用或预算、技能要求、SLA 时间。
- 工程师画像模块：工程师编号、姓名、级别、技能、服务范围、接单状态、状态恢复时间和收费标准。
- 工程师负载模块：作业中、已申请验收、其他未完成工单和最大容量。
- 状态映射：待派单、待认领、作业中、已申请验收和已结束。

#### 4.4.1 CLI 字段来源与新鲜度

| 事实 | CLI 来源 | 口径与新鲜度 |
| :--- | :--- | :--- |
| 接单状态 | FSM 工程师接单状态 | 返回可接单/暂不可接单、恢复时间、原因、最后修改人和修改时间；暂不可接单直接排除，读取失败时禁止 L1 自动执行 |
| 工程师覆盖范围 | 工程师服务范围、正在处理工单的站点、最近签到位置 | 返回原始来源；Agent 综合判断是否覆盖目标站点 |
| 服务范围 | FSM 现场工程师档案 | 必须包含可服务区域或站点集合 |
| 技能与认证 | FSM 现场工程师档案 | 返回技能、认证及有效期；过期认证不得视为满足关键技能 |
| 收费标准 | FSM 工程师档案 | 返回币种、计费单位和标准费率 |
| 实时负载 | FSM 已接单且尚未验收的工单 | 以 Agent 运行时点为统计时点；作业中和其他未验收计 1，已申请验收计 0.5 |
| ETA | FSM 服务区域经验值 | 返回经验 ETA 及适用区域，不使用实时地图路线作为当前版本依赖 |
| 预计完成时间 | 工单定义的期望完成时间、当前站点相似工单 SLA 解决时间、其他站点同类型工单 SLA 解决时间 | 对有效样本取平均；缺少某类样本时使用剩余有效来源并标记完整度 |
| 历史费用 | 当前站点相似工单实际费用 | 与工程师标准收费共同计算预计费用；无有效历史时仅展示工程师标准收费 |

CLI 只返回原始事实、来源、统计时点和数据完整度，不计算最终匹配度。权重、归一化、并列排序和非关键字段缺失处理由系统 Skill 定义；Agent 产品契约负责硬性过滤、权限、状态和输出边界。

预计费用口径：存在有效站点相似工单历史时，取“工程师标准收费估算”和“站点相似工单历史平均费用”的平均值；无有效历史时取工程师标准收费估算。结果必须展示币种、计算来源和完整度。

缺少产品模块、字段或状态映射时，每项 CLI 分别返回成功、失败或数据不完整及具体缺失项。关键数据缺失时 Agent 不得生成推荐；业务页面展示“AI 派工暂不可用”、处理建议和日志入口，不提供确认或自动执行入口。非关键数据缺失时展示部分完成结果，并在对应证据上标记未验证。

### 4.5 原型验收链路

1. AI 平台选择业务租户，打开 FSM 调度推荐 Agent。
2. 页面读取全局 Agent 状态、当前租户提示词与生效档位，并执行 FSM CLI 能力检查。
3. CLI 能力完整时，可保存租户提示词并申请变更租户档位；能力不完整时禁止申请 L1 自动执行。
4. 档位申请进入 AI 治理中心，记录租户、当前档位、目标档位、申请人与审批节点。
5. 高层治理角色审批通过后，仅更新申请租户的生效档位；驳回不改变原档位。
6. MSP 我的待办按派工记录所属租户检查 CLI 能力，不使用当前页面导航租户替代业务对象租户。
7. 进入 FSM 工单详情时同步工单所属租户。L2 展示推荐并等待确认；L1 自动派单并进入待认领；L3 每次生成冻结的派工快照并提交 FSM 业务审批。
8. Agent 停用或 CLI 能力缺失时，我的待办和 FSM 工单均展示不可用原因，不提供 AI 确认或自动执行入口。
9. 派工结果按租户与工单隔离保存，并进入 AI 治理审计。
10. 租户选择器包含“全部租户（MSP视角）”和具体租户。MSP 汇总视角只能查看能力概况，保存租户策略、提交治理申请或运行测试前必须切换到具体租户。
11. 原型阶段页面内选择器与右下角全局切换器并存，且使用同一租户数据源；研发落地时可统一为其中一种交互，不得改变租户范围语义。
12. 所有智能派工入口统一展示生成时间、调用编号、CLI 结果摘要和审计入口；无派单权限时结果只读，并提示“没有派单权限”。派单权限沿用 FSM 标准产品的调度员权限，不由 Agent 另建权限体系。
13. 状态统一为：待派单 → 选择候选工程师 → 待认领 → 任一候选人认领 → 已派单。手工派单和 AI 派单使用同一状态机；待派单阶段不展示转派。

### 4.6 指标口径与效果反馈

- 推荐采纳率分母：成功生成可用推荐的工单数；CLI 失败、关键数据不足和未形成推荐的调用不进入分母。
- 推荐采纳率分子：L2 下用户确认全部推荐候选或选择任一推荐候选的工单数，加上 L1 自动执行的工单数。
- 推荐后工单取消不从统计中排除，因为该工单已经使用 Agent 并获得推荐。
- 最终履约结果、是否准时到场、转派情况和实际处理工程师必须回写到 Agent 运行记录，用于评估推荐质量及后续规则、Prompt 和模型优化。
- 每张工单只按一次有效推荐进入采纳率；重复运行以最终被执行的推荐版本为准，历史版本保留审计记录。
- 准时到场率分母为已使用 AI 派单、存在有效计划到场时间且实际进入到场状态的工单数；分子为实际到场时间不晚于计划到场时间的工单数。客户主动改期后使用最新确认时间；到场前取消、缺少时间戳及测试数据不进入分母。
- 转派率单独统计。AI 推荐工程师认领后又被转派，仍计入推荐采纳，但标记履约结果为“后续转派”，不得计入成功履约样本。
- 多候选人派单时，只要最终认领者属于本次推荐集合即视为推荐命中；Top 1、Top 2、Top 3 分别保留排名，用于计算 Top 1 命中率和 Top 3 命中率。

### 4.7 权限配置

| 权限 | 作用域 | 约束 |
| :--- | :--- | :--- |
| 查看 AI 推荐 | FSM 业务对象权限 | 与工单查看权限一致 |
| 确认或手工派单 | FSM 调度员权限 | 无权限时推荐只读并显示提示 |
| 维护 Agent 全局配置 | AI 平台管理权限 | 可维护默认模型与全局启停 |
| 维护租户提示词、申请档位 | AI 租户策略管理权限 | 只能维护授权租户 |
| 导入用户 Skill | AI Skill 管理权限 | 不得删除或替换系统必需 Skill |
| 审批档位变更 | AI 治理审批权限 | L1/L2/L3 按租户生效；申请人与审批人必须为不同用户，系统必须校验 |
| 查看运行日志和证据 | AI 审计查看权限 | 同时受租户和业务对象权限限制 |

## 5. Skill 页面设计

Skill 是 Markdown 格式的 AI 工作流文件，全部进入平台全局 Skill 库，不按租户拆分。页面只提供文件导入、删除和详情预览，不提供表单化新增、在线编辑、测试、发布、版本流转或 Agent 关联。系统预置 Skill 不允许删除，用户导入 Skill 可以删除。

导入时必须填写 Skill 名称、用途或摘要并选择 `.md` 文件；名称和用途不得只依赖文件内容自动生成。选择文件后可以预览 Markdown，确认后进入全局 Skill 库。

Skill 详情使用右侧抽屉预览 Markdown 原文和文件信息。导入使用本地 `.md` 文件选择器；系统读取文件名、大小、更新时间与文本内容后保存。删除仅适用于用户导入 Skill，并需要二次确认。

CLI 当前版本只提供 EMS 内置命令目录、命令详情、运行测试和调用记录，不提供外部 CLI 接入、命令注册、在线修改或发布管理。CLI 不定义 L1/L2/L3，也不区分自动执行或手工确认；执行控制由业务场景和 Agent 档位决定。

## 6. 删除的旧设计

原型调整时必须删除：

- 产品工具双分类。
- 工具注册、脚本上传和执行制品审核。
- 对外工具端点、Token 生成、轮换和吊销。
- Agent 的旧工具授权区域。
- 任何第二套工具协议兼容入口。
