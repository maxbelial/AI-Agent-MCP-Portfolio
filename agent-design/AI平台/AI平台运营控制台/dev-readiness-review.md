# 研发就绪复审

## 1. 当前结论

产品方向已收敛为 EMS 官方 CLI 单一工具接口。首期只建设内部产品 CLI 最小闭环，不包含外部应用连接、脚本注册、自由 Shell 和 CLI 分发平台。完成首批命令与 Runner 方案确认后即可进入原型和研发拆解。

## 2. 阻断项

| 优先级 | 待确认项 | 输出物 |
| :--- | :--- | :--- |
| P0 | 首期 CLI 产品域与命令清单 | 命令目录、读写属性、权限、输入输出 |
| P0 | 内部身份传递 | 当前用户身份、平台服务身份、租户范围和失效规则 |
| P0 | Agent Runtime 执行 CLI 方式 | 命令形成、Runner 解析校验、隔离、超时和输出协议 |
| P0 | 场景到 Agent 的注册规范 | 场景字段、版本、输入输出、失败和降级 |
| P0 | Agent 运行时能力发现与实际权限计算 | 可用能力目录、权限交集和拒绝原因 |
| P1 | 官方 Skill 提供与加载机制 | 包结构、发现、加载和适用规则 |
| P1 | 调用链和计量事件 | 运行事件、审计字段和成本口径 |

## 3. 原型改造前检查

- [ ] 不再出现工具注册或脚本上传入口。
- [ ] 不再出现对外工具端点和独立 Token 管理。
- [ ] CLI 页面只展示内部命令、运行健康和调用记录。
- [ ] Agent 页面不提供 Skill/CLI 绑定或选择器，只开放租户可维护配置。
- [ ] Skill 页面区分系统预置与用户导入，只提供 Markdown 导入、预览及用户导入文件删除。
- [ ] 业务页面调用链能够展示实际 CLI 命令和证据来源。

## 4. 研发拆分建议

1. ITOM 根因分析首批 CLI 命令。
2. 当前用户与平台服务身份传递。
3. Agent Runtime 与受控 CLI Runner。
4. 官方 Skill 加载。
5. 最小 AI 平台配置面。
6. 运行审计与治理。
