## 2. Agent 定位

### 2.1 一句话定义

ITSM 事件理解与分配 Agent 面向服务台、事件经理和 NOC 值守人员，在事件工单创建或待分配时，先理解事件描述与告警上下文，自动识别告警信息、影响范围、关联 CI、事件分类、SLA 等级、优先级和重要性等标签；再优先复用 ITSM 已配置的固定分单规则；当规则未命中、规则冲突、命中结果不完整或存在 SLA/VIP/风险例外时，基于分类结果、相似事件历史处理人、处理组能力、工程师技能与负载、排班、SLA、风险等级和客户 VIP 身份，推荐或自动写入最合适的处理人或处理组，并保留可追溯的分类与分单证据。

### 2.2 与 FSM 调度推荐 Agent 的区别

| 维度 | FSM 调度推荐 Agent | ITSM 事件理解与分配 Agent |
| :--- | :--- | :--- |
| 业务对象 | 现场工单 | ITSM 事件工单 |
| 动作目标 | 派给一个或多个候选工程师，等待工程师认领 | 先补全事件分类/标签，再直接分配处理人或处理组，无需认领 |
| 后续闭环 | 关注候选工程师是否认领，支持无人认领后的重派或人工升级 | 不维护认领计时，不做重派；SLA 临期或处理异常由 ITSM 事件 workflow 的升级机制处理 |
| 候选形态 | Top 3 工程师，可同时通知候选人 | Top 1 推荐分配对象，备选处理组/处理人用于人工核对 |
| SLA 使用方式 | 用于派工及时性、无人认领重派和到场/完成判断 | 用于决定分配优先级、目标处理层级和是否进入人工确认；SLA 升级动作由 ITSM 自身执行 |
| 排班依赖 | FSM 已有现场工程师排班 | ITSM 当前未设计排班系统，方案预留 ITSM 值班/On-call 排班能力 |
| 失败回退 | 保留手工派工、转派和人工升级入口 | 保留 ITSM 原有手工分配；不得自动转派或重派 |

### 2.3 背景与业务问题

- 当前问题：ITSM 已支持用户基于工单字段和状态配置固定分单规则；对老客户而言，长期沉淀的规则通常非常准确，不能被 Agent 另起一套逻辑覆盖。
- 现有方式：事件创建或字段变化后，ITSM 按固定分单规则把工单分配到处理组或处理人；分单规则未覆盖、规则冲突、字段缺失、VIP/高风险例外和处理人可用性不足时，再由服务台人工判断。
- 主要痛点：固定规则适合稳定、确定的分单场景，但对新客户冷启动、规则空白、跨字段复杂例外、相似历史复用、排班/负载感知和规则有效性解释支持不足。
- 新增痛点：告警转工单或人工提单时，事件描述、告警摘要、CI、影响范围、分类、SLA 等级、优先级和重要性可能不完整或不一致，导致固定分单规则无法命中或命中不准确。
- 改善目标：Agent 不替代固定分单规则，而是在规则体系之上做“事件理解、标签补全、规则解释、分单规则补位、例外识别、候选建议和效果反馈”，在不改变 ITSM 事件 workflow 和现有规则权威性的前提下，提高分单规则命中质量和分单规则未覆盖场景的首次分配准确性。

### 2.4 业务目标

1. 兼容并优先尊重 ITSM 固定分单规则，避免与老客户既有规则发生抢权。
2. 根据事件描述、告警信息、影响范围和关联 CI 自动补全事件分类、SLA 等级、优先级、重要性和标签，为固定规则和智能分单提供结构化输入。
3. 优先复用相似事件的成功处理经验，尤其是同客户、同服务、同 CI、同类别事件的历史处理人或处理组。
4. 将 VIP、优先级、风险等级、SLA 剩余时间和排班可用性纳入统一评分。
5. 保证自动分类和自动分单不绕过 ITSM 权限、字段白名单、状态机、SLA 和事件升级 workflow。
6. 对数据不足、无候选、权限不足、排班缺失等情况透明降级到手工补字段或手工分配。

### 2.5 成功指标

| 指标 | 目标值 | 度量方式 | 统计范围与排除项 |
| :--- | :--- | :--- | :--- |
| 分单覆盖率 | >= 90% | 固定规则解释成功 + Agent 成功生成可用建议的事件数 / 满足触发条件的授权事件数 | 未授权、无权限、关键字段缺失单独统计 |
| 首次分配时效 | >= 95% 在平台阈值内完成 | 阈值内完成建议或自动分配的次数 / 成功启动次数 | CLI 超时和服务异常单独统计 |
| 自动分配成功率 | >= 95% | L1 成功写入处理人或处理组的事件数 / L1 尝试事件数 | 对象状态变化、权限拒绝单独统计 |
| 分配采纳率 | >= 80% | L2 确认建议 + L1 自动分配 / 成功生成建议的去重事件数 | 测试运行、受限结果不进入分母 |
| 首次分配准确率 | 待基线评审 | 无需人工改派且最终解决的 Agent 建议/补位事件数 / Agent 建议或补位后已关闭事件数 | 固定规则直接命中事件单独统计，不混入 Agent 推荐准确率 |
| 规则补位有效率 | 待基线评审 | 固定规则未命中、冲突、失效或结果不完整时被采纳的 Agent 建议数 / 进入补位流程的事件数 | 老客户成熟规则场景需单独看补位价值 |
| SLA 风险降低 | 待基线评审 | Agent 建议/补位事件的响应超时率与人工处理基线对比 | 固定规则直接命中事件单独统计；按优先级、VIP、团队分别统计 |
| 自动分类采纳率 | >= 85% | AI 自动分类/标签未被人工修改的事件数 / 已生成分类建议的事件数 | 固定规则原生字段完整的事件单独统计 |
| 固定规则命中提升 | 待基线评审 | AI 补全字段后固定规则成功命中的事件数 / 原始字段未命中的事件数 | 需记录补全前、补全后两次规则评估 |

### 2.6 Agent 不负责的事项

- 不负责创建、关闭、解决或审批事件工单。
- 不替代 ITSM 字段字典、SLA 策略、优先级矩阵和重要性定义；只能在授权字段范围内建议或写入结构化标签。
- 不替代 ITSM 事件 workflow、SLA 计时、升级规则和通知机制。
- 不维护“认领”状态，不判断无人认领，不执行重派。
- 不覆盖已经命中且成功执行的 ITSM 固定分单规则。
- 不自行修改、生成或删除客户现有固定分单规则。
- 不在未满足对应档位执行条件的情况下写入事件分类、标签、处理人或处理组：L1 需通过自动执行规则、ITSM 权限和执行前复核；L2 需用户确认采纳且通过当前用户 ITSM 权限；L3 需业务审批通过。满足条件后，由 Agent 通过 ITSM CLI 完成字段或分配写入。
- 不自行创建团队、用户、技能、排班或 SLA 事实。
- 不把缺失数据推断为正常、空闲或低风险。

## 3. 用户与使用角色

| 角色 | 使用目的 | 允许的主要操作 |
| :--- | :--- | :--- |
| 服务台坐席 | 查看推荐并确认事件分配 | 查看证据、确认处理组/处理人、改为手工分配 |
| 事件经理 | 处理高优先级、VIP 或异常分单 | 查看风险原因、确认或覆盖分配建议、跟进升级 workflow |
| NOC 值守人员 | 快速分配告警转事件 | 查看建议、确认分配、补充分类或影响信息 |
| 处理组负责人 | 了解本组被分配原因和负载 | 查看分单证据和审计，不直接维护 Agent 规则 |
| AI 平台管理员 | 维护 Agent 启停、模型、档位和租户策略 | 配置默认模型、运行测试、申请档位变更 |
| 测试人员 | 验证规则、边界和异常 | 执行 Dry-run，核对候选、证据和回退 |
| 平台运维 | 保障 Agent 运行稳定 | 查看调用日志、失败原因、性能和依赖状态 |

业务分配权限沿用 ITSM 标准产品权限；AI 平台配置、治理审批和审计查看使用 EMS AI 平台权限。

## 4. 业务范围与边界

### 4.1 支持范围

| 范围项 | 支持内容 | 备注 |
| :--- | :--- | :--- |
| 业务对象 | ITSM 事件工单 | 必须能唯一识别租户和事件编号 |
| 事件状态 | 待分配、已登记未分配、处理组为空或处理人为空 | 具体状态名以租户 ITSM 状态映射为准 |
| 分配对象 | 处理组、处理人，或处理组 + 处理人 | 默认优先保证处理组正确；可配置是否直达处理人 |
| 固定分单规则 | 读取并尊重 ITSM 现有分单规则命中结果 | 规则命中且执行成功时，Agent 只解释和审计，不覆盖 |
| 租户范围 | 已获得 Agent License 且 ITSM 能力门禁通过的租户 | MSP 全部租户视角只允许汇总查看，不允许直接写分配 |
| 触发来源 | 事件创建/更新事件、告警转事件、用户手动重新生成、AI 平台 Dry-run | L1 由业务事件触发，不依赖页面打开 |
| 数据来源 | ITSM 事件、相似事件、团队、用户、排班、负载、SLA、客户与服务主数据、CMDB/ITOM 影响信息 | 由 EMS CLI 返回事实和来源 |

### 4.2 不支持范围

| 不支持项 | 处理方式 |
| :--- | :--- |
| 非事件类工单，如服务请求、问题、变更 | 返回不支持，保留原业务流程 |
| 已解决、已关闭、已取消事件 | 不触发，不改写历史分配 |
| 已存在有效处理人且处理组有效 | 默认不自动改派；仅允许有权限用户手动重新分析作为参考 |
| 固定规则已命中并完成分配 | Agent 不覆盖结果；只记录规则命中、解释依据和后续效果 |
| 租户未授权 Agent | 不展示智能分单入口，不产生 Agent 调用 |
| ITSM 关键字段或状态映射缺失 | 返回受限，不输出伪完整建议 |
| 无可用处理组或处理人 | 返回无候选，提示手工分配或补充团队配置 |
| SLA 临期后的升级动作 | 由 ITSM 事件 workflow 执行，Agent 只记录分单上下文 |
| 分配后再次自动改派 | 不支持；如业务需要，必须通过 ITSM 人工改派或 workflow 升级 |

### 4.3 Agent、Skill 与 CLI 分工

| 层级 | 负责内容 | 不负责内容 |
| :--- | :--- | :--- |
| Agent 产品契约 | 触发条件、硬性过滤、权限、状态、输出、L1/L2/L3 行为和审计 | 不定义租户业务事实 |
| Skill | 分单评分、排序、相似事件解释和缺失处理 | 不授予权限，不执行 ITSM 升级，不越过状态机 |
| EMS CLI | 返回事件、团队、用户、SLA、排班、负载、历史事件等原始事实 | 不计算最终推荐，不决定是否自动写入 |
| 模型 | 依据已验证事实组织推荐理由、风险说明和摘要 | 不编造事实，不绕过硬性过滤和治理策略 |

### 4.4 与固定分单规则的兼容策略

ITSM 固定分单规则是确定性业务配置，优先级高于 Agent 推荐。Agent 的默认定位不是替代规则引擎，而是增强规则体系的可解释性、覆盖率和例外处理能力。

| 固定规则结果 | Agent 行为 | 是否允许写入 |
| :--- | :--- | :--- |
| 单一规则命中，已成功写入处理组/处理人 | 不重新推荐，不覆盖；记录规则命中结果、命中字段、规则版本和效果跟踪 | 否 |
| 单一规则命中，但只给出处理组，租户允许 AI 补处理人 | 在处理组范围内推荐处理人；排班、负载或权限未验证时降级 L2 | 按档位 |
| 多条规则命中且结果冲突 | 不自动选择；输出冲突规则、字段依据、推荐优先项和人工确认建议 | L2 或 L3 |
| 规则未命中 | Agent 按相似历史、职责、SLA、VIP、风险、排班和负载生成建议 | 按档位 |
| 规则命中对象不可用，如处理组停用、处理人离职或无权限 | 标记规则失效风险，推荐有效备选，并建议维护规则 | L2，必要时 L3 |
| 命中规则与高风险/VIP 策略冲突 | 不自动覆盖；提示风险并进入人工确认或审批 | L2 或 L3 |

兼容原则：

1. 规则命中且写入成功时，Agent 不消耗正式模型调用生成替代建议；可记录轻量审计和效果指标。
2. 规则未命中、冲突、执行失败或命中结果不完整时，Agent 才进入推荐流程。
3. Agent 的推荐结果不能反向修改固定规则；规则优化只能形成“规则优化建议”，由有权限管理员人工维护。
4. L1 自动执行只允许在固定规则未命中，或固定规则只命中处理组且租户明确允许 AI 补处理人的范围内使用。
5. 新客户或规则冷启动场景可以更多依赖 Agent 建议；老客户成熟规则场景应以规则结果为主、Agent 作为解释和兜底。

## 5. 业务场景与案例

### 5.1 场景清单

| 场景编码 | 场景名称 | 触发入口 | 触发方式 | 预期结果 |
| :--- | :--- | :--- | :--- | :--- |
| ITSM-ASSIGN-00 | 事件自动分类与标签补全 | ITSM 事件创建/告警转工单 | 自动分析、按档位写入或确认 | 根据描述、告警、影响范围和 CI 识别分类、SLA、优先级、重要性和标签，为固定规则评估提供结构化字段 |
| ITSM-ASSIGN-01 | L2 智能分单建议 | ITSM 事件创建/详情页 | 自动分析、人工确认 | 输出推荐处理组/处理人、备选项和证据；用户确认采纳后，Agent 使用当前用户的 ITSM 分配权限调用 CLI 写入 |
| ITSM-ASSIGN-02 | L1 自动分配 | ITSM 事件创建事件 | 自动 | 低风险、证据完整时，Agent 使用租户绑定的平台服务身份和 ITSM 权限校验调用 CLI 自动写入处理组或处理人 |
| ITSM-ASSIGN-03 | 手动重新生成 | ITSM 事件详情 | 手动 | 生成新运行记录，仅作为改派参考，不自动改写已分配事件 |
| ITSM-ASSIGN-04 | Agent 运行测试 | AI 平台 Agent 详情 | 手动 Dry-run | 展示 License、权限、Skill、CLI、候选、证据和 trace ID，不改变事件 |
| ITSM-ASSIGN-05 | 数据不足 | ITSM 事件创建事件 | 自动 | 返回受限或部分完成，明确缺失字段和手工处理建议 |
| ITSM-ASSIGN-06 | VIP 或高风险事件 | ITSM 事件创建事件 | 自动分析、人工确认或审批 | 默认降级为 L2；如租户配置高风险审批，则形成 L3 快照 |
| ITSM-ASSIGN-07 | 固定规则命中解释 | ITSM 事件创建/详情页 | 自动记录、页面查看 | 展示命中规则、命中字段、分配结果和规则版本，不生成替代推荐 |
| ITSM-ASSIGN-08 | 固定规则冲突或失效补位 | ITSM 事件创建事件 | 自动分析、人工确认 | 展示冲突/失效规则和 AI 备选建议，等待人工确认 |

- 租户：ENT 企业租户，Agent License 有效。
- 事件信息：P2，影响生产网络，关联 CI、服务、客户和告警。
- 历史事实：同一 CI 最近 90 天内 3 起类似事件均由网络二线处理组解决，其中 2 起由工程师 Lee 处理。
- 当前事实：网络二线有值班人员，Lee 当前负载可接受且在排班窗口内。
- 结果：推荐处理组“网络二线”，推荐处理人“Lee”，备选为“网络一线值班组”。
- 用户操作：服务台确认后写入处理组和处理人，事件进入 ITSM 既有处理流程。

### 5.2.1 正常案例：告警转工单自动分类

- 告警：DNS-Core-01 出现 SERVFAIL 和查询超时突增，影响 18 家门店 POS 交易。
- 原始工单：标题和描述来自 ITOM 告警，分类、SLA、优先级和重要性为空或使用默认值。
- Agent 识别：
  - 告警信息：`DNS 查询 SERVFAIL 突增`、`DNS-Core-01`、影响服务为门店联网。
  - 影响范围：18 家门店交易链路，属于客户关键业务服务。
  - 关联 CI：DNS-Core-01，CI 关键度高，归属网络域。
  - 自动标签：事件分类=网络 → DNS 解析，SLA 等级=Gold，优先级=P2，重要性=高，标签=`告警转工单`、`VIP客户`、`核心交易链路`、`DNS`。
- 结果：Agent 先写入或提交分类字段建议，再调用固定分单规则评估；若补全字段后规则命中，则采用固定规则；若仍未命中，才进入智能分单建议。

### 5.3 正常案例：固定规则已准确命中

- 事件：INC-2026-09124，邮箱账号无法登录。
- 租户：老客户，已配置成熟固定分单规则。
- 规则命中：`分类=账号与权限`、`服务=企业邮箱`、`状态=新建`，固定规则将事件分配给“办公应用一线组”。
- Agent 行为：不生成替代推荐，不覆盖处理组；仅记录命中规则、命中字段、规则版本和后续是否改派。
- 用户看到：事件详情可查看“由固定规则分配”，并可展开查看规则依据；如需改派，仍走 ITSM 原有手工改派。

### 5.4 受限案例：排班缺失

- 事件关键分类、优先级、SLA 和服务信息完整。
- 团队和技能可查询，但 ITSM 排班系统未启用或未配置。
- Agent 可以推荐处理组，但处理人可用性标记为未验证。
- L1 不得自动直达处理人；如租户允许，可自动分配处理组，或降级为 L2 等待人工确认。

### 5.5 高风险案例：VIP P1 事件

- 事件来自 VIP 客户，优先级 P1，影响核心业务服务。
- Agent 可以输出推荐处理组、建议处理人、相似事件证据和 SLA 风险说明。
- 默认不自动写入处理人；进入 L2，由事件经理确认。
- 若租户配置“VIP P1 分配需审批”，Agent 形成不可变分配快照并提交 ITSM 业务审批流。
- 审批未通过时不执行分配，事件仍保留 ITSM 原有手工处理和升级机制。

## 6. 触发、流程与状态

### 6.1 触发条件

必须同时满足：

1. 业务对象为 ITSM 事件工单。
2. 事件处于可分配状态，且处理组或处理人未满足租户分配规则。
3. 租户 Agent License 有效。
4. Agent 全局启用且租户档位有效。
5. 系统预置必需 Skill 可读取并解析。
6. ITSM 事件、团队、用户、SLA 和历史事件 CLI 能力门禁通过。
7. 当前用户或平台服务身份具有租户、事件和分配动作权限。

自动分类阶段需额外满足：事件存在可解析的描述、标题、告警摘要、告警 ID、影响范围、服务、CI 或客户上下文中的至少一类输入。若无法形成最低可信分类，Agent 不写入字段，只返回“需人工补充字段”。

若固定分单规则已命中并成功完成分配，Agent 不再进入推荐流程；只保留规则解释、审计和效果反馈。若规则未命中、冲突、执行失败，或仅命中处理组且租户允许 AI 补处理人，才继续执行智能分单。

L1 由 ITSM 事件状态事件触发，不依赖列表或详情页被打开。业务页面只负责读取结果、展示证据和提供允许的后续操作。

### 6.2 标准流程

```text
ITSM 事件进入待分配
  → 校验租户 License、Agent 启用状态与生效档位
  → 校验租户、用户或平台服务身份、事件权限和分配权限
  → 校验必需系统 Skill
  → 读取事件描述、告警上下文、影响范围、关联 CI、客户与服务信息
  → Skill 执行事件理解和自动分类：输出分类、SLA 等级、优先级、重要性、标签和置信度
  → 按字段白名单、优先级矩阵和 SLA 策略校验分类结果
  → L1：低风险且字段置信度达标时，通过 ITSM CLI 写入分类/标签；L2/L3：形成待确认或审批快照
  → 调用 ITSM 固定分单规则评估
  → 规则已命中并成功分配：记录规则解释和审计，结束 Agent 推荐流程
  → 规则未命中、冲突、执行失败或结果不完整：继续智能分单
  → 调用事件、团队、用户、排班、负载、SLA、历史事件 CLI
  → 执行硬性过滤
  → Skill 计算相似历史、技能/职责、排班、负载、SLA、VIP 和风险分数
  → Agent 形成推荐处理组/处理人、备选项、证据和未验证项
  → L2：等待服务台或事件经理确认；确认采纳后，以当前用户 ITSM 分配权限调用 CLI 写入
  → L1：执行前复核事件仍可分配，以平台服务身份和 ITSM 权限校验调用 CLI 自动写入
  → L3：提交 ITSM 业务审批流，审批通过且执行前复核成功后通过 CLI 写入
  → 记录分单结果、证据和 trace ID
  → 事件后续处理、SLA 升级和通知继续由 ITSM workflow 执行
```

### 6.3 状态边界

```text
待分配
  → 写入处理组或处理人
已分配 / 处理中
  → 后续 SLA 升级、催办、转派或改派均由 ITSM workflow 和人工流程处理
```

- ITSM 智能分单不新增“待认领”状态。
- 分配成功不等于事件已响应或已解决。
- Agent 不维护认领截止时间，不监听无人认领，不自动重派。
- 已分配事件如需改派，必须走 ITSM 原有人工改派或 workflow 升级，不由 Agent 主动触发。

### 7.1 输入信息

| 输入 | 必填 | 来源 | 用途 | 缺失处理 |

| 场景编码 | 是 | ITSM 事件或页面 | 路由智能分单场景 | 不启动 |
| 租户、用户或平台身份 | 是 | EMS 上下文 | License、权限和审计 | 拒绝运行 |
| 事件编号 | 是 | ITSM 事件 | 确定业务对象 | 不启动 |
| 事件状态 | 是 | ITSM 事件 | 判断是否可分配 | 不支持则不触发 |
| 原始描述、标题、告警来源和影响范围 | 是 | ITSM/ITOM | 理解事件类型、告警含义和影响 | 缺失则受限 |

| 关联 CI 与服务 | 告警转工单必填 | ITOM/CMDB/服务目录 | 判断技术域、业务影响、重要性和候选处理组 | 缺失则不得 L1 写入分类 |

| SLA 等级、重要性和标签 | 否 | ITSM SLA/服务目录或 Agent 分类 | 判断固定规则、SLA 和重要性 | 缺失时先进入自动分类 |
| 客户身份与 VIP 标识 | 否 | 客户主数据/合同 | 决定优先级修正和治理档位 | 缺失时标记未验证 |
| 风险等级 | 否 | ITSM/CMDB/ITOM | 决定 L1/L2/L3 和处理层级 | 缺失时不得自动降风险 |
| 固定分单规则结果 | 是 | ITSM 分单规则 | 判断是否需要 Agent 补位或推荐 | 无法评估则降级 L2 或受限 |

| 当前负载 | 否 | ITSM 事件队列 | 避免分配给过载团队或用户 | 缺失时降级 L2 |

| 事实 | 来源 | 业务口径 | 关键性 |
| :--- | :--- | :--- | :--- |
| 事件基础信息 | ITSM 事件 | 编号、状态、标题、描述、分类、优先级、服务、CI、客户、影响范围 | 关键 |
| 告警上下文 | ITOM/NPM/MOP | 告警名称、指标、阈值、级别、首次触发、持续时间、聚合关系、原始告警 ID | 分类关键 |

| SLA 信息 | ITSM SLA | 响应时限、解决时限、剩余时间、日历和暂停状态 | 关键 |
| 处理组职责 | ITSM 团队/组配置 | 分类、服务、CI、客户或区域的归属组 | 关键 |
| 处理用户资格 | EMS 用户、ITSM 用户、团队成员 | 激活状态、角色、所属组、技能、权限 | 关键 |

| 历史处理结果 | ITSM 历史事件 | 最终处理组、处理人、响应时长、解决时长、是否改派、是否超时 | 评分关键 |

| 风险等级 | ITSM/CMDB/ITOM | 事件风险、CI 关键度、业务服务影响 | 治理关键 |
| 固定分单规则 | ITSM 分单规则引擎 | 命中规则、命中字段、规则优先级、规则版本、输出处理组/处理人和执行结果 | 关键 |
| 排班 | ITSM 排班/on-call | 当前班次、值班组、可用人员、休假 | 非关键，但影响 L1 |
| 当前负载 | ITSM 队列 | 未解决事件数、P1/P2 数、接近 SLA 数、个人当前任务量 | 非关键，但影响排序 |

所有 CLI 结果必须包含数据来源、统计时间、原始记录标识、完整度和错误状态。`无数据`、`无权限`、`超时`、`服务异常`必须区分。

### 7.3 自动分类口径

自动分类不是自由生成字段，必须在 ITSM 已定义字段字典、优先级矩阵、SLA 策略和字段白名单内选择。

| 分类输出 | 来源依据 | 写入策略 |
| :--- | :--- | :--- |
| 事件分类 / 子类 | 事件描述、告警名称、CI 类型、服务目录、相似事件 | 仅允许选择字典内值；低置信度进入 L2 |
| SLA 等级 | 客户服务等级、服务目录、合同、事件影响范围 | 不自行创建 SLA；只选择 ITSM 已存在 SLA 策略 |
| 优先级 | 影响范围、紧急度、CI 关键度、客户 VIP、告警级别 | 必须通过 ITSM 优先级矩阵校验 |
| 重要性 | 业务服务关键度、客户身份、CI 关键度、影响用户或门店数 | 不得低估 VIP、核心服务或 P1/P2 告警 |
| 标签 | 告警转工单、VIP 客户、核心交易链路、DNS、数据库、网络等 | 标签需来自租户标签库或平台预置标签 |
| 关联 CI / 服务 | 告警对象、拓扑关系、CMDB 映射、服务目录 | 多 CI 冲突时只建议，不自动写主 CI |

自动分类可信度建议：

- 置信度 >= 90%，且字段均通过字典、矩阵和权限校验：可按租户档位 L1 写入。
- 置信度 70% 至 90%，或存在多候选字段：进入 L2 手工确认。
- 置信度 < 70%，关键字段冲突，或缺失 CI/服务主数据：不写入，提示人工补充。

自动分类结果必须记录补全前字段、补全后字段、依据、置信度、字段白名单校验结果和是否影响固定规则命中。

### 7.4 推荐评分口径

建议 v1 使用“硬性过滤 + 加权评分”的组合。

#### 硬性过滤

候选处理组或处理人必须满足：

1. 有权处理当前租户、客户、服务或事件分类。
2. 处于启用状态，未被停用、冻结或移出团队。
3. 具备当前事件分类、服务、CI 或技术域所需职责范围。
4. 不违反租户的 VIP、风险等级或优先级处理规则。
5. 执行前事件仍处于可分配状态。
6. 不覆盖已经成功执行的固定分单规则结果。

#### 加权评分

| 评分项 | 建议权重 | 说明 |
| :--- | :--- | :--- |
| 固定规则结果 | 前置优先 | 规则命中并成功执行时直接采用；冲突、未命中或失效时进入评分 |
| 相似事件历史命中 | 30% | 同客户、同服务、同 CI、同分类事件的成功处理组/处理人优先 |
| 职责与技能匹配 | 25% | 团队职责、用户技能、产品模块和技术域匹配程度 |
| SLA 与优先级适配 | 15% | P1/P2、响应剩余时间短、解决风险高时优先更高层级或值班组 |
| 排班与可用性 | 15% | 当前班次、on-call、休假、工作时间窗口 |
| 当前负载 | 10% | 未解决事件数、临期事件数、个人或团队容量 |
| VIP 与风险策略 | 5% | VIP 专属组、关键客户、核心服务优先规则 |

以上权重为初始建议，最终值需产品、ITSM 和 AI 平台评审。模型不得自行改变硬性过滤规则；权重调整必须形成 Skill 或配置版本。

### 7.5 推荐对象规则

| 情况 | 推荐策略 |
| :--- | :--- |
| 固定规则命中且已完成分配 | 不推荐替代对象，只解释规则命中结果 |
| 固定规则仅命中处理组 | 在该处理组内推荐处理人；若处理人条件不完整则只保留处理组 |
| 固定规则冲突或命中对象失效 | 展示规则冲突/失效原因，并给出备选建议供人工确认 |
| 能明确到处理人且排班、负载、权限完整 | 推荐处理组 + 处理人 |
| 能明确处理组但处理人可用性未验证 | 推荐处理组，处理人标记未验证或不推荐 |
| 相似事件强命中同一处理人，但该人员不在班或过载 | 推荐其所在处理组，备选展示该人员历史命中但不自动分配 |
| VIP 或 P1 事件 | 默认推荐高级处理组或值班经理确认，不直接低风险自动分配 |
| 多个处理组分数接近 | 输出首选 + 备选，说明差异和未验证项 |

| `ems itsm incident get` | tenant、incident_id | 状态、分类、优先级、描述、客户、服务、CI、SLA、当前处理组/处理人 | 获取分单目标和约束 |
| `ems itsm incident classify` | tenant、incident_id、source_context、allowed_fields、trace_id | 建议分类、SLA 等级、优先级、重要性、标签、关联 CI/服务、置信度、字段差异、校验状态 | 根据描述和告警上下文生成结构化分类建议 |

| `ems itsm incident similar` | tenant、incident_id、time_range、match_fields | 相似事件、相似度、最终处理组/处理人、响应/解决结果、是否改派 | 复用历史处理经验 |
| `ems itsm team query` | tenant、category、service_id、ci_id、customer_id | 处理组、职责范围、支持等级、启用状态、成员数 | 筛选候选处理组 |
| `ems itsm user query` | tenant、team_ids、skills、status | 用户、团队、角色、技能、权限、启用状态 | 筛选候选处理人 |
| `ems itsm schedule get` | tenant、team_ids、user_ids、as_of | 当前班次、on-call、休假、值班窗口、可用性 | 判断排班可用性 |
| `ems itsm workload get` | tenant、team_ids、user_ids、as_of | 未解决事件数、P1/P2 数、临期数、容量 | 计算负载 |
| `ems itsm sla get` | tenant、incident_id | SLA 策略、响应剩余时间、解决剩余时间、升级状态 | 判断时效和治理档位 |
| `ems itsm incident assign` | tenant、incident_id、assignment_group、assignee、reason、trace_id、execution_identity | 写入结果、事件版本、状态、审计编号 | L1/L2/L3 在完成权限校验、确认或审批后执行分配 |

CLI 能力门禁最低要求：

- ITSM 事件字段：事件编号、状态、分类、优先级、描述、客户、服务或 CI、SLA、处理组、处理人。
- ITSM 自动分类字段：分类、子类、SLA 等级、优先级、重要性、标签、影响范围、关联 CI、关联服务和置信度。
- ITSM 字典与矩阵字段：分类字典、标签字典、优先级矩阵、SLA 策略、字段白名单和可写权限。
- ITSM 团队字段：处理组编号、名称、职责范围、成员、启用状态。
- ITSM 用户字段：用户编号、名称、状态、所属处理组、角色或技能。
- ITSM 分单规则字段：规则编号、名称、优先级、启停状态、条件字段、输出对象、规则版本和最近更新时间。
- 状态映射：待分配、已分配、处理中、已解决、已关闭、已取消。
- 分配写入能力：必须支持乐观锁或事件版本校验，避免覆盖人工刚刚完成的分配。

## 9. 输出与页面要求

### 9.1 输出内容

| 输出 | 必需 | 展示要求 |
| :--- | :--- | :--- |
| 运行状态 | 是 | 分析中、待确认、待审批、已分配、部分完成、受限、失败、不支持 |
| 自动分类摘要 | 是 | 分类、SLA 等级、优先级、重要性、标签、关联 CI/服务和置信度 |
| 告警识别摘要 | 告警转工单必需 | 告警名称、级别、指标、阈值、持续时间、影响范围和来源告警 ID |
| 字段变更差异 | 按场景 | 补全前、补全后、是否已写入、写入身份和审计编号 |
| 推荐摘要 | 是 | 首选处理组、建议处理人、分配原因和 SLA 风险 |
| 固定规则摘要 | 按场景 | 命中规则、命中字段、规则版本、输出对象和执行结果 |
| 候选集合 | 是 | 首选 1 个，备选最多 2 个 |
| 候选证据 | 是 | 相似事件、职责/技能、排班、负载、SLA、VIP/风险 |
| 未验证项 | 按场景 | 明确字段、原因和对 L1/L2 的影响 |
| CLI 结果摘要 | 是 | 每项 CLI 的成功、失败或数据不完整状态 |
| 运行标识 | 是 | trace ID 或调用编号 |
| 建议动作 | 是 | 确认分配、手工分配、补充字段或查看日志 |

### 9.2 输出状态

| 状态 | 业务含义 | 页面处理 |
| :--- | :--- | :--- |
| 分析中 | 正在读取事件、历史、团队、用户、排班和 SLA | 不阻塞手工分配 |
| 待补字段确认 | 自动分类结果需人工确认 | 展示分类字段差异、确认写入和手工编辑 |
| 待确认 | 已生成建议但不自动执行 | 展示确认分配和手工分配 |
| 待审批 | 高风险场景已形成审批快照 | 展示审批状态，不执行写入 |
| 已分配 | 已成功写入处理组或处理人 | 展示分配结果和审计编号 |
| 规则已分配 | 固定分单规则已成功完成分配 | 展示规则依据，不展示替代推荐 |
| 规则冲突 | 多条固定规则命中且输出不一致 | 展示冲突规则和 AI 建议，等待人工确认 |
| 部分完成 | 可推荐处理组，但处理人、排班或负载存在未验证项 | 标明限制，L1 不得自动直达处理人 |
| 受限 | 关键字段、字段字典、优先级矩阵、权限或 CLI 能力不足 | 不展示伪候选，提示补字段或手工分配 |
| 失败 | 本次运行未完成 | 展示失败原因、重试和手工分配入口 |
| 不支持 | 事件状态或对象类型不在范围内 | 不触发后续动作 |

## 10. 权限与治理

### 10.1 自主权档位

| 档位 | Agent 行为 | 用户行为 |
| :--- | :--- | :--- |
| L1 自动执行 | 对低风险、证据完整、字段字典校验通过且状态可分配的事件，使用平台服务身份通过 ITSM CLI 自动写入分类/标签或处理组/处理人 | 查看结果；后续按 ITSM workflow 处理 |
| L2 手工确认 | 生成分类补全和分单建议但不立即写入；用户确认采纳后，Agent 使用当前用户权限通过 ITSM CLI 写入 | 服务台、事件经理确认、取消、手工编辑字段或改为手工分配 |
| L3 业务审批 | 对租户定义的高风险分类变更或分配形成不可变快照并提交 ITSM 审批流；审批通过后通过 ITSM CLI 写入 | 按 ITSM 审批配置处理 |

默认档位建议为 L2。固定规则命中且写入成功时，不视为 Agent 自动执行；这是 ITSM 规则引擎原有行为。租户可将低优先级、非 VIP、分类明确、规则未命中但相似历史稳定的事件配置为 L1。P1、VIP、核心服务、重大影响、固定规则冲突、分类置信度不足或风险等级高的事件默认不进入 L1；如需强制审批，使用 L3，但 L3 审批只约束“分类字段写入”或“分配写入”动作，不替代事件自身升级 workflow。

### 10.2 权限规则

| 权限 | 要求 |
| :--- | :--- |
| 查看推荐 | 与 ITSM 事件查看权限一致 |
| 确认分类补全 | 用户点击确认后，由 Agent 使用当前用户身份调用 ITSM CLI；必须通过 ITSM 事件字段编辑权限和字段白名单校验 |
| 确认分配 | 用户点击确认后，由 Agent 使用当前用户身份调用 ITSM CLI；必须通过 ITSM 分配权限校验 |
| 自动分类/自动分配 | 由 Agent 使用绑定到具体租户和场景的平台服务身份调用 ITSM CLI；必须通过 ITSM 权限、字段白名单和场景治理校验 |
| Agent 配置 | 需要 AI 平台管理权限 |
| 档位申请 | 需要 AI 租户策略管理权限 |
| 档位审批 | 需要 AI 治理审批权限，申请人与审批人分离 |
| L3 任务审批 | 使用 ITSM 产品业务审批流 |
| 查看审计 | 需要 AI 审计权限，并受租户与事件对象权限限制 |

## 11. 异常、降级与回退

| 异常场景 | 业务处理 | 用户表现 | 重试 |
| :--- | :--- | :--- | :--- |
| License 未授权 | 不启动 Agent | 不展示 AI 分单入口 | 授权后重新触发 |
| 系统 Skill 缺失或解析失败 | 停止推荐 | 显示失败和手工分配 | 平台修复后允许 |
| 事件关键字段缺失 | 返回受限 | 显示缺失字段和补充建议 | 补齐后允许 |
| 固定规则命中且分配成功 | 不生成替代推荐 | 展示规则命中和分配结果 | 不需要 |
| 固定规则冲突 | 停止自动写入，生成冲突说明和备选建议 | 展示冲突规则和人工确认入口 | 规则调整后允许 |
| 固定规则命中对象失效 | 标记规则失效风险，生成备选建议 | 提示维护规则或人工确认 | 数据修复后允许 |
| 相似事件无样本 | 可继续推荐，但标记样本不足 | 展示基于职责/技能/SLA 的建议 | 数据变化后允许 |
| 排班未配置 | 降级为处理组建议或 L2 | 标记处理人可用性未验证 | 配置后允许 |
| 无候选处理组 | 返回无候选 | 建议手工分配或维护团队规则 | 数据变化后允许 |
| CLI 超时或服务异常 | 按平台策略重试，超过限制后失败 | 显示原因、重试结果和日志入口 | 允许手动重试 |
| 模型输出不符合结构 | 受控重试；仍失败则结束 | 不展示伪候选 | 允许手动重试 |
| 执行前事件已被人工分配 | 停止写入，记录状态变化 | 显示已由其他用户处理 | 不自动覆盖 |
| SLA 已触发升级 | 不执行重派；按 ITSM workflow 状态展示 | 提示事件已进入升级流程 | 视事件状态允许重新分析 |
| 全局熔断触发 | 暂停自动写动作 | 保留只读建议和手工分配 | 运维解除后恢复 |

统一回退原则：任何 AI 异常不得阻断 ITSM 原有手工分配；不得把空数据当作零，不得用模型猜测补齐业务事实，不得在运行失败后执行分配。

## 12. 审计、计量与反馈闭环

### 12.1 审计范围

必须记录：

- 租户、触发来源、用户或平台身份、触发和完成时间。
- 事件编号、状态、分类、优先级、客户、服务和 SLA 摘要。
- Agent、模型、系统 Skill 和版本。
- 每项 CLI、输入范围、结果状态、耗时和来源摘要。
- 固定分单规则命中结果、规则版本、命中字段、输出对象和执行状态。
- 推荐处理组、处理人、备选项、分数、证据、未验证项和排除原因。
- L1/L2/L3、生效租户策略和治理审批记录。
- 用户确认、取消、手工分配、审批通过/驳回和执行前复核结果。
- 最终分配对象、后续是否改派、响应结果、解决结果和 SLA 达成情况。

### 12.2 计量

- 记录模型 input/output token、credits、运行耗时和正式/测试标识。
- CLI 查询不重复计为模型 token，但需要记录命令调用量和耗时。
- 同一事件重复运行保留所有调用记录，指标按最终有效建议版本去重。
- 熔断、未授权、权限拒绝和受限结果单独统计。

### 12.3 反馈闭环

- L1 自动分配记为采纳。
- L2 用户确认推荐对象记为采纳。
- 用户选择非推荐对象记为未采纳，并记录原因。
- 事件关闭前未发生人工改派可作为首次分配准确的正向信号。
- 后续响应超时、解决超时、人工改派、升级 workflow 触发和客户投诉作为负向评估信号。
- 反馈进入脱敏评测样本，需经产品与研发评审后才能更新系统 Skill、Prompt 或模型版本。

## 13. PM 验收标准

| AC | 前置条件 | 触发动作 | 预期结果 |
| :--- | :--- | :--- | :--- |
| ITSM-A8-AC-01 | L2、License 有效、事件待分配、数据完整 | 事件创建触发 | 返回推荐处理组/处理人、备选项、证据、未验证项和 trace ID，不执行分配 |
| ITSM-A8-AC-02 | L2 推荐完成且用户有分配权限 | 用户确认推荐 | Agent 使用当前用户身份调用 `ems itsm incident assign` 写入处理组或处理人，记录审计，事件进入 ITSM 既有处理流程 |
| ITSM-A8-AC-03 | L1 已审批生效、低风险、证据完整 | 事件进入待分配 | Agent 使用平台服务身份调用 `ems itsm incident assign` 自动写入分配对象，执行前复核事件仍可分配 |
| ITSM-A8-AC-04 | 租户未授权 Agent | 打开事件详情或创建事件 | 不展示 AI 分单区块，不产生调用 |
| ITSM-A8-AC-05 | 关键字段缺失 | 触发推荐 | 返回受限，不生成伪候选 |
| ITSM-A8-AC-06 | 排班未配置 | 触发推荐 | 可推荐处理组，但处理人可用性标记未验证；不得 L1 自动直达处理人 |
| ITSM-A8-AC-07 | 相似事件命中同一处理人但该人员不在班 | 触发推荐 | 不自动分配该人员，推荐其处理组或值班人员，并展示历史命中说明 |
| ITSM-A8-AC-08 | VIP P1 或高风险事件 | 触发推荐 | 默认降级 L2；租户配置审批时进入 L3，不执行 L1 |
| ITSM-A8-AC-09 | 用户无分配权限 | 查看推荐 | 推荐只读，确认操作禁用并提示权限不足 |
| ITSM-A8-AC-10 | 执行前事件已被其他用户分配 | 确认或自动执行 | Agent 停止写入，不覆盖现有分配，记录状态变化 |
| ITSM-A8-AC-11 | 事件已分配并进入处理中 | SLA 临期 | Agent 不重派；由 ITSM workflow 执行升级 |
| ITSM-A8-AC-12 | AI 平台 Dry-run | 输入有效事件编号 | 展示前置校验、CLI、候选、证据、版本和 trace ID，不改变事件 |
| ITSM-A8-AC-13 | 无可用处理组 | 触发推荐 | 返回无候选，提示维护团队规则或手工分配，不降低硬性过滤 |
| ITSM-A8-AC-14 | 全局熔断触发 | L1 场景触发 | 暂停自动写动作，保留只读建议和 ITSM 手工分配 |
| ITSM-A8-AC-15 | 固定分单规则命中且写入成功 | 事件创建触发 | Agent 不生成替代推荐、不覆盖分配结果；记录规则命中、规则版本和审计 |
| ITSM-A8-AC-16 | 多条固定分单规则命中且输出冲突 | 事件创建触发 | 不自动写入；展示冲突规则、命中字段和 AI 备选建议，进入 L2 |
| ITSM-A8-AC-17 | 固定规则只命中处理组且租户允许 AI 补处理人 | 事件创建触发 | Agent 仅在该处理组内推荐处理人；排班或负载未验证时降级 L2 |
| ITSM-A8-AC-18 | 固定规则命中对象已停用或无权限 | 事件创建触发 | 标记规则失效风险，不执行 L1；输出有效备选和规则维护建议 |

## 14. 待评审参数

| 参数 | 当前建议 | 待确认内容 |
| :--- | :--- | :--- |
| 相似事件窗口 | 90 天 | 是否按优先级、分类、客户单独配置 |
| 相似事件最少样本 | 3 条 | 样本不足时如何影响置信度 |
| 处理人直达条件 | 排班、权限、负载和技能完整 | 是否所有租户都允许直达处理人 |
| 固定规则优先级 | 固定规则命中并成功执行时 Agent 不覆盖 | 规则结果不完整、冲突、失效时的统一状态编码 |
| 规则优化建议 | 只输出建议，不自动改规则 | 是否纳入后续版本的规则治理能力 |
| 排班系统 | 预留 ITSM on-call/值班表 | 是否复用 FSM 排班模型或独立设计 |
| L1 低风险条件 | 非 VIP、P3/P4、分类明确、历史稳定 | 各租户可配置范围 |
| VIP 规则 | VIP 默认不进入 L1 | VIP 来源字段和服务等级映射 |
| SLA 风险阈值 | 由 ITSM SLA 返回 | Agent 不配置升级阈值，只读取状态 |
| 负载口径 | 未解决事件、P1/P2、临期数 | 团队与个人容量基线 |
| 权重配置 | 本文建议权重 | 是否进入系统 Skill 版本或租户策略 |

这些参数不得由模型自行推断。未定稿参数在开发方案中必须标记为配置项或待确认项。
