# 根因分析 Agent 设计

> 根因分析 Agent 直接复用早期 ITOM 已实现并在生产环境使用的 RCA 能力。新版 EMS 负责按 AI 平台规范托管该 Agent，并通过 EMS 官方 CLI 提供原有数据能力，不重新设计 RCA 业务算法。

## 1. 定位与复用结论

根因分析 Agent 面向 IT 技术人员，对 ITOM 告警进行数据收集、快速预判、模型分析、证据验证和处置建议生成。

本次复用包括：

- 防火墙端口 Down、CPU、内存、设备离线告警的 RCA 流程。
- 按告警类型维护的原因分类、原因代码和分析模板。
- 多数据源并行收集、数据预处理和关联分析。
- 配置变更、物理状态、资源状态等快速预判能力。
- Top 3 候选根因、独立置信度、证据和处置建议输出。
- 对模型引用证据进行原始数据反查验证的机制。
- 用户评价、实际根因和实际解决方案反馈。

新版 EMS 的变化仅限于平台承载方式：模型由 AI 平台配置，Agent 使用 EMS 官方 CLI 获取内部产品能力，调用进入统一审计与计量。原有 RCA 的业务判断和用户结果保持一致。

## 2. 用户与业务场景

| 用户 | 使用目的 | 主要行为 |
| :--- | :--- | :--- |
| IT 技术人员 | 快速定位告警根因并获得排查建议 | 在告警列表或详情查看分析结果、证据与建议，确认并评价结果 |
| IT 中层（MSP IT 经理） | 了解故障分析质量和处理效率 | 查看 RCA 使用情况、准确性反馈和故障处理结果 |
| AI 平台管理员 | 保障 RCA Agent 可用 | 配置授权模型、启用状态并执行运行测试 |

支持两种触发方式：

- 自动触发：符合 RCA 支持范围的告警产生后，系统自动启动分析。
- 手动触发：IT 技术人员在告警列表或告警详情主动发起或重新运行分析。

## 3. 范围边界

### 3.1 本期范围

- 对生产能力已支持的四类告警执行 RCA。
- 展示分析摘要、候选根因、置信度、有效证据和处置建议。
- 支持结果确认、评分和实际结果反馈。
- 使用 ITOM、CMDB、NPM、ITSM CLI 获取分析所需事实数据。

### 3.2 不在范围

- 不新增生产能力尚未支持的告警类型和原因体系。
- 不改变现有 RCA 的原因代码、快速预判逻辑和证据验证标准。
- 不自动执行修复、配置回滚、告警确认或工单状态变更。
- 不把模型生成内容直接写回为监控事实或资产事实。

## 4. 成功指标

| 指标 | 目标值 | 度量方式 |
| :--- | :--- | :--- |
| 支持场景覆盖率 | >= 90% | 可正常启动 RCA 的目标告警数 / 属于生产支持类型且满足基础数据条件的告警数 |
| 初步分析时效 | >= 95% 在 30 秒内完成 | 30 秒内返回初步 RCA 结果的分析次数 / 成功启动分析次数 |
| Top 3 根因命中率 | >= 85% | 专家或最终处理结果确认的实际根因出现在 Top 3 中的分析数 / 有效评价分析数 |
| RCA 辅助后的 MTTR | <= 15 分钟 | 使用 RCA 的目标告警从触发到完成根因确认的平均时长 |
| 用户满意度 | >= 80 分 | IT 技术人员对分析准确性、证据有效性和建议可用性的有效评价平均分，按百分制计算 |

指标只统计属于当前生产支持范围且具备有效评价依据的告警。无反馈、测试数据、依赖服务不可用和权限前置拦截不进入准确率分母，但应单独统计运行成功率和失败原因。

## 5. 触发前置条件

启动分析前必须满足：

1. 告警属于当前 RCA 支持的告警类型。
2. 告警具有可识别的监控对象、发生时间和必要指标信息。
3. 根因分析 Agent 已启用，License / SKU 有效。
4. Agent 已配置可用模型，模型处于运行中状态。
5. Agent Runtime 可发现执行本次分析所需的 EMS 内置只读 CLI；用户无需另行登记或提前授权内部产品命令。
6. 当前租户和用户具有对应告警及关联对象的数据权限。

任一必要条件不满足时，不生成模拟分析结果，应返回明确的不可分析原因。

## 6. 输入与输出

### 6.1 输入

| 输入 | 必填 | 说明 |
| :--- | :--- | :--- |
| 告警标识 | 是 | 用于查询当前告警和关联数据 |
| 告警类型 | 是 | 决定原因体系、预判规则、证据类型和提示词模板 |
| 告警发生时间 | 是 | 作为分析时间范围的基准 |
| 监控对象标识 | 是 | 关联设备、端口、CI、拓扑和指标数据 |
| 用户与租户上下文 | 是 | 用于权限、数据隔离和审计 |
| 分析配置 | 系统 | 数据源开关、分析深度、可信度阈值、分析时间范围和最大响应时间 |

### 6.2 输出

| 输出 | 说明 |
| :--- | :--- |
| 分析状态 | 分析中、分析完成、分析受限或分析失败 |
| 分析摘要 | 说明主要故障判断及关键时间关系 |
| 候选根因 | 最多 3 个预置原因代码及原因描述 |
| 置信度 | 每个候选原因的独立可信程度，不要求合计为 100% |
| 有效证据 | 已与 CLI 原始记录验证匹配的证据 |
| 处置建议 | 与候选原因和有效证据对应的排查步骤 |
| 数据完整度 | 本次应取数据与成功取得数据的完整程度 |
| 分析元数据 | Agent 版本、模型、执行耗时和完成时间 |

## 7. 业务流程

1. 接收告警上下文，根据告警类型加载生产版本的原因体系和分析策略。
2. 以告警发生时间为基准，按照生产配置确定分析时间范围。
3. 并行调用 CLI，获取配置变更、日志、状态历史、性能指标、拓扑及连通性数据。
4. 将不同来源结果转换为统一证据结构，完成去重、时间对齐和关联分析。
5. 执行生产版本快速预判，生成疑似原因类别、初始可信程度和重点分析区域。
6. 将告警信息、快速预判和真实证据提交给已配置模型。
7. 要求模型仅从该告警类型的预置原因体系中输出最多 3 个候选原因。
8. 按证据类型调用验证规则，在原始 CLI 结果中反查模型引用内容。
9. 删除未验证证据；根据有效证据形成最终候选原因、置信度和处置建议。
10. 将结果展示在告警列表和详情，并记录用户确认与评价。

## 8. 确定性规则与模型职责

### 8.1 确定性规则

以下能力不交给模型自由决定：

- 告警类型识别和对应原因体系选择。
- 数据时间范围、权限范围和所需业务能力。
- 数据预处理、快速预判和证据类型分派。
- 证据与原始记录的匹配及是否有效。
- 输出结构校验、最大候选数量和必填字段。
- 数据不足、调用失败和超时后的降级行为。

### 8.2 模型职责

模型负责：

- 对多来源证据进行语义归纳和关联解释。
- 从预置原因体系中选择并排序候选根因。
- 生成简明分析摘要和与证据一致的处置建议。

模型不得：

- 生成原因体系以外的原因代码。
- 引用本次 CLI 调用未返回的日志、指标或变更记录。
- 声称已经执行处置动作。
- 将无数据解释为“状态正常”。

## 9. CLI 要求

### 9.1 命令清单

| CLI 命令 | 能力 | 必要输入 | 关键输出 | 用途 |
| :--- | :--- | :--- | :--- | :--- |
| `ems itom alert get/history` | 查询告警详情与历史 | 告警标识、时间范围 | 告警状态、等级、描述、历史和关联告警 | 建立告警上下文与时间线 |
| `ems itom change list` | 查询配置变更与操作记录 | 监控对象、时间范围 | 变更时间、内容、操作人和结果 | 判断近期变更关联 |
| `ems itom log query` | 查询设备与系统日志 | 监控对象、时间范围、日志类型 | 日志时间、级别、内容和来源 | 提取异常事件证据 |
| `ems itom metric query` | 查询指标时序 | 监控对象、指标、时间范围 | 时间点、指标值、单位和采集状态 | 判断资源和状态异常 |
| `ems itom port history` | 查询端口状态历史 | 设备、端口、时间范围 | 状态变化时间、前后状态 | 判断端口 Down 与恢复过程 |
| `ems cmdb ci relations` | 查询 CI 与拓扑关系 | 监控对象、关系方向和深度 | CI、关系、邻居及上下游对象 | 判断拓扑影响和故障传播 |
| `ems npm path history` | 查询连通性与路径结果 | 监控对象、时间范围 | Ping、端口连通、路径和逐跳状态 | 判断网络可达性和故障位置 |
| `ems itsm incident similar` | 查询历史相似工单与处理结果 | 告警、监控对象、故障特征和时间范围 | 相似工单、处理备注、根因和回传结果 | 为历史案例匹配提供事实上下文 |
| `ems itom device health` | 查询设备硬件状态 | 监控对象、时间范围 | 电源、温度、风扇及硬件状态 | 判断设备硬件异常 |
| `ems itom maintenance list` | 查询维护记录 | 监控对象、时间范围 | 维护窗口、任务、状态和操作人 | 识别计划内维护影响 |

### 9.2 CLI 通用约束

- 本 Agent 只使用查询类命令，不配置写命令范围。
- 所有工具必须支持租户、用户和业务对象权限校验。
- 时间类结果必须包含统一时间信息，支持与告警发生时间对齐。
- 每条原始记录必须包含稳定来源标识，以支持证据反查。
- 工具必须区分“无数据”“无权限”“超时”和“服务异常”。
- CLI 调用必须记录 Agent、Skill、命令、业务对象、调用人、租户、结果和耗时。
- 单个工具失败不得伪装为空数据；Agent 根据数据重要程度决定受限分析或失败。

### 9.3 统一证据结构

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| evidence_id | 是 | 本次分析中的证据标识 |
| source_record_id | 是 | CLI 原始记录稳定标识 |
| evidence_type | 是 | 配置变更、日志、指标、状态、拓扑、连通性、硬件或维护记录 |
| occurred_at | 是 | 证据发生时间 |
| content | 是 | 用于分析和展示的事实内容 |
| source_command | 是 | 证据来源 CLI 命令 |
| validation_status | 是 | 待验证、有效或无效 |
| reliability | 是 | 生产验证规则计算的可靠性结果 |

## 10. 状态、异常与降级

| 场景 | 处理方式 |
| :--- | :--- |
| 非支持告警类型 | 不启动模型分析，提示该告警暂不支持 RCA |
| 非关键数据源为空 | 使用已有数据继续分析，展示缺失项并降低数据完整度 |
| 关键数据源失败 | 标记分析受限或失败，不输出伪完整结论 |
| 模型调用超时 | 保留快速预判结果，提示模型分析未完成 |
| 模型输出不符合结构 | 按平台策略执行受控重试；仍失败则分析失败 |
| 候选原因无有效证据 | 不输出确定性根因，提示需要人工分析 |
| 分析期间告警恢复 | 继续完成分析并标记当前告警状态，不把恢复等同于根因消失 |
| 重复运行 | 保留各次运行记录，页面展示最新完成结果并可追溯历史结果 |

## 11. 权限、审计、计量与档位

- **自主权档位**：L3 业务审批。Agent 直接展示 RCA 结果和处置建议，不直接自动执行业务动作；用户选择建议中的业务动作后，必须把冻结快照提交目标产品业务审批流。审批人和节点由 ITOM/CMDB 对应流程决定，审批通过且执行前复核通过后，才可执行审批快照中的动作。AI 治理中心只记录审计，不承担运行任务审批。
- **数据权限**：调用者只能获得其有权查看的告警、设备、指标、日志和拓扑数据。
- **CLI 调用边界**：Agent 按任务动态选择完成 RCA 所需的只读命令；实际数据权限自动继承当前用户或平台服务身份。
- **审计范围**：记录触发来源、告警、用户、Agent 版本、模型、CLI 调用摘要、结果、耗时、用量和反馈。
- **计量范围**：记录模型 input/output token、credits、运行耗时及测试/正式运行标识；CLI 查询不重复计为模型 token。

## 12. 验收标准

| AC | 前置条件 | 触发动作 | 预期结果 |
| :--- | :--- | :--- | :--- |
| RCA-AC-01 | 支持类型告警且依赖可用 | 自动或手动触发 RCA | 系统完成数据收集、预判、模型分析和证据验证，并返回结构化结果 |
| RCA-AC-02 | 模型返回候选根因 | Agent 验证候选证据 | 最终证据均能关联 CLI 原始记录，未验证证据不展示 |
| RCA-AC-03 | 部分非关键数据缺失 | 执行 RCA | 系统展示数据完整度和缺失项，并基于已有证据返回受限分析 |
| RCA-AC-04 | 关键 CLI 调用失败 | 执行 RCA | 系统明确标记分析受限或失败，不生成伪造证据 |
| RCA-AC-05 | 模型引用不存在的数据 | 执行证据验证 | 对应证据被判定无效，不得支撑最终高可信结论 |
| RCA-AC-06 | 用户查看分析详情 | 打开 RCA 结果 | 可查看摘要、候选根因、独立置信度、有效证据、处置建议和元数据 |
| RCA-AC-07 | 用户确认或评价结果 | 提交反馈 | 系统记录准确性、有用性、实际根因及实际解决方案，并关联本次分析 |
| RCA-AC-08 | 用户无关联对象权限 | 触发 RCA 或查看结果 | CLI 不返回越权数据，结果中不泄露无权访问的信息 |
| RCA-AC-09 | Agent 使用 L3 档位 | 查看或接受建议 | 建议展示不改变配置、告警、工单或设备状态；建议动作必须完成人工审批后才可执行 |
