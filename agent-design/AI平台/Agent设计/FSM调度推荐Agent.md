## 2. Agent 定位

### 2.1 一句话定义

FSM 调度推荐 Agent 面向 FSM 调度员，在现场工单待派单或待认领超时时，基于历史服务连续性、满意度、技能、服务范围、负载、收费和 SLA 时效生成可解释的 Top 3 推荐，并按租户生效档位完成自动派单、人工确认或高风险审批，持续跟踪到任一候选工程师完成认领。

### 2.2 背景与业务问题

- 当前问题：调度员需要跨工程师档案、排班、工单和收费信息寻找候选人。
- 现有方式：调度员在 FSM 中人工筛选工程师，再逐一判断技能、区域、负载和费用。
- 主要痛点：信息分散、判断口径不一致、派单耗时长，且推荐依据难以追溯。
- 改善目标：统一候选过滤与排序规则，在工单上下文中直接提供可核对的推荐和证据。

### 2.3 业务目标

1. 缩短待派单工单的候选筛选和派单时间。
2. 提高工程师技能、服务范围和负载的匹配程度。
3. 让每次推荐、确认、自动执行和后续履约结果可追溯。
4. 在不同租户 FSM 配置存在差异时，通过 CLI 能力检查阻止伪完整推荐。
5. 对无人认领和 SLA 临期工单及时重派或升级人工，目标是工程师完成认领，而不是只生成推荐。

### 2.4 成功指标

| 指标 | 目标值 | 度量方式 | 统计范围与排除项 |
| :--- | :--- | :--- | :--- |
| 场景覆盖率 | >= 90% | 成功生成可用推荐的目标工单数 / 满足触发条件的授权工单数 | 未授权、无权限和产品模块缺失单独统计，不计为算法失败 |
| 推荐时效 | >= 95% 在平台超时阈值内完成 | 阈值内完成推荐的次数 / 成功启动次数 | 测试运行单独统计 |
| 推荐采纳率 | >= 80% | L2 确认推荐工单数 + L1 自动执行工单数 / 成功生成可用推荐的去重工单数 | CLI 失败、关键数据不足不进入分母；推荐后取消不排除 |
| Top 1 命中率 | 待基线评审 | 最终认领人为 Top 1 的工单数 / 最终认领人为推荐集合成员的工单数 | 仅统计存在有效认领结果的工单 |
| Top 3 命中率 | >= 90% | 最终认领人在推荐集合内的工单数 / 存在有效认领结果的 AI 派单工单数 | 手工选择非推荐人员不计为命中 |
| 派单成功率 | >= 90% | 在允许轮次和 SLA 阈值内完成工程师认领的 AI 派单工单数 / 已进入 AI 派单流程的工单数 | 取消、License 中止和业务数据失效单独统计 |
| 首轮认领率 | 待基线评审 | 首轮候选通知后完成认领的工单数 / 已发送首轮候选通知的工单数 | 用于评估候选质量和通知时效 |
| 准时到场率 | >= 90% | 实际到场不晚于有效计划到场时间的工单数 / 有有效计划和实际到场时间的 AI 派单工单数 | 到场前取消、缺失时间戳、测试数据排除；客户改期使用最新确认时间 |

### 2.5 Agent 不负责的事项

- 不负责创建、关闭、验收或结算 FSM 工单。
- 不替代 FSM 调度员权限和 FSM 标准状态机。
- 不自行创建工程师、技能、服务范围、收费或位置事实。
- 不把缺失数据推断为零或正常。
- 不替代调度员处理超过自动重派上限、无可用候选或高风险审批被拒绝的工单。

## 3. 用户与使用角色

| 角色 | 使用目的 | 允许的主要操作 |
| :--- | :--- | :--- |
| FSM 调度员 | 查看推荐并完成派单 | 查看证据、确认全部推荐候选或指定一名推荐候选、使用手工派单 |
| FSM 只读用户 | 了解推荐和派单结果 | 查看有权访问工单的推荐结果，不可确认或派单 |
| AI 平台管理员 | 维护 Agent 平台配置 | 配置默认模型、全局启停，维护租户业务提示词，申请档位变更，运行测试 |
| AI 治理审批人 | 审批租户档位变更 | 通过或驳回 L1/L2/L3 档位申请；不得审批本人申请 |
| 测试人员 | 验证业务和异常场景 | 执行 Dry-run，核对结果、证据、边界和回退 |
| 平台运维 | 保障运行稳定 | 查看调用日志、失败原因、性能和依赖状态 |

业务派单权限沿用 FSM 标准产品的调度员权限，不由 Agent 建立第二套业务权限。AI 平台配置、Skill 管理、治理审批和审计查看需要在 EMS 用户角色中独立配置权限。

## 4. 业务范围与边界

### 4.1 支持范围

| 范围项 | 支持内容 | 备注 |
| :--- | :--- | :--- |
| 业务对象 | FSM 现场工单 | 必须能唯一识别工单和租户 |
| 工单状态 | 待派单、待认领 | 待派单生成首轮推荐；待认领由 FSM 响应 SLA 阈值事件再次触发 Agent |
| 候选人 | 一个或多个现场工程师 | 同时通知，最先认领者成为处理工程师 |
| 租户范围 | 已获得 Agent License 且 FSM 能力检查通过的租户 | MSP 汇总视角不能执行具体工单推荐 |
| 触发来源 | FSM 工单状态事件、FSM 响应 SLA 阈值事件、调度员手动重新生成、AI 平台 Dry-run | Agent 不维护独立认领计时器；L1 不依赖用户打开页面 |
| 数据来源 | FSM 工单与工程师数据；按工单关联链补充 ITSM 事件、ITOM 告警、ITAM 资产和 CMDB CI 上下文 | FSM 是派工状态与执行约束的主数据源；上游系统只补充故障、资产和业务影响证据 |

### 4.2 不支持范围

| 不支持项 | 处理方式 |
| :--- | :--- |
| 租户未授权 Agent | 业务页面不展示智能派工区块，不产生 AI 派工待办或调用 |
| 工单不是待派单 | 不触发推荐，保留当前业务状态 |
| 已指定候选工程师 | 不重复生成推荐 |
| 必需系统 Skill 缺失或解析失败 | 停止推荐，记录失败，保留手工派单 |
| 关键数据缺失 | 返回受限，不输出候选人 |
| 无符合条件的工程师 | 返回成功但无候选，提示使用手工派单或补充资源 |
| 超过自动重派上限 | 停止 Agent 自动调用，升级调度员人工处理，保留手工派单和转派入口 |
| SLA 已越界或剩余时间不足以完成安全重派 | 停止自动重派，升级调度员和主管；不得降低技能、资质或风险门槛凑候选 |

### 4.3 Agent、Skill 与 CLI 分工

| 层级 | 负责内容 | 不负责内容 |
| :--- | :--- | :--- |
| Agent 产品契约 | 触发条件、硬性过滤、权限、状态、输出、L1/L2 行为和审计 | 不定义租户业务事实 |
| Skill | 评分、排序和事件处理工作流；结合 FSM 次数事实决定重派或升级 | 不授予权限，不定义 SLA 阈值，不越过 FSM 最大重派次数 |
| EMS CLI | 返回原始事实、来源、统计时点、数据完整度和错误状态 | 不计算最终匹配度，不决定派单 |
| 模型 | 依据已验证事实组织候选解释和推荐摘要 | 不编造事实，不绕过硬性过滤和治理策略 |

## 5. 业务场景与案例

### 5.1 业务旅程一：告警事件转现场处置

该旅程适用于 ITOM 告警经过 ITSM 事件研判后，需要现场工程师处理的情况。跨产品对象必须使用同一租户和显式关联标识串联。

| 阶段 | 主产品 | 状态与动作 | 输入或回传 |
| :--- | :--- | :--- | :--- |
| 告警产生 | ITOM | 产生有效告警并关联监控对象/CI | `alert_id`、等级、症状、指标、发生时间、`ci_id` |
| 事件建立 | ITSM | 告警创建或关联事件，服务台补充影响、紧急度、优先级、客户和服务 | `incident_id` 保存 `alert_id`、`ci_id` 和可选 `asset_id` |
| 现场工单建立 | ITSM → FSM | 事件确认需要现场处置，创建 FSM 工单 | FSM 保存 `incident_id`、`alert_id`、`asset_id`、`ci_id`，并生成现场工作要求 |
| 智能派工 | FSM + AI | Agent 读取 FSM 主工单并按关联读取上游上下文，推荐满足技能、资质、级别、范围和时效要求的工程师 | 高等级告警、关键 CI、特定资产型号或厂商授权进入硬性过滤或风险控制 |
| 工程师认领 | FSM | 通知候选工程师，最先认领者成为处理工程师 | 工单由待认领进入已派单；Agent 目标完成 |
| 现场处理 | FSM | 签到、诊断、维修、使用备件、记录结果并提交验收 | 现场处理结果、照片、工时、费用、资产/CI 状态和告警验证结果 |
| 验收与工单完成 | FSM | 客户或有权验收人确认；验收通过后工单完成 | FSM 向 ITSM 回传完成结论、处理记录和完成时间 |
| 事件解决 | ITSM | 根据现场结果进入已解决，完成业务验证后关闭事件 | ITSM 保留 FSM 工单和 ITOM 告警的完整关联 |
| 告警关闭 | ITOM | 监控信号已恢复且关联事件关闭后，按 ITOM 规则恢复/关闭告警 | 告警仍活跃时不得因为 FSM 完成而强制关闭；继续告警或重新进入事件处理 |

闭环原则：FSM 工单完成不等于 ITSM 事件自动关闭，也不等于 ITOM 告警已经恢复。各产品根据自己的状态机完成校验，Agent 只提供派工与认领能力，不直接解决事件或关闭告警。

### 5.2 业务旅程二：客户报障直接现场服务

该旅程适用于客户通过电话、门户或服务台报障，由调度员直接建立 FSM 工单，不要求先创建 ITSM 事件。

| 阶段 | 主产品 | 状态与动作 | 必要信息 |
| :--- | :--- | :--- | :--- |
| 客户报障 | FSM / 服务入口 | 调度员确认客户诉求和现场服务必要性 | 客户、服务网点、现场联系人、联系电话、故障描述 |
| 调度员开单 | FSM | 选择客户和网点，填写工单类型、描述、期望时间、TAC 工程师及是否需要技术面试 | 客户与网点必须从主数据选择；可关联资产和合同，不要求 ITSM 事件 |
| 智能派工 | FSM + AI | Agent 基于站点、工单类型、资产、合同/SLA、历史服务连续性、满意度、技能、负载和收费推荐候选 | 资产或合同存在明确引用时按需查询 ITAM/CMDB；无引用时仅使用 FSM 事实 |
| 工程师认领 | FSM | 通知一个或多个候选人，最先认领者成为处理工程师 | 工单由待认领进入已派单；Agent 目标完成 |
| 现场处理 | FSM | 工程师签到、执行作业、记录工时/备件/费用并提交验收 | 处理记录、附件、客户签字或其他交付证据 |
| 验收 | FSM | 客户或有权验收人确认结果；不通过则退回继续处理 | 验收意见、时间和操作人完整留痕 |
| 工单完成 | FSM | 验收通过后完成工单并进入费用、调查问卷等后续流程 | 完成状态、实际费用、SLA 结果和满意度用于后续推荐反馈 |

该旅程没有 ITSM 事件和 ITOM 告警的反向关闭动作。后续确需问题、事件或变更管理时，由对应产品流程另行建立关联对象。

### 5.3 Agent 执行子场景

以下子场景共用 FSM 调度推荐 Agent。L1/L2/L3 是租户运行档位，不拆成不同业务场景。

| 子场景 | 触发入口 | 触发方式 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 首次智能派工 | FSM 待派单事件 / 业务页面 | 自动分析，按租户档位执行 | 生成可解释 Top 3；L1 自动通知，L2 人工确认，L3 进入 FSM 业务审批 |
| 无人认领处理 | FSM 响应 SLA 阈值事件 | Skill 决策，按租户档位执行 | 根据 FSM 次数事实重派或升级人工 |
| 手动重新生成 | FSM 工单详情 | 手动 | 生成新运行记录并展示最新有效结果 |
| NEO Copilot 派工 | NEO Copilot | 对话发起，人工确认 | 查询待派工单并复用同一推荐和确认规则 |
| NEO Copilot 创建现场工单 | NEO Copilot | 对话发起，分步确认 | 先创建 FSM 工单，再独立生成推荐和确认派工 |
| Agent 运行测试 | AI 平台 Agent 详情 | 手动 Dry-run | 展示前置校验、关联来源、CLI、候选、证据和 trace ID，不改变工单 |

### 5.4 正常案例：L2 手工确认

- 工单：FSM-2026-139，UPS 电池更换，状态为待派单。
- 租户：达美乐（Domino），License 有效。
- 数据：工单、工程师画像和负载 CLI 成功，系统 Skill 可读。
- 结果：输出 P.Y. Lau、S.Y. Lee、T.K. Yip 三名候选及匹配度、费用、ETA 和证据。
- 操作：调度员可确认全部推荐候选或指定一名候选。
- 结果状态：同时通知所选候选人，工单进入待认领；任一候选人认领后进入已派单。

### 5.5 部分完成案例

- 工单关键数据完整，候选工程师技能、范围、接单状态和负载可验证。
- 某候选人的 ETA 缺失或历史费用样本不足。
- Agent 可以保留该候选，但必须显示“部分完成”和具体未验证字段。
- L2 允许调度员人工确认；L1 对超过预算或关键执行字段未验证的结果不得自动执行。

### 5.6 受限案例

- 工程师服务范围或关键技能字段缺失。
- Agent 不应生成候选或匹配度。
- 页面显示各 CLI 的成功、失败或数据不完整状态、缺失项、处理建议和日志入口。
- 用户仍可使用 FSM 原有手工派单。

### 5.7 治理案例：租户档位变更

- AI 平台管理员为具体租户申请 L1/L2/L3 档位变更。
- 申请进入 AI 治理中心，审批前继续按当前生效档位运行。
- 申请人与审批人必须为不同用户。
- 审批通过后只更新申请租户的生效档位；驳回不改变运行行为。

## 6. 触发、流程与状态机

### 6.1 触发条件

必须同时满足：

1. 工单状态为待派单。
2. 工单尚未完成候选工程师派单。
3. 租户 Agent License 有效。
4. Agent 全局启用且租户档位有效。
5. 系统预置必需 Skill 可读取并解析。
6. FSM 工单、工程师和负载 CLI 能力门禁通过。
7. 当前用户或平台服务身份具有租户和业务对象权限。

L1 由 FSM 工单状态事件触发，不依赖列表或详情页被打开。业务页面只负责读取结果、展示证据和提供允许的后续操作。

### 6.2 标准流程

```text
FSM 工单进入待派单
  → 校验租户 License、Agent 启用状态与生效档位
  → 校验租户、用户、工单权限和工单状态
  → 校验必需系统 Skill
  → 调用工单、工程师、负载 CLI
  → 执行硬性过滤
  → Skill 计算子项分数、综合匹配度和排序
  → Agent 形成 Top 3、证据和未验证项
  → L2：等待调度员确认
  → L1：自动选择通过硬性过滤的 Top 3（不足 3 人时选择全部）
  → 同时通知候选工程师
  → 工单进入待认领
  → FSM 按既有响应 SLA 规则计时并监听工单状态
  → FSM 发布响应 SLA 阈值事件：Agent 按租户 Prompt 选择 Skill，决定重派或升级人工
  → 达到 FSM 最大智能重派次数或无安全候选：停止 Agent，升级调度员人工处理
  → 任一候选人认领
  → 工单进入已派单
  → 回写履约、到场、转派和最终处理结果
```

### 6.3 工单状态机

```text
待派单
  → 选择一个或多个候选工程师
待认领
  → FSM 响应 SLA 阈值事件：按 Skill 重新推荐或升级人工
  → 任一候选工程师先认领
已派单
```

- 手工派单和 AI 派单使用同一状态机。
- 待派单阶段不展示转派。
- 候选工程师同时收到通知，不存在拒绝操作和认领顺序。
- 每轮派单必须记录候选集合、通知时间、FSM 响应 SLA 事件时间和结果。
- 重派时默认排除本工单上一轮未认领候选；调度员可在 L2 中手工重新加入并填写原因。
- 达到自动重派上限后不得继续消耗模型 Token，工单保持可人工处理并生成升级待办。

### 6.4 跨产品完成回传

智能派工 Agent 在工程师认领后标记目标完成，不继续编排现场作业、验收、事件解决或告警关闭。跨产品闭环由产品状态事件驱动：

1. FSM 验收通过并完成工单后，发布包含 `work_order_id`、关联对象、完成结论、完成时间和证据引用的幂等事件。
2. 存在 `incident_id` 时，ITSM 接收回传并将现场结果追加到事件；由 ITSM 规则或有权用户把事件置为已解决，业务验证后关闭。
3. 存在 `alert_id` 时，ITOM 读取当前监控状态。信号已经恢复且关联事件关闭时，按 ITOM 规则恢复/关闭告警；信号仍活跃时保持告警并继续处置，不允许 FSM 直接关闭告警。
4. 客户报障直接建单没有 `incident_id`、`alert_id` 时，FSM 验收通过并完成即结束该业务旅程，不创建伪事件或伪告警。
5. 所有回传使用原始关联标识和幂等键；重复事件不得重复改变状态或创建对象。

### 7.2 关联上下文与字段优先级

FSM 工单是派工事务的主对象，必须保存标准化来源引用：`source_system`、`source_object_type`、`source_object_id`，并可保存 `incident_id`、`alert_id`、`asset_id`、`ci_id`。ITOM 告警转 ITSM 事件、再转 FSM 工单时，FSM 工单应同时保留事件和告警引用，不依赖 Agent 反向猜测。

字段冲突按以下规则处理：

1. 工单状态、服务网点、候选人、派工轮次、FSM 响应 SLA 和执行结果以 FSM 为准。
2. 事件影响、紧急度、优先级、客户和 ITSM SLA 以 ITSM 为准，仅作为派工风险与人员级别输入，不覆盖 FSM SLA。
3. 告警等级、告警对象、原始指标和发生时间以 ITOM 为准。
4. 资产品牌型号、序列号、维保合同和厂商要求以 ITAM 为准；CI 关键度与依赖关系以 CMDB 为准。
5. FSM 手工录入内容与上游事实冲突时不自动覆盖，输出冲突项并阻止 L1；L2/L3 由用户核对后继续。

## 8. 系统 Skill 与评分规则

### 8.1 必需 Skill

| 项目 | 要求 |
| :--- | :--- |
| 文件 | `dispatch-recommend.md` |
| 来源 | 系统预置 |
| 删除 | 不允许 |
| 用户编辑 | 不允许 |
| 更新 | 随产品版本发布，保留版本和回滚能力 |
| 缺失或解析失败 | 停止推荐，记录失败，回退手工派单 |

用户导入 Skill 可以补充其他工作流，但不能替换必需 Skill、修改硬性过滤、权限、状态机或执行档位。

### 8.2 硬性过滤

候选工程师必须满足：

1. 档案已激活且接单状态为可接单。
2. 服务范围覆盖目标站点。
3. 满足全部关键技能和有效认证。
4. 有效负载低于最大容量。

### 8.3 综合匹配度

```text
综合匹配度
= 历史服务连续性 × 30%
+ 调查问卷满意度 × 20%
+ 技能匹配 × 15%
+ 可用负载 × 15%
+ 收费匹配 × 10%
+ SLA 到场时效 × 10%
- 负向因子扣分
```

- 历史服务连续性：同一站点、同一工单类型且由同一工程师完成的有效历史记录得分最高；结合最近服务时间、履约完成和样本数衰减，避免单次偶然记录形成满分。
- 调查问卷满意度：使用该工程师在同站点、同类型工单的有效问卷均分；有效样本不足时使用 60 分中性值并标记样本不足，不得视为 100 分。
- 技能匹配：`已满足技能数 / 要求技能数 × 100`；关键技能缺失直接排除。
- 有效负载：`作业中 + 其他已接单未验收 + 已申请验收 × 0.5`。
- 可用负载：`100 × (1 - min(有效负载 / 最大容量, 1))`。
- 收费匹配：预计费用不超过预算时得 100；超过预算不得由 L1 自动执行，并标记人工确认。
- 到场时效：区域经验 ETA 不超过 SLA 可用到场时间时得 100；超出时按比例递减。
- 并列排序：历史服务连续性、满意度、关键技能匹配程度、可用负载、ETA、预计费用依次比较。
- 最终分数取整显示，同时保留计算前精度用于排序。

负向因子在加权得分后扣减：

| 负向因子 | 默认处理 |
| :--- | :--- |
| 本工单上一轮已通知但未认领 | 下一轮默认排除该工程师；L2 人工重新加入时必须填写原因 |
| 近 30 天收到通知但未认领率较高 | 按分段扣 5～15 分；样本少于 3 次只提示不扣分 |
| 同站点同类型工单发生转派或未按时到场 | 每次扣 10 分，最多扣 20 分 |
| 有效问卷低于满意阈值或存在未关闭投诉 | 扣 10～30 分；严重投诉未关闭时直接排除 |
| 当前推荐预计无法满足 SLA 响应时间 | L1 不得执行；L2/L3 显示风险并升级调度员 |
| 认证即将过期、位置过旧或状态新鲜度不足 | 标记未验证；关键资质无法确认时直接排除 |

权重与负向扣分由系统 Skill 随产品版本交付，用户不直接编辑。产品可在版本评审后调整并保留版本、评测结果和回滚能力。

L1 仅在全部硬性过滤证据完整、工单风险满足 L1 白名单、至少存在一名候选且不存在需人工确认项时自动执行。高等级告警关联工单、关键业务站点、资质不足风险、预算超限、SLA 高风险或关键执行字段未验证时不得按 L1 自动派工，应按租户场景策略进入 L2 或 L3；本次降级不改变租户配置的生效档位。

### 8.4 预计费用

```text
有有效历史：
预计费用 =（工程师标准收费估算 + 当前站点相似工单历史平均费用）/ 2

无有效历史：
预计费用 = 工程师标准收费估算
```

工程师标准收费估算必须说明费率、计费单位和预计工时。结果展示币种、计算来源和完整度。原型案例：`HKD 900/h × 2h = HKD 1,800`，与站点历史均值 `HKD 5,400` 取平均，预计费用为 `HKD 3,600`。

### 8.5 预计完成时间

预计完成时间基于以下有效来源取平均：

1. 工单定义的期望完成时间。
2. 当前服务网点历史相似工单的 SLA 解决时间。
3. 不同站点同类型工单的 SLA 解决时间。

来源缺失时使用剩余有效来源，并标记数据完整度；所有来源均缺失时显示未验证，不得生成伪造时间。

| 推荐摘要 | 是 | 首选工程师、预计费用和预计完成时间 |

| 候选证据 | 是 | 技能、范围、接单状态、负载、收费、ETA 和工单要求 |
| 未验证项 | 按场景 | 明确字段和对执行的影响 |
| CLI 结果摘要 | 是 | 每项 CLI 的成功、失败或数据不完整状态 |
| 运行标识 | 是 | 调用编号或 trace ID |
| 运行元数据 | 是 | 生成时间、Agent、Skill、模型、版本和耗时 |
| 建议动作 | 是 | L2 确认推荐、手工派单或处理缺失数据 |

### 9.2 页面状态

| 状态 | 页面要求 |
| :--- | :--- |
| 分析中 | 显示正在读取工单、工程师和负载；不阻塞手工派单 |
| 成功 | 展示 Top 3、分数、证据、费用、ETA、调用编号和审计入口 |
| 部分完成 | 展示可用候选，标明未验证字段及对 L1/L2 的影响 |
| 受限 | 不展示候选，展示具体缺失项、CLI 状态、解决建议和日志入口 |
| 失败 | 显示超时或服务错误、已执行重试和手工派单入口 |
| 未授权 | 不展示 AI 推荐区块、快捷入口和 AI 派工待办 |
| 已派单 | 展示执行结果和候选名单，不再展示确认操作 |
| 待认领 | 展示当前轮次、候选集合、认领截止、SLA 剩余时间和下一步策略 |
| 重派中 | 展示上一轮未认领结果、排除候选和新一轮运行状态 |
| 升级人工 | 展示停止原因、全部历史轮次和手工派单/转派入口，不再自动调用模型 |

### 9.3 确认弹窗

- 标题：`确认 AI 派工推荐 · 工单编号`。
- 选项一：派给全部推荐工程师。
- 选项二：仅派给指定推荐工程师。
- 固定说明：系统同时通知所选候选工程师，最先认领者成为处理工程师。
- 确认结果：完成派单并进入待认领，发送通知并记录审计。
- 我的待办和 FSM 工单详情必须使用同一弹窗组件、文案和状态迁移。

### 9.5 NEO Agent 对话入口

- NEO Agent 只负责识别意图、收集上下文、编排步骤和展示结果，不重新实现推荐算法。
- 用户只输入“创建工单”时，必须先选择“事件工单”或“现场工单”，不得默认创建某一产品的工单。
- 创建现场工单和智能派工是两个独立事务：先确认工单草稿并创建，成功后再生成推荐和确认派工。
- 对话创建现场工单时，客户和服务网点必须通过主数据下拉选择且保持联动；工单类型、工单描述、现场联系人、联系电话、TAC 工程师和是否需要 TAC 技术面试为必填。
- NEO Agent、FSM 工单详情和我的待办必须读取同一 Agent 运行记录，并使用相同候选、文案、状态机和审计编号。
- 对话确认派工后，“查看工单详情”必须打开本次创建或选择的工单，并展示已选择候选工程师及“待认领”状态，不得降级到其他样例工单。
- MSP 全部租户视角只允许查询，不允许创建工单或确认派工；写操作前必须选择具体租户。
- 租户未获得 License 时不展示推荐结果，只提示使用 FSM 手工派单；用户无 FSM 派单权限时结果只读。

## 10. 权限与治理

### 10.1 自主权档位

| 档位 | Agent 行为 | 用户行为 |
| :--- | :--- | :--- |
| L1 自动执行 | 仅对租户批准的低风险范围自动选择候选、通知并进入待认领；无人认领时在上限内自动重派 | 查看结果；后续按 FSM 权限处理 |
| L2 手工确认 | 生成推荐或重派方案但不执行派单 | 调度员确认全部候选、指定候选或转为手工派单 |
| L3 业务审批 | 对高风险工单形成候选、证据和拟派工快照，每次任务提交 FSM 业务审批流 | 按 FSM 审批配置处理；通过且执行前复核成功后系统通知候选并进入待认领 |

FSM Agent 只调用统一业务审批提交契约，不维护审批人或节点。提交参数包括租户、FSM 场景、工单、候选工程师、推荐证据、拟执行派工动作、申请人和回调地址；FSM/Corteza 审批流决定审批人和节点。AI 治理中心只接收审批结果审计事件。

默认档位为 L2，按 `租户 × Agent 场景` 配置和生效。租户可以为普通派工配置 L1/L2，并为高等级告警关联工单、关键站点或其他高风险条件配置强制 L3 规则。档位或风险规则变更进入 AI 治理审批，审批通过前继续使用当前版本。

档位不能降低业务风险约束。即使租户默认采用 L1，命中高风险条件时也必须进入 L2 或 L3；不得把高等级告警事件对应工单自动派给资质、经验或技能不满足要求的初级工程师。

### 10.2 权限配置

| 权限 | 要求 |
| :--- | :--- |
| 查看推荐 | 与 FSM 工单查看权限一致 |
| 确认和手工派单 | 使用 FSM 调度员权限；无权限时只读并提示“没有派单权限” |
| Agent 全局配置 | AI 平台管理权限 |
| 租户提示词和档位申请 | AI 租户策略管理权限 |
| 用户 Skill 导入 | AI Skill 管理权限；不可删除系统必需 Skill |
| 租户档位变更审批 | AI 治理审批权限；申请人与审批人必须分离 |
| L3 任务审批 | 使用 FSM 产品业务审批流；审批人和节点由业务流程配置，申请人不得审批本人任务，审批通过后由平台服务身份执行冻结快照 |
| 查看日志和证据 | AI 审计查看权限，同时受租户和业务对象权限限制 |

## 11. 异常、降级与回退

| 异常场景 | 业务处理 | 用户表现 | 重试 |
| :--- | :--- | :--- | :--- |
| License 未授权 | 不启动 Agent | 不展示 AI 功能 | 授权后重新触发 |
| 系统 Skill 缺失或解析失败 | 停止推荐 | 显示失败和手工派单 | 平台修复后允许 |
| 关键字段缺失 | 返回受限 | 显示缺失字段、CLI 状态和解决建议 | 补齐后允许 |
| 非关键字段缺失 | 返回部分完成 | 展示未验证项，L2 可确认 | 补齐后可重新运行 |
| 无候选工程师 | 返回无候选结果 | 建议手工派单或补充资源 | 数据变化后允许 |
| CLI 超时或服务异常 | 按平台策略重试，超过限制后失败 | 显示原因、重试结果和日志入口 | 允许手动重试 |
| 模型输出不符合结构 | 受控重试；仍失败则结束 | 不展示伪候选 | 允许手动重试 |
| 用户无派单权限 | 保留只读推荐 | 禁用确认并显示权限提示 | 否 |
| L1 治理审批驳回 | 保持 L2 | 显示驳回结果 | 可重新申请 |
| FSM 响应 SLA 阈值事件到达且仍无人认领 | Skill 读取 FSM 次数事实后决定重派或升级人工 | 显示事件、实际 Skill、轮次和决策依据 | 不超过 FSM 最大智能重派次数 |
| 推荐连续未被调度员采纳 | 达到该租户场景的抑制阈值后暂停主动调用 | 显示“AI 推荐已暂停”，保留手动运行和人工派单 | 到期自动恢复，也可由有权用户提前恢复 |
| 达到 FSM 最大智能重派次数 | Skill 必须停止重派并升级人工；FSM 同时拒绝越界请求 | 保留全部轮次与手工转派入口 | 不自动重试 |
| SLA 临期且无安全候选 | 不降低资质或技能条件 | 通知调度员和主管，标记 SLA 风险 | 人工处理 |
| 全局熔断触发 | 所有租户暂停自动写动作 | 保留只读推荐和 FSM 手工派单 | 有权用户解除全局熔断后恢复 |

统一回退原则：任何 AI 异常均不得阻断 FSM 原有手工派单；不得把空数据当作零，不得用模型猜测补齐业务事实，不得在运行失败后执行派单。

### 11.1 FSM 业务策略与 Skill 决策

AI 平台不维护 SLA 时间阈值或派工次数。FSM 是响应 SLA、工单状态、当前重派次数和最大智能重派次数的唯一事实来源。FSM 到达既有响应 SLA 阈值时发布事件，Agent 根据租户提示词加载 Skill；Skill 可以决定继续重派或升级人工，但不得修改阈值、次数或越过 FSM 上限。

不同租户可以通过提示词选择不同 Skill，例如`dispatch-redispatch-first.md`或`dispatch-manual-escalation.md`。Skill 进入全局库而不按租户复制；每次运行必须记录租户提示词版本、最终 Skill ID/版本和选择原因。Skill 选择失败时停止自动执行并回退手工派单。

### 11.2 Agent 未采纳抑制

平台提供全局默认策略，并允许按`租户 × Agent × 场景`覆盖：

| 参数 | 平台默认值 | 作用 |
| :--- | :--- | :--- |
| 统计窗口 | 7 天 | 统计用户已经看到且可正常采用的建议 |
| 连续未采纳次数 | 30 次 | 命中后暂停该租户场景主动调用 |
| 暂停时长 | 24 小时 | 到期自动恢复，也可由有权用户提前恢复 |

CLI 失败、数据不足、License 不可用、用户未看到建议和 Dry-run 不进入统计。抑制不改变档位，不影响手动调用、历史结果查看或 FSM 原有人工派单。

### 11.3 平台全局熔断阈值

以下参数由 AI 平台管理员全局配置，不区分租户：

| 参数 | 推荐默认值 | 触发动作 |
| :--- | :--- | :--- |
| Agent 连续失败次数 | 5 次 | 暂停受影响 Agent 的自动写动作 |
| 15 分钟错误率 | 20% 且样本不少于 20 次 | 暂停受影响 Agent 的自动写动作 |
| 全平台月度 AI 预算使用率 | 100% | 暂停新增模型调用，保留手工业务流程 |
| 单工单最大正式模型调用次数 | 5 次 | 停止该工单 Agent 并升级人工 |

全局熔断优先级高于租户档位、Skill 决策和未采纳抑制。触发后不把任务自动改成 L3，不新建无意义审批；只读结果可继续查看，业务写操作回退到 FSM 原有人工流程。恢复需要人工解除并记录原因、操作人和时间。

## 12. 审计、计量与反馈闭环

### 12.1 审计范围

必须记录：

- 租户、触发来源、用户或平台身份、触发和完成时间。
- 工单编号、状态和业务对象权限校验结果。
- Agent、模型、系统 Skill 和版本。
- 每项 CLI、输入范围、结果状态、耗时和来源摘要。
- 候选集合、分数、证据、未验证项和排除原因。
- L1/L2/L3、生效租户策略和治理审批记录。
- 用户确认、取消、手工派单和最终候选集合。
- 每轮候选通知、FSM 响应 SLA 事件时间、未认领结果、重派原因、SLA 剩余时间和停止条件。
- 最终认领人、到场、完成、转派、取消和履约结果。

### 12.2 计量

- 记录模型 input/output token、credits、运行耗时和正式/测试标识。
- CLI 查询不重复计为模型 token，但需要记录命令调用量和耗时。
- 同一工单重复运行保留所有调用记录，指标按最终有效推荐版本去重。
- 达到租户场景抑制阈值、单工单调用上限或全局熔断后不得继续产生主动正式模型调用；手动运行是否允许以对应策略为准。

### 12.3 反馈闭环

- 调度员确认全部或任一推荐候选均记为采纳。
- L1 自动执行记为采纳。
- 手工选择非推荐工程师记为未采纳，并记录原因。
- 最终认领者用于计算 Top 1 和 Top 3 命中率。
- 工程师完成认领才计为派单成功；生成推荐、调度员确认或发送通知均不等于派单成功。
- 无人认领轮次、认领耗时和最终升级人工结果用于评估重派策略。
- 准时到场、完成、转派和实际费用用于评估推荐质量。
- 反馈进入脱敏评测样本，需经产品与研发评审后才能更新系统 Skill、Prompt 或模型版本。

### 12.4 端到端预期效果与演示流程

以下场景用于向用户说明产品效果，也作为研发联调和验收的标准流程。演示数据必须使用同一租户、同一工单和同一 `trace ID` 串联业务页面、运行记录与审计记录。

| 场景 | 演示步骤 | 用户预期效果 | 研发验收证据 |
| :--- | :--- | :--- | :--- |
| L2 首次智能派单 | 创建未选择候选工程师的待派单工单，触发 Agent，调度员确认 Top 3 | 展示候选、匹配依据、预计费用和未验证项；确认后同时通知候选，工单进入待认领 | 工单状态、候选集合、Prompt/Skill 版本、CLI 证据和 `trace ID` 一致；不在确认时标记派单成功 |
| 工程师认领闭环 | 任一候选工程师认领 | 最先认领者成为处理工程师，工单由待认领进入已派单，其他候选通知失效 | FSM 写入认领人和认领时间；Agent 运行记录标记“目标完成”；后续不再触发该轮重派 |
| L1 自动派单 | 租户 L1 已审批生效，创建满足自动执行条件的工单 | 用户无需打开页面，系统自动选择候选并进入待认领；详情页可追溯推荐依据 | 事件触发、硬性条件校验、候选通知和审计完整；命中高风险或未验证条件时不得自动写入 |
| 租户差异化策略 | 租户 A 的提示词引用重派优先 Skill，租户 B 引用人工升级 Skill；分别模拟 FSM 响应 SLA 阈值事件 | A 在未达 FSM 上限时生成新候选；B 直接形成调度员人工处理事项 | 同一 Agent 下记录不同租户 Prompt 版本、最终 Skill 文件/版本和选择原因；AI 平台不保存 SLA 阈值 |
| 无人认领重派 | FSM 发布响应 SLA 阈值事件，当前智能重派次数小于最大次数 | 按 Skill 决策生成新一轮候选，默认排除上一轮未认领人员；页面展示轮次与原因 | 重派次数从 FSM 读取并由 FSM 校验；每轮候选、排除原因和事件编号可追溯 |
| 达到重派上限 | FSM 事件携带当前次数等于最大次数 | 不再调用模型生成候选，进入人工调度；手工派单始终可用 | FSM 拒绝越界写入；运行记录为“已升级人工”，不产生额外正式模型调用 |
| L3 业务审批 | 高风险派工方案命中 L3 | 方案进入 FSM 业务审批，审批通过且执行前复核成功后才通知候选 | 审批发生在 FSM 产品流程而非 AI 治理中心；申请人与审批人分离；审批快照不可变 |
| 抑制与全局熔断 | 模拟租户场景连续未采纳达到阈值，再模拟平台全局熔断 | 前者仅暂停该租户场景主动调用；后者暂停所有租户自动写动作；均保留人工派单 | 抑制范围为`租户 × Agent × 场景`，可覆盖平台默认；熔断为全局配置，且均不改写租户档位 |
| 异常降级 | 模拟 License 未开通、必需 Skill 缺失、关键 CLI 数据缺失 | 未授权时不显示 AI 区块；其余情况说明失败原因和解决方式，不伪造候选，允许手工派单 | 失败类型、CLI 状态、重试结果与日志可查；任何失败均不得产生派单写操作 |

对外说明时统一强调三个结果：**推荐生成不等于派单成功，候选通知不等于派单成功，工程师完成认领才是 Agent 目标完成。**

### 12.5 效果验收口径

| 指标 | 计算口径 | 验收用途 |
| :--- | :--- | :--- |
| 推荐采纳率 | 已确认推荐或 L1 自动执行的有效运行数 / 用户已看到且可采用的有效推荐数 | 判断推荐是否被调度员采用；CLI 失败、数据不足和 License 不可用不计入分母 |
| 首轮认领率 | 首轮候选中有人认领的工单数 / 已发送首轮候选通知的工单数 | 判断首次推荐质量 |
| 派单成功率 | 最终完成认领的工单数 / 已进入待认领的 AI 派工工单数 | 验收 Agent 是否真正完成业务目标 |
| 平均认领时长 | FSM 候选通知时间至首位工程师认领时间的平均值 | 对比 AI 派工与人工派工效率 |
| 智能重派成功率 | 智能重派后完成认领的工单数 / 发生智能重派的工单数 | 判断重派 Skill 的有效性 |
| 人工升级率 | 最终升级人工的工单数 / 触发 Agent 的有效工单数 | 识别资源不足、策略不适配或数据问题 |
| 履约效果 | 准时到场率、按期完成率、转派率、满意度和实际费用 | 反哺推荐质量；数据来源仍为 FSM，不由模型推断 |
| 抑制节省调用量 | 抑制期间被阻止的主动调用次数 | 验证未采纳抑制是否减少无效 Token 消耗 |

## 13. PM 验收标准

| AC | 前置条件 | 触发动作 | 预期结果 |
| :--- | :--- | :--- | :--- |
| FSM-A7-AC-01 | L2、License 有效、工单待派单、数据完整 | FSM 事件触发 | 返回 Top 3、匹配度、费用、ETA、证据和运行标识，不执行派单 |
| FSM-A7-AC-02 | L2 推荐完成 | 调度员确认全部推荐候选 | 同时通知全部候选，工单进入待认领，最先认领者进入已派单 |
| FSM-A7-AC-03 | L2 推荐完成 | 调度员指定一名推荐候选 | 只通知该候选，工单进入待认领 |
| FSM-A7-AC-04 | L1 已审批生效、证据完整且不存在人工确认项 | 工单进入待派单 | 无需打开页面，自动选择通过硬性过滤的 Top 3（不足 3 人时选择全部）并进入待认领，记录事件触发和审计 |
| FSM-A7-AC-05 | 租户未授权 Agent | 打开任一业务页面 | 不显示 AI 派工区块、快捷入口或 AI 派工待办 |
| FSM-A7-AC-06 | 必需系统 Skill 缺失或解析失败 | 触发推荐 | Agent 失败且不生成候选，手工派单可用 |
| FSM-A7-AC-07 | 关键字段缺失 | 触发推荐 | 返回受限和各 CLI 结果，不生成伪候选 |
| FSM-A7-AC-08 | 非关键数据缺失 | 触发推荐 | 返回部分完成，明确未验证字段和执行限制 |
| FSM-A7-AC-09 | 无符合硬性条件的工程师 | 触发推荐 | 返回无候选，不降低硬性过滤标准 |
| FSM-A7-AC-10 | 调度员使用手工派单 | 选择候选工程师 | 工单进入待认领，与 AI 派单使用相同状态机 |
| FSM-A7-AC-11 | 用户无 FSM 派单权限 | 查看推荐 | 推荐只读，确认操作禁用并提示无权限 |
| FSM-A7-AC-12 | 平台管理员申请 L1 | 提交治理申请 | 审批前仍按 L2；申请人不能审批本人申请 |
| FSM-A7-AC-13 | 运行测试 | 输入有效待派单工单 | 展示 License、权限、Skill、CLI、候选、证据、版本和 trace ID，不改变工单 |
| FSM-A7-AC-14 | 已完成 AI 派单 | 查看我的待办、FSM 详情和治理审计 | 候选、状态、调用编号和审计记录一致 |
| FSM-A7-AC-15 | 工程师完成后续履约 | 回写到场、完成或转派 | 运行记录关联最终结果并更新效果指标 |
| FSM-A7-AC-16 | L1 已生效但存在预算超限或关键执行字段未验证 | 工单进入待派单 | 本次运行降级为 L2，不自动派单；租户生效档位保持 L1 |
| FSM-A7-AC-17 | FSM 发布响应 SLA 阈值事件、仍无人认领且当前次数小于最大次数 | Agent 按租户 Prompt 加载重派 Skill | 记录上一轮失败，按 Skill 生成或执行新方案，默认排除上一轮未认领候选，FSM 校验并累计次数 |
| FSM-A7-AC-18 | FSM 发布响应 SLA 阈值事件，租户 Prompt 引用人工升级 Skill | Agent 处理事件 | 不生成新候选，形成调度员人工处理事项并保留手工派单入口 |
| FSM-A7-AC-19 | FSM 当前智能重派次数已达到最大次数 | 再次收到阈值事件 | 不再调用模型，标记升级人工；FSM 拒绝任何越界重派请求 |
| FSM-A7-AC-20 | 该租户场景连续未采纳达到平台默认或覆盖阈值 | 再次发生主动触发 | 暂停`租户 × Agent × 场景`主动调用，保留手动运行、历史结果和人工派单；到期自动恢复 |
| FSM-A7-AC-21 | 高风险工单命中 L3 规则 | 生成派工方案 | 形成不可变快照并进入 FSM 业务审批；业务流程全部节点通过且执行前复核成功后才通知候选 |
| FSM-A7-AC-22 | 全局熔断触发 | 任意租户触发自动派工或重派 | 暂停自动写动作，不改写租户档位，不自动创建 L3 审批，保留只读结果和手工派单 |
| FSM-A7-AC-23 | 最终候选完成认领 | 工程师认领 | 工单进入已派单，Agent 目标完成；FSM 关闭本工单响应 SLA 阶段并不再发布该阶段重派事件 |
| FSM-A7-AC-24 | 租户 Prompt 指定的 Skill 不存在、重名或解析失败 | Agent 选择 Skill | 停止自动执行，显示明确原因并回退人工派单，不使用模型猜测替代 Skill |
| FSM-A7-AC-25 | FSM 独立创建且没有上游引用 | 触发推荐 | 只调用 FSM CLI，正常生成推荐；不搜索或猜测 ITSM、ITOM、ITAM、CMDB 对象 |
| FSM-A7-AC-26 | FSM 工单关联 ITSM 事件 | 触发推荐 | 按 incident_id 读取影响、优先级、客户、服务和事件 SLA，并作为技能、人员级别和时效证据，不覆盖 FSM SLA |
| FSM-A7-AC-27 | FSM 工单关联 ITSM 事件及 ITOM 告警 | 触发推荐 | 沿显式引用读取告警等级、症状和 CI；高等级告警进入风险约束并阻止不满足条件的 L1 自动派工 |
| FSM-A7-AC-28 | FSM 工单关联 ITAM 资产及 CMDB CI | 触发推荐 | 读取品牌型号、维保、厂商授权、关键度和关系；候选必须满足对应技能、认证和人员级别要求 |
| FSM-A7-AC-29 | 上游引用存在但 CLI 无权限、超时或数据冲突 | 触发推荐 | 显示具体系统、对象和失败状态；关键证据受影响时禁止 L1，允许 L2/L3 核对或手工派单，不伪造上下文 |
| FSM-A7-AC-30 | 告警事件来源工单完成现场处理并验收通过 | FSM 完成工单并发布回传事件 | ITSM 追加现场结果并按自身流程解决/关闭事件；ITOM 仅在监控恢复且满足关闭规则后恢复/关闭告警，完整关联可追溯 |
| FSM-A7-AC-31 | 客户报障直接创建的 FSM 工单验收通过 | 完成工单 | FSM 旅程结束并记录费用、SLA 和满意度；不创建 ITSM 事件或 ITOM 告警，不执行跨产品关闭动作 |

## 14. 评审参数

以下参数方向已明确，但具体值必须在开发开始前由产品、FSM 和 AI 平台共同评审：

| 参数 | 当前要求 | 待确认内容 |
| :--- | :--- | :--- |
| 接单状态有效性 | 激活工程师默认可接单；暂不可接单必须包含恢复时间和原因，到期自动恢复 | 最长持续时间默认 30 天，保留租户级配置能力 |
| 历史样本窗口 | 使用站点相似工单与跨站同类型工单 | 时间窗口、最少样本数、异常值剔除 |
| 相似工单定义 | 同站点、同类型优先 | 设备、技能、SLA 等匹配条件 |
| 区域经验 ETA | 当前版本不使用实时地图 | 数据维护人、区域粒度、更新周期 |
| Agent 超时与重试 | 使用平台统一运行重试策略、租户场景抑制和全局熔断 | 单次超时、重试次数、监控周期和通知渠道 |
| 同站同类型连续性 | 最高权重 30% | 历史有效窗口、时间衰减和最少样本数 |
| 满意度评分 | 权重 20%，默认阈值 3.5/5 | 问卷有效性、严重投诉定义和样本不足口径 |
| 无人认领重派 | 等待判定来自 FSM 响应 SLA 事件，最大次数来自 FSM 配置 | 候选排除期限和人工重新加入原因；AI 平台不得重复配置 SLA 阈值或最大次数 |
| License 生效 | 授权变化后更新业务入口和 Runtime | 缓存刷新和最大生效时延 |
| 权限编码 | 按本文权限分类配置 | EMS 权限编码和默认角色映射 |
| 系统 Skill 发布 | 产品版本管理，不允许用户修改 | 审批、灰度、回滚和兼容策略 |

这些参数不得由模型自行推断。未定稿参数在开发方案中必须标记为配置项或待确认项。
