# 智能开单 Agent 设计

> 本文定义 ITOM 告警转 ITSM 事件工单的智能开单方案。Agent 负责判断告警是否需要转事件、生成 AI 处置建议、摘取并组装事件工单内容，以及在授权档位下起草或创建 ITSM 事件；事件创建后交由 ITSM 事件理解与分配 Agent 继续完成分类补全、处理组/处理人推荐与分配。

- AI 建议、事件工单标题、描述、影响范围、初始分类、优先级、SLA、关联 CI、告警证据、处置建议等字段的摘取规则。

- 外部 ITSM 系统适配和第三方工单系统字段映射。
- 告警自动修复、配置变更、远程执行脚本或设备操作。

## 2. Agent 定位

### 2.1 一句话定义

智能开单 Agent 面向 NOC 值守人员、IT 运维人员和 Copilot 用户，在 ITOM 告警发生、查看或对话查询告警时，基于告警等级、影响范围、关联 CI、历史事件、RCA 结果、降噪/抑制状态和租户开单策略，判断是否建议转 ITSM 事件工单，并负责生成可追溯的事件草稿或在授权档位下自动创建事件工单。

### 2.2 与相关 Agent 的边界

| Agent | 负责内容 | 不负责内容 | 与智能开单 Agent 的关系 |
| :--- | :--- | :--- | :--- |
| 告警降噪 Agent | 告警聚合、抑制、关联和噪声识别 | 不创建 ITSM 事件 | 智能开单应读取降噪结论，避免为被抑制或已归并的子告警重复开单 |
| 根因分析 Agent | 对告警生成候选根因、证据和处置建议 | 不判断是否开单，不创建事件 | 智能开单可引用 RCA 结论作为工单描述和 AI 建议的一部分 |
| 智能开单 Agent | 判断是否转事件、生成工单草稿、摘取字段、创建事件 | 不负责事件分配和后续处理 | 创建事件后把事件编号、告警上下文和字段快照传给 A8 |
| ITSM 事件理解与分配 Agent | 理解事件、补全分类/标签、推荐或写入处理组/处理人 | 不从 ITOM 告警创建事件 | 接收智能开单创建的事件，继续完成分配链路 |

端到端链路：

```text
ITOM 告警
  → 告警降噪/关联状态检查
  → 根因分析可选补充证据
  → 智能开单 Agent 判断是否转事件、生成草稿或创建事件
  → ITSM 事件理解与分配 Agent 补全分类、优先级、SLA 和分配对象
  → ITSM 事件 workflow 处理、升级、关闭
```

### 2.3 背景与业务问题

- 当前问题：ITOM 告警和 ITSM 事件之间缺少稳定的智能转化层，运维人员需要手动判断哪些告警要开单、摘取哪些信息、如何描述影响和建议。
- 现有方式：用户在告警详情页或告警列表中人工复制告警内容，再到 ITSM 创建事件；或由简单规则按告警等级直接自动开单。
- 主要痛点：人工复制耗时且字段口径不一致；简单规则容易重复开单、误开单或漏开单；告警上下文、RCA 证据和历史事件经验难以沉淀到工单中。
- Copilot 新入口：用户在 Copilot 中查询告警事件时，希望系统直接判断是否值得转事件工单，并给出已摘取好的工单内容，而不是让用户手工整理。
- 改善目标：建立告警到事件工单的智能起草与自动开单能力，让每张事件工单都包含明确来源、影响、证据、建议和后续分配上下文。

### 2.4 业务目标

1. 降低 NOC/运维人员从告警到事件工单的整理成本。
2. 减少重复开单、噪声开单和低价值开单。
3. 保证事件工单初始内容结构化、可追溯、可被 ITSM 后续 Agent 使用。
4. 支持自动开单策略，但不绕过告警抑制、重复检测、权限、确认和审批。
5. 让 Copilot 查询告警时可以自然推荐“转事件工单”，并展示字段来源和可编辑草稿。

### 2.5 成功指标

| 指标 | 目标值 | 度量方式 | 统计范围与排除项 |
| :--- | :--- | :--- | :--- |
| 开单建议覆盖率 | >= 90% | 成功输出可用建议的目标告警数 / 满足触发条件的授权告警数 | 未授权、无权限、告警数据缺失单独统计 |
| 自动草稿时效 | >= 95% 在平台阈值内完成 | 阈值内完成草稿生成次数 / 成功启动次数 | 测试运行单独统计 |
| 转单采纳率 | >= 80% | 用户确认创建 + L1 自动创建 / 成功生成开单建议数 | 被抑制、已存在事件、规则禁止开单不进入分母 |
| 重复开单率 | <= 3% | 后续被标记为重复事件的 AI 开单数 / AI 创建事件数 | 需按租户、告警类型和 CI 单独分析 |
| 工单字段完整率 | >= 90% | 必填和推荐字段符合字段契约的事件数 / AI 创建或起草事件数 | ITSM 字段映射缺失单独统计 |
| 一次开单可用率 | >= 85% | 创建后未被人工大幅重写标题、描述、影响范围和优先级的事件数 / AI 创建或起草事件数 | 只统计进入正式处理的事件 |

### 2.6 Agent 不负责的事项

- 不负责关闭、确认、恢复或删除 ITOM 告警。
- 不负责事件分配、升级、解决、关闭和 SLA 计时。
- 不负责根因确认；只能引用 RCA 或历史事实作为建议证据。
- 不替代告警降噪策略，不为被抑制、归并或维护窗口内的告警强制开单。
- 不根据缺失事实编造影响范围、客户、CI、SLA 或处理建议。
- 不在未满足档位、权限、重复检测和审批条件时创建 ITSM 事件。

| 角色 | 使用目的 | 允许的主要操作 |
| :--- | :--- | :--- |
| NOC 值守人员 | 从告警快速生成事件工单 | 查看建议、编辑草稿、确认创建、查看已关联事件 |

| Copilot 用户 | 用自然语言查询告警并发起转事件 | 查看推荐、确认或取消创建 |
| 事件经理 | 审核高风险告警转事件 | 查看审批快照、通过或驳回开单 |
| AI 平台管理员 | 管理 Agent 启停、模型、档位和租户策略 | 配置档位、运行测试、查看审计 |
| 测试人员 | 验证开单字段、重复检测和异常边界 | 执行 Dry-run、核对字段契约 |

## 4. 业务范围与边界

### 4.1 支持范围

| 范围项 | 支持内容 | 备注 |
| :--- | :--- | :--- |
| 业务对象 | ITOM 告警、告警组、关联告警事件 | 必须能唯一识别告警、租户和来源系统 |
| 目标对象 | ITSM 事件工单 | 本期只转事件，不转服务请求、问题或变更 |
| 告警状态 | 活跃、未恢复、反复震荡、已恢复但仍需复盘 | 维护窗口、抑制、低价值告警默认不自动开单 |
| 触发来源 | 告警详情、告警列表批量操作、ITOM 自动规则、Copilot 对话、AI 平台 Dry-run | 自动触发不依赖用户打开页面 |
| 数据来源 | ITOM 告警、告警历史、告警关联、监控指标、CMDB CI、服务拓扑、RCA 结果、历史相似事件、ITSM 重复检测 | 由 EMS CLI 返回事实和来源 |
| 输出形态 | 不建议开单、建议开单草稿、自动创建事件、需审批开单、受限/失败 | 受限时不输出伪完整工单 |

### 4.2 不支持范围

| 不支持项 | 处理方式 |
| :--- | :--- |
| 非 ITOM 告警对象 | 返回不支持，不创建事件 |
| 无法识别租户或告警 ID | 返回受限，提示补充上下文 |
| 告警被降噪策略抑制或已归并为父告警 | 默认不创建；提示查看父告警或关联事件 |
| 告警已存在有效关联事件 | 不重复创建；展示已有关联事件和建议动作 |
| 维护窗口内且无业务影响证据 | 不自动开单；可生成人工参考草稿 |
| ITSM 事件字段映射缺失 | 不创建事件；提示管理员补齐映射 |
| 无 ITSM 创建权限 | 只读展示建议，不显示确认创建按钮 |
| 高风险策略要求审批 | 形成审批快照，审批通过后才创建 |

### 4.3 Agent、Skill 与 CLI 分工

| 层级 | 负责内容 | 不负责内容 |
| :--- | :--- | :--- |
| Agent 产品契约 | 触发条件、硬性过滤、字段契约、L1/L2/L3 行为、输出状态和审计 | 不定义告警事实或 ITSM 字段事实 |
| Skill | 告警到事件字段摘取、摘要生成、重复风险解释、建议动作组织 | 不授予权限，不绕过规则创建事件 |
| EMS CLI | 查询告警、CI、指标、RCA、历史事件和创建事件 | 不决定是否开单，不生成最终工单文案 |
| 模型 | 在已验证事实内归纳影响、生成标题/描述/建议、解释开单理由 | 不编造事实，不声明未执行动作已完成 |

### 4.4 告警组与批量开单拆合规则

智能开单的默认业务对象是“降噪后的主告警或告警组”，而不是每条原始子告警。批量开单入口必须先执行拆合判断，再生成事件草稿。

| 场景 | 默认处理 | 例外 |
| :--- | :--- | :--- |
| 同一告警组内多条子告警 | 创建一张 ITSM 事件，子告警作为关联证据 | 子告警跨客户、跨服务、跨根因或需要不同处理团队时，建议拆分 |
| 父告警已创建事件 | 子告警只追加关联，不重复创建事件 | 父事件已关闭且新告警发生在新的时间窗口，可重新评估 |
| 批量选择多个告警 | 先按租户、客户、服务、CI、根因、时间窗口聚类 | 用户可在 L2 页面手动拆分或合并草稿，但需记录差异 |
| 同一 CI 高频震荡 | 默认聚合为一张事件，描述中保留震荡次数和时间线 | 震荡跨越维护窗口或恢复后再次异常，可形成新的事件窗口 |
| 跨租户 MSP 视角批量开单 | 只允许汇总分析，不允许一次写入多个租户 | 必须拆成单租户执行任务，每个租户单独校验权限和档位 |

告警组字段生成规则：

1. 严重级别取组内最高告警等级，并记录等级来源告警。
2. 标题优先使用主告警对象和共同异常类型，避免堆叠所有子告警名称。
3. 影响范围按已验证服务、客户、站点和 CI 去重后写入。
4. 关联告警字段必须包含主告警 ID、告警组 ID、子告警 ID 列表和聚合原因。
5. 拆分建议必须说明拆分依据，例如不同客户、不同业务服务、不同处理团队或不同根因。

### 4.5 自动创建幂等与重复控制

智能开单必须把重复检测和创建事件设计为可幂等、可并发安全的业务动作，避免自动规则、用户点击、RCA 完成事件和批量开单同时触发时重复创建事件。

幂等键生成规则：

```text
idempotency_key =
  tenant_id
  + source_type
  + primary_alert_or_group_id
  + incident_window_start
  + primary_ci_or_service_id
```

要求：

1. `incident_window_start` 由告警规则或降噪事件组确定；没有事件组时使用告警首次发生时间所在的租户配置窗口。
2. ITSM 创建命令必须支持幂等键。推荐提供 `ems itsm incident create-from-alert --idempotency-key`，由服务端在同一事务内完成重复检测、事件创建和告警关联。
3. 若同一幂等键已存在事件，CLI 必须返回既有 `incident_id`、创建时间、当前状态和关联告警，不得创建新事件。
4. 幂等键命中已关闭事件时，不直接复用；必须结合新的事件窗口、告警恢复/再次发生时间和租户策略重新判断。
5. 用户强制创建也不能绕过幂等键；如确需创建新事件，必须填写 override reason，并进入 L2 记录或 L3 审批。

### 4.6 字段所有权与 A8 边界

为避免智能开单 Agent 与 ITSM 事件理解与分配 Agent 重复写入同一字段，事件字段分为“来源事实、开单草稿、A8 最终补全”三类。

| 字段类型 | sa3 智能开单职责 | A8 事件理解与分配职责 |
| :--- | :--- | :--- |
| 来源事实 | 写入来源系统、告警 ID、告警组 ID、告警 URL、Agent trace ID、证据快照 | 读取并引用，不修改来源事实 |
| 工单草稿 | 生成标题、描述、影响摘要、AI 建议、待确认项 | 可读取草稿内容作为理解输入 |
| 初始建议字段 | 输出 `suggested_category`、`suggested_priority`、`suggested_sla`、`suggested_ci` | 评估后写入或修正最终 `category`、`priority`、`sla`、`ci` |
| 分配字段 | 不写处理组、处理人；仅可给出建议转交方向 | 负责固定规则评估、处理组/处理人推荐或写入 |
| 审计字段 | 记录 sa3 字段来源、草稿版本和用户修改差异 | 记录 A8 分类、分单和规则命中证据 |

默认情况下，sa3 不直接写入最终分类、SLA、优先级和处理对象；只输出建议字段。若租户显式配置“开单时写入初始分类/优先级”，也必须标记字段来源为 `sa3_initial`，A8 后续修正时保留前后差异。

## 5. 业务场景设计

### 5.1 场景清单

| 场景编码 | 场景名称 | 触发入口 | 触发方式 | 预期结果 |
| :--- | :--- | :--- | :--- | :--- |
| ITOM-TICKET-01 | 告警详情推荐转事件 | ITOM 告警详情 | 手动/自动预分析 | 展示是否建议开单、AI 建议和事件草稿 |
| ITOM-TICKET-02 | 告警列表批量开单 | ITOM 告警列表 | 用户批量选择 | 对每条告警做去重和可开单判断，生成批量结果 |
| ITOM-TICKET-03 | ITOM 告警自动开单 | 告警产生或状态变化事件 | 自动 | 符合策略的告警自动创建事件或提交审批 |
| ITOM-TICKET-04 | Copilot 查看告警后转事件 | Copilot 对话 | 用户确认 | Copilot 展示告警事件和推荐草稿，用户确认后创建事件 |
| ITOM-TICKET-05 | RCA 结果辅助开单 | RCA 完成事件 / 告警详情 | 自动引用/手动刷新 | 将候选根因、证据和处置建议写入事件草稿 |
| ITOM-TICKET-06 | 已有关联事件 | 告警详情/自动规则/Copilot | 自动检测 | 不重复创建，展示已有事件和关联理由 |
| ITOM-TICKET-07 | 高风险开单审批 | P1/VIP/核心服务告警 | 自动提交审批 | 生成不可变开单快照，审批通过后创建事件 |
| ITOM-TICKET-08 | AI 平台 Dry-run | Agent 详情 | 手动测试 | 展示前置校验、字段映射、CLI、草稿和 trace ID，不创建事件 |

### 5.2 开单判断规则

Agent 先执行确定性前置规则，再由模型对已验证事实进行归纳解释。以下规则属于产品硬性规则：

1. 已有关联事件且事件未关闭时，不再创建新事件；只建议追加告警或查看已有事件。
2. 告警被抑制、被降噪归并为子告警、处于维护窗口且无业务影响证据时，不自动创建事件。
3. 告警等级、影响服务、CI 关键度、客户/VIP、持续时间、重复次数、影响范围、历史相似事件必须作为是否开单的重要依据。
4. P1、VIP、核心业务服务、大范围影响或跨租户风险告警默认不得静默自动开单后直接进入处理；至少需要 L2 人工确认或 L3 审批，除非租户显式配置低风险白名单。
5. 告警已恢复不等于不需要开单；如果存在持续影响、频繁震荡、SLA 记录、客户可见影响或复盘要求，仍可建议开单。
6. 数据不足时不得输出“无需开单”的确定性结论；应返回受限并说明缺失数据。

### 5.3 工单内容摘取规则

| ITSM 事件字段 | 来源优先级 | 生成规则 |
| :--- | :--- | :--- |
| 标题 | 告警名称、对象、服务、影响摘要 | 使用“影响对象 + 异常类型 + 影响服务/范围”的短标题，避免堆叠原始告警文本 |
| 描述 | 告警详情、时间线、RCA 摘要、影响范围 | 分段写入告警概况、发生时间、当前状态、影响范围、证据和建议 |
| 来源 | 固定为 ITOM 告警转事件 | 写入来源系统、告警 ID、告警 URL、Agent 运行 ID |
| 关联告警 | 当前告警、父告警、关联告警组 | 必须保留稳定告警 ID 和关联关系 |
| 关联 CI | 告警对象、CMDB 匹配 CI、拓扑上下游 | 只写入 CLI 已验证 CI；不确定对象放入待确认项 |
| 影响范围 | 服务拓扑、受影响客户/站点/门店、指标异常范围 | 区分已验证影响和疑似影响 |
| 初始分类 | 告警类型、监控域、CI 类型、历史事件 | 可作为建议字段；创建后可由 A8 再补全或修正 |
| 优先级 | 告警等级、影响范围、CI 关键度、VIP、SLA 策略 | 不低于租户优先级矩阵给出的最低级别 |
| SLA 等级 | 服务、客户、合同、告警等级 | 字段映射缺失时不强行写入 |
| AI 建议 | RCA、历史相似事件、运行手册、告警类型模板 | 必须标明建议来源和置信度，不写成已执行 |
| 附件/证据 | 指标快照、日志片段、拓扑路径、RCA 证据 | 只引用可追溯证据 ID 或链接 |
| 待确认项 | 无法验证的客户、CI、影响、分类 | 展示给用户确认，不作为确定事实写入 |

事件描述建议结构：

```text
告警概况：
- 告警名称、等级、对象、首次发生时间、最近发生时间、当前状态

影响判断：
- 已验证影响范围
- 疑似影响范围或待确认项

证据摘要：
- 关键指标、日志、拓扑、历史相似事件或 RCA 证据

AI 建议：
- 初步判断
- 建议排查步骤
- 建议转交方向或后续处理提示

来源：
- ITOM 告警 ID、告警组 ID、Agent trace ID
```

## 6. 触发、流程与状态

### 6.1 触发方式

- 自动触发：告警创建、告警等级升级、告警持续超阈值、告警震荡、RCA 完成、告警组成为主告警。
- 手动触发：用户在告警详情点击“生成事件草稿”或“转事件工单”。
- 批量触发：用户在告警列表选择多条告警执行“批量转事件”。
- Copilot 触发：用户询问告警、查看告警详情或要求“把这个告警转成事件工单”。
- 测试触发：AI 平台 Agent 详情执行 Dry-run。

### 6.2 业务流程

```text
触发智能开单
  → 校验租户、License、Agent 启用、档位和权限
  → 获取告警、告警组、降噪状态、维护窗口和关联事件
  → 执行重复开单检测
  → 获取 CI、服务、客户、拓扑、指标、RCA 和历史事件上下文
  → 判断是否建议转事件
  → 生成事件草稿、AI 建议和证据
  → 按档位进入 L1 自动创建、L2 人工确认或 L3 审批
  → 创建 ITSM 事件并关联告警
  → 触发 ITSM 事件理解与分配 Agent
  → 记录审计、计量和反馈
```

### 6.3 状态定义

| 状态 | 说明 | 用户可见动作 |
| :--- | :--- | :--- |
| `not_recommended` | 不建议开单，且证据充分 | 查看原因、手动强制草稿 |
| `draft_ready` | 已生成事件草稿，等待确认 | 编辑草稿、确认创建、取消 |
| `auto_created` | L1 自动创建事件成功 | 查看事件、查看证据 |
| `approval_required` | 需 L3 审批 | 查看审批快照、等待审批 |
| `duplicate_found` | 已有关联事件或疑似重复 | 查看已有事件、追加关联 |
| `limited` | 数据不足或能力门禁缺失 | 查看缺失项、补充数据、手工开单 |
| `failed` | Agent 或 CLI 异常失败 | 重试、查看日志、手工开单 |

### 6.4 Copilot 入口要求

Copilot 中的智能开单必须复用同一 Agent、同一场景编码和同一字段契约，不单独实现一套摘要逻辑。

典型交互：

1. 用户问：“看一下核心交换机这条告警。”
2. Copilot 展示告警概况、影响判断、是否已有事件、AI 建议。
3. 若建议转事件，展示事件草稿摘要和关键字段来源。
4. 用户说：“创建事件工单”或点击确认。
5. Agent 执行权限、重复和档位复核，通过后创建 ITSM 事件。
6. Copilot 返回事件编号，并提示后续分配由 ITSM 事件理解与分配 Agent 接续。

Copilot 不得只凭对话上下文创建事件；必须传入稳定告警 ID，并通过 CLI 重新读取最新事实。

### 6.5 A8 接力契约

事件创建成功后，智能开单 Agent 必须发布标准业务事件，供 ITSM 事件理解与分配 Agent 接续运行。

事件名称：

```text
itsm.incident.created_from_itom_alert
```

事件载荷：

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| tenant_id | 是 | 目标租户 |
| incident_id | 是 | 已创建的 ITSM 事件编号 |
| source_alert_ids | 是 | 当前事件关联的告警 ID 列表 |
| source_alert_group_id | 否 | 告警组 ID |
| draft_snapshot_id | 是 | 创建事件时使用的草稿快照 |
| field_provenance | 是 | 标题、描述、影响、CI、建议字段的来源和验证状态 |
| idempotency_key | 是 | 本次创建使用的幂等键 |
| sa3_trace_id | 是 | 智能开单 Agent 运行追踪 ID |
| requested_next_agent | 是 | 默认 `A8` |

接力规则：

1. A8 只在事件创建成功后运行；sa3 草稿阶段不触发 A8 正式写入。
2. A8 失败不回滚事件创建，但必须记录接力失败原因，并保留 ITSM 手工分配入口。
3. A8 重试必须使用同一 `incident_id` 和 `sa3_trace_id`，不得再次触发 sa3 创建事件。
4. 若事件被人工关闭、取消或已分配，A8 重试时必须重新校验事件状态。

### 6.6 执行身份与权限规则

| 入口/档位 | 执行身份 | 允许动作 | 关键限制 |
| :--- | :--- | :--- | :--- |
| L1 自动创建 | 租户绑定的平台服务身份 | 读取告警、生成草稿、幂等创建事件、关联告警、发布 A8 接力事件 | 必须通过租户 License、Agent 档位、白名单、ITSM 创建权限和对象权限校验 |
| L2 人工确认 | 当前用户身份 | 查看草稿、编辑草稿、确认创建事件 | 用户必须有目标租户 ITSM 事件创建权限；确认前重新读取最新告警事实 |
| L3 业务审批 | 审批通过后的业务执行身份 | 按审批快照创建事件 | 审批通过后仍需执行前复核；事实变化时退回确认 |
| Copilot 入口 | 当前用户身份 | 查询、展示建议、发起 L2 确认 | 不得因对话入口扩大数据范围；不能直接静默执行 L1 写动作 |

权限有效范围为以下交集：

```text
Agent 允许命令范围
∩ 租户 License 与模块开通状态
∩ 当前用户或平台服务身份权限
∩ ITOM 告警对象权限
∩ ITSM 事件创建权限
∩ 场景治理策略和自主权档位
```

## 8. Skill 与 CLI 要求

### 8.1 Skill 要求

系统预置必需 Skill：

- 告警转事件判断 Skill：定义何时建议开单、何时不建议开单、何时需要确认或审批。
- 告警字段摘取 Skill：定义 ITOM 告警、RCA、CMDB 和历史事件到 ITSM 事件字段的映射和摘要规则。
- 重复开单检测 Skill：定义同告警、同 CI、同服务、同时间窗口、同根因的重复判断口径。
- Copilot 转事件 Skill：定义对话入口如何展示草稿、请求确认和复核最新事实。

必需 Skill 缺失、解析失败或输出不符合 Schema 时，Agent 不得创建事件。

### 8.2 CLI 命令要求

| CLI 命令 | 能力 | 用途 |
| :--- | :--- | :--- |
| `ems itom alert get` | 查询告警详情 | 获取告警名称、等级、对象、状态、时间、描述 |
| `ems itom alert group get` | 查询告警组/父子告警 | 判断主告警、子告警和关联告警 |
| `ems itom alert noise-status` | 查询降噪、抑制、维护窗口状态 | 避免噪声和维护窗口自动开单 |
| `ems itom metric snapshot` | 查询关键指标快照 | 形成证据摘要 |
| `ems cmdb ci get/relations` | 查询 CI 与服务拓扑 | 识别影响对象和上下游 |
| `ems itsm incident duplicate-check` | 查询疑似重复事件 | 防止重复开单 |
| `ems itsm incident create-draft` | 生成或校验事件草稿 | 校验字段映射和必填项 |
| `ems itsm incident create-from-alert` | 幂等创建告警来源事件 | 在同一事务内执行重复检测、创建事件和关联告警 |
| `ems itsm incident create` | 创建 ITSM 事件 | L1/L2/L3 通过后执行 |
| `ems itsm incident link-alert` | 关联事件与告警 | 创建后写入关联关系 |
| `ems itsm incident similar` | 查询历史相似事件 | 支持建议和字段摘取 |
| `ems ai agent run-result get` | 查询 RCA 等 Agent 结果 | 引用根因分析和处置建议 |

写操作命令必须执行创建前复核：告警状态、重复事件、用户/服务身份权限、字段映射、档位、审批状态和幂等键均未变化时才允许提交。自动创建推荐使用 `create-from-alert`；若研发拆分为 `create` + `link-alert`，必须由服务端事务或补偿机制保证不会出现事件已创建但告警未关联、或告警已关联但事件创建重复的中间状态。

## 9. 自主权档位与治理

| 档位 | 行为 | 适用场景 | 限制 |
| :--- | :--- | :--- | :--- |
| L1 自动创建 | 满足白名单策略后自动创建 ITSM 事件 | 非高风险、非 VIP、重复检测通过、字段完整、租户明确启用 | 不允许 P1/VIP/核心服务默认静默创建 |
| L2 人工确认 | 生成草稿，用户确认后创建 | 告警详情、Copilot、普通自动建议 | 使用当前用户 ITSM 创建权限 |
| L3 业务审批 | 形成不可变审批快照，审批通过后创建 | 高风险、VIP、核心服务、大范围影响、跨客户影响 | 审批通过后仍需执行前复核 |

治理要求：

1. 自动创建必须可按租户、告警等级、服务、CI 类型、客户/VIP、时间窗口配置启停。
2. 每次创建必须记录告警 ID、事件 ID、字段来源、模型、Skill、CLI、用户/服务身份、档位和 trace ID。
3. 用户编辑草稿后，需记录 AI 原始草稿和用户修改差异。
4. L3 审批快照必须冻结告警事实、草稿字段、证据和建议动作；审批通过后如果告警或重复检测结果变化，必须重新确认。

## 10. 异常与降级

| 场景 | 处理方式 |
| :--- | :--- |
| 告警不存在或无权限 | 返回受限，不展示草稿 |
| 告警已恢复 | 根据震荡、影响和复盘要求判断；证据不足时只给人工草稿 |
| 重复检测服务失败 | 不允许 L1 自动创建，降级 L2 或失败 |
| RCA 未完成 | 可先基于告警事实生成草稿，并标记 RCA 结果缺失 |
| CMDB 未匹配 CI | 不写入关联 CI，放入待确认项 |
| 字段映射缺失 | 不创建事件，提示管理员配置 ITSM 字段映射 |
| 创建事件失败 | 保留草稿和 trace ID，允许用户重试或手工创建 |
| 创建后触发 A8 失败 | 事件仍创建成功；记录后续分配 Agent 失败并保留手工分配入口 |
| 幂等键命中既有事件 | 不创建新事件；展示既有事件并允许追加关联或查看详情 |
| 批量开单跨租户 | 拆分为单租户任务；MSP 汇总视角不直接写入 |
| 用户强制覆盖不建议开单结论 | 需要填写 override reason；重复、抑制、高风险场景进入 L3 或只允许人工参考草稿 |
| 告警组拆分依据不足 | 默认合并为一张事件，拆分建议进入待确认项 |

## 11. 验收标准

| AC | 前置条件 | 触发动作 | 预期结果 |
| :--- | :--- | :--- | :--- |
| TICKET-AC-01 | 告警活跃、无重复事件、字段映射完整 | 在告警详情生成草稿 | 返回标题、描述、影响、CI、优先级、AI 建议和证据来源 |
| TICKET-AC-02 | 告警已存在有效关联事件 | 触发智能开单 | 不创建新事件，展示已有事件编号和重复依据 |
| TICKET-AC-03 | 告警被抑制或归并为子告警 | 自动开单规则触发 | 不自动创建事件，提示查看父告警或主事件 |
| TICKET-AC-04 | L2 用户在 Copilot 确认创建 | 用户说“创建事件工单” | Agent 复核最新告警事实和权限后创建事件，并返回事件编号 |
| TICKET-AC-05 | L1 自动开单策略命中 | 告警产生事件触发 | Agent 自动创建 ITSM 事件、关联告警，并触发 A8 |
| TICKET-AC-06 | P1/VIP/核心服务告警 | 自动开单规则触发 | 不静默创建，形成 L3 审批快照或 L2 确认建议 |
| TICKET-AC-07 | RCA 结果已完成 | 生成事件草稿 | 草稿包含 RCA 候选根因、证据和处置建议，且标明来源 |
| TICKET-AC-08 | ITSM 字段映射缺失 | 触发创建 | 返回受限，不创建事件，并说明缺失字段 |
| TICKET-AC-09 | 事件创建成功但 A8 触发失败 | 创建后接力 | 事件保留成功状态，记录 A8 失败原因，允许手工分配 |
| TICKET-AC-10 | 用户编辑 AI 草稿后创建 | 确认创建 | 审计记录 AI 原始草稿、用户修改差异、最终事件字段 |
| TICKET-AC-11 | 同一告警被自动规则和用户同时触发 | 并发创建 | 系统使用同一幂等键，只返回一张 ITSM 事件 |
| TICKET-AC-12 | 告警组包含 5 条子告警且根因一致 | 智能开单 | 默认创建一张事件，子告警作为关联证据 |
| TICKET-AC-13 | 批量选择跨租户告警 | 执行批量开单 | 系统拆分为单租户任务，不能以 MSP 汇总身份直接写入 |
| TICKET-AC-14 | sa3 创建事件成功 | 发布接力事件 | A8 收到 `itsm.incident.created_from_itom_alert`，使用事件编号和字段快照继续分配 |
| TICKET-AC-15 | sa3 输出分类/优先级/SLA 建议 | A8 接续处理 | sa3 字段以 `suggested_*` 或 `sa3_initial` 留痕，A8 写入最终字段并保留差异 |

## 12. 产品原型设计

### 12.1 原型页面

### 12.2 主页面区块

1. 顶部 AI 建议条：展示当前最重要的开单建议、档位和事件链接。
2. 指标卡：展示有效告警、自动转事件、重复拦截、平均起草时间。
3. 转单流水线：展示告警接收、降噪/聚合、智能判断、幂等检测、事件创建、A8 接力。
4. 智能开单 Agent 工作台：展示当前候选告警组、开单判断、幂等键、重复检测、草稿字段来源、执行身份和确认按钮。
5. 告警组拆合策略：展示默认合并、建议拆分、父子告警关联和批量开单拆分结果。
6. AI 加工策略：展示字段所有权、L1/L2/L3 档位、强制覆盖审计和治理入口。
7. 最近转单记录：展示事件编号、来源告警、幂等键、A8 接力状态和处理状态。

### 12.3 交互状态

| 状态 | 页面表现 | 用户动作 |
| :--- | :--- | :--- |
| 建议开单 | 显示事件草稿和字段来源 | 编辑草稿、确认创建 |
| 已有关联事件 | 显示既有事件和重复依据 | 查看事件、追加关联 |
| 需审批 | 显示 L3 审批快照 | 提交审批、等待审批 |
| 数据不足 | 显示缺失字段和受限原因 | 补充字段、手工开单 |
| A8 接力失败 | 事件创建成功但分配状态异常 | 重新触发 A8、手工分配 |
| 强制覆盖 | 显示 override reason 输入 | 填写原因后进入确认或审批 |
