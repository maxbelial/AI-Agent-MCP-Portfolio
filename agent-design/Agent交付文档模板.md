> 版本：v1.0

| Agent/模型信息 | 按场景 | 支持结果追溯和问题定位 |

### 8.2 输出状态

| 状态 | 业务含义 | 页面处理 |
| :--- | :--- | :--- |
| 成功 | 已完成分析，结论有足够依据 | 展示完整结果 |
| 部分完成 | 已获得部分结果，但存在缺失 | 展示已知内容并标明限制 |
| 受限 | 因权限、数据或规则无法完整分析 | 说明原因和可行的补救方式 |
| 失败 | 本次分析未完成 | 展示失败原因并提供重试或退出 |
| 不支持 | 当前场景不属于 Agent 能力范围 | 说明不支持原因 |

### 8.3 输出约束

- 结论必须能对应到事实依据；
- 未验证内容必须明确标记；
- 证据不足时不得输出确定性根因；
- 建议动作不能伪装成已经执行；
- 用户必须能区分“事实”“判断”“建议”和“审批状态”。

## 10. 异常、降级与回退

| 异常场景 | 业务处理要求 | 用户可见提示 | 是否允许重试 |
| :--- | :--- | :--- | :--- |
| 场景不支持 | 停止分析 | 暂不支持该场景 | 否 |
| 关键数据缺失 | 返回受限结果 | 请补充： | 是 / 否 |
| 无权限 | 拒绝访问 | 无权查看相关信息 | 否 |
| 查询超时 | 保留已取得事实并标记受限 | 当前处理超时 | 是 |
| 服务异常 | 不生成伪结论 | 服务暂时不可用 | 是 |
| 结果不确定 | 标明未确认内容 | 结论仅供参考 | 视情况 |
| 审批未通过 | 不执行后续动作 | 审批未通过 | 否 / 重新提交 |

### 10.1 统一回退原则

- 不以空白结果冒充成功；
- 不以模型猜测补齐缺失事实；
- 不因分析失败而自动执行高风险动作；
- 保留用户已经获得的事实和处理记录；
- 失败后必须能回到业务对象页面或上一步操作。

## 12. PM 验收标准

### 12.1 场景验收

- [ ] 每个支持场景都能从规定入口触发；
- [ ] 不支持场景不会被误触发或强行处理；
- [ ] 正常案例能得到预期结果；
- [ ] 数据不足案例能得到受限结果；
- [ ] 高风险案例能进入正确的确认或审批流程。

### 12.2 交互验收

- [ ] Agent 入口、分析中、成功、失败、受限状态与原型一致；
- [ ] 用户能区分结论、证据、未确认内容和建议；
- [ ] 用户知道下一步可以做什么；
- [ ] 重试、返回、补充信息和审批入口可用；
- [ ] 无权限用户看不到不应看到的内容。

### 12.3 结果验收

- [ ] 输出字段和展示内容满足本文档要求；
- [ ] 结论能追溯到事实依据；
- [ ] 不输出未验证的确定性事实；
- [ ] 建议动作不会被误认为已执行；
- [ ] 处理状态和异常原因清晰可见。

### 12.4 治理验收

- [ ] L1/L2/L3 的行为符合本 Agent 定义；
- [ ] L2 必须经过用户确认；
- [ ] L3 必须经过规定审批链；
- [ ] 权限不足、审批拒绝和服务失败均有正确回退；
- [ ] 关键操作和结果可查询、可追溯。
